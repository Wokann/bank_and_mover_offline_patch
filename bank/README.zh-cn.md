# 离线、下载与解锁合并补丁

原版程序的内存分布、状态表、网络路径、BankObject 与 bankdata 结构见
[`docs/code-analysis.zh-cn.md`](docs/code-analysis.zh-cn.md)。本文只说明当前补丁的设计、
实现与独立构建方法。

这是 Pokemon Bank v1.5 本体 `00040000000C9B00` 当前维护的补丁。它把旧版独立
下载补丁和独立离线补丁中仍然有效的功能与安全检查整合到一个可在运行时选择模式的
工程中。它不是把两个 IPS 直接拼接起来，而是在每个共用的联网、数据、文本和保存
钩子中按照本次会话模式分派行为。

上传补丁已经永久废止。本工程在下载模式下把服务器数据导入本地，并在离线模式下使用
相互独立的本地副本；不会把离线修改上传至官方服务。解锁模式会进入原版联网事务恢复
流程，但不会用本地 Bankdata 替换服务器银行。

## 模式与建议使用流程

标题界面默认显示**离线模式**。每按一次实体 **R** 键，会依次在**离线模式**、
**下载模式**和**解锁模式**之间循环；原版 HOME 选单说明下方的模式文字会立即刷新。
按 **A**、**START** 或触摸下屏时，画面所示模式会锁定为本次会话模式；离开标题界面
后 R 键不再切换模式。

```text
标题界面（默认：离线模式）
        │
        ├── 按 R ──────────────► 下载模式
        ├── 再按 R ────────────► 解锁模式
        ├── 再按 R ────────────► 离线模式
        └── A / START / 触摸
                  │ 锁定当前显示模式
                  ├── 下载 ─► 官方服务器下载 ─► 本地文件
                  ├── 解锁 ─► 原版强制解锁路线
                  └── 离线 ─► 本地文件 ─► 正常使用 Bank
```

建议首次使用顺序：

1. 备份 SD 卡和已有的 `sd:/3ds/Bank/` 文件。
2. 切换到下载模式，进入功能选单第一项，选择任意兼容游戏，让官方服务返回完整
   银行对象。
3. 等待下载完成提示并返回标题界面。
4. 确认 `sd:/3ds/Bank/bankdata.bin` 已生成，之后使用离线模式正常操作银行。

如果没有任何可恢复的本地文件，离线模式也能通过原版首次使用初始化器创建新的本地
银行文件。但如果需要保留官方账户中已有的银行数据，仍建议先使用下载模式。

## 本地文件与基本约束

离线模式和下载模式共用同一套经过检查的 Bankdata 文件实现；三种模式都共用下文所述
的 Turtle 记录重定向后端。

| 文件 | 用途 |
|---|---|
| `sd:/3ds/Bank/bankdata.bin` | 当前完整银行文件（`0xBB518` 字节） |
| `sd:/3ds/Bank/bankdata.tmp` | 提交前完整写入的暂存文件 |
| `sd:/3ds/Bank/bankdata.bak` | 提交过程中保留的上一份完整文件 |
| `sd:/3ds/Bank/bankdata.bin.break` | 无法识别的主文件逐字节保全副本 |
| `sd:/3ds/Bank/bankdata.bak.break` | 无法识别的备份文件逐字节保全副本 |
| `sd:/3ds/Bank/sav.bin` | 重定向后的完整本地记录镜像（`0x200` 字节） |
| `sd:/3ds/Bank/sav.tmp` | 本地记录替换前的完整暂存镜像 |

补丁会在需要时创建 `sd:/3ds` 和 `sd:/3ds/Bank`。完整写入会检查文件创建／打开、
长度设置、服务返回值、刷新行为和实际写入字节数；短写或写入失败绝不会被当作完整
银行文件接受。

`bankdata.tmp` 是必要的事务文件，用于避免失败写入直接替换最后一份正常主文件。
`bankdata.bak` 是上一代已提交文件，不是第二份同时使用的银行数据。`.break` 只在
实际存在的无效文件无法用于恢复时作为保全副本生成。

### 本地记录重定向

补丁的三种模式都会把原版逻辑记录 `data:/turtle` 的持久化后端重定向至
`sd:/3ds/Bank/sav.bin`，但不会替换或直接解析外层的 `00000001.sav`。原版对象清空、
语言设置、事务字段更新、校验值生成、有效性校验、loaded 标志和上层初始化状态机均
保持不变；补丁只替换检查、读取、格式化和保存所使用的落盘后端。

```text
检查 sav.bin
    ├── 存在且为 0x200 字节 ─► 读取对象 ─► 原版校验器判定内容
    ├── 存在但长度或内容无效 ─► 原版首次使用初始化 ─► 写入 sav.bin
    └── 缺失
          ├── 完整 sav.tmp ─► 提升为 sav.bin
          └── 无可恢复 tmp ─► 只读尝试原版 data:/turtle
                                  ├── 有效 ─► 迁移为 sav.bin
                                  └── 缺失或无效 ─► 原版首次使用初始化
                                                        └── 写入 sav.bin
```

首次初始化仍由原版流程清空对象、应用所选语言并调用常规保存包装函数；重定向格式化
步骤只重置 `sav.bin`／`sav.tmp`，不伪造对象初始化，也不格式化原存档。成功得到
`sav.bin` 后，后续三种模式的本地记录读写都只指向该文件。SD 写入失败会作为保存失败
返回，不会改写原版存档作为补救。

`sav.bin` 是固定 `0x200` 字节的逻辑记录镜像，其中原版对象序列化长度为 `0x30`，
当前已确认字段占前 `0x2C` 字节。结构声明见
[`include/turtle_redirect.h`](include/turtle_redirect.h)。该记录可由原存档重新迁移或由
首次使用流程重建，因此只使用 `sav.tmp` 防止短写，不另建 `.bak` 或 `.break`。

## 下载模式

下载模式保留原版的启动、账户初始化、首次用户服务器记录创建、游戏检测、游戏选择、
事务恢复、联网、银行数据请求和断开作业。

```text
功能选单：下载银行数据到本地
        │
        ▼
原版游戏检测与游戏选择
        │
        ▼
原版服务器连接并下载完整银行数据
        │
        ▼
普通 Bank 远端成功回调取得 0xBB518 字节
        │
        ▼
写入并刷新 bankdata.tmp；核对长度和实际写入量
        ├── 失败 ─► 不改变原版回调结果
        └── 成功
              │
              ▼
旧 bin 轮换为 bak；tmp 改名为 bin
        ├── 失败 ─► 尽可能保留或恢复上一份文件
        └── 成功 ─► 标记本地捕获完成
                            │
                            ▼
跳过里程、盒子与保存界面
        │
        ▼
原版“不保存”事务释放与断开流程
        │
        ▼
显示下载完成并返回标题界面
```

只有完整对象返回后才会执行捕获，不会在网络接收过程中分块写入文件。成功回调还会
再次检查内部模式，只允许普通 Bank 路线写入本地，其他内部路线无法覆盖
`bankdata.bin`。

游戏选择界面会提示任意可选择的软件都能用于下载完整银行数据。本地提交成功后，流程
跳过本地里程、银行盒子和保存界面，进入原版“不保存并结束”路线。本地捕获失败时，
补丁不会伪造官方回调结果，也不会把失败静默标记成成功。

下载模式默认保留原版 state 15 的使用权、票务、活动和联网礼物检查，包括原版等待、
提示及失败处理。模拟器测试时可用下述单字节开关改为本地跳过；下载完成后跳过里程、
盒子和保存界面的规则不受该开关影响。

## 解锁模式

解锁模式是进入原版联网事务恢复流程的独立入口，不继承下载模式的 Bankdata 捕获、
下载后状态跳转或下载完成提示。

```text
标题界面：解锁模式
        │
        ▼
功能选单：进入强制解锁模式
        │
        ▼
选择对应游戏，并在确认时按住 L + A + START
        │
        ▼
原版强制解锁挑战码状态
        ├── 服务器没有候选值 ─► 保留原版两行提示
        └── 存在候选值 ───────► 第三行显示第一个可接受的八位形式：
                                  “输入此解锁码: xxxxxxxx”
        │
        ▼
原版输入验证、回滚请求、结果处理与后续流程
```

服务器响应对象中保存了一组候选值；原版验证器会把输入值与每个候选值模
`100,000,000` 后的结果比较。补丁严格按同一规则显示第一个候选值，并由原版文本系统
补足前导零；不会自行生成解锁码、跳过校验、伪造成功或替换后续服务器操作。候选列表
为空时，界面仍使用未经修改的原版两行提示。

该模式仍共用项目级选单限制和 Turtle 记录重定向，默认保留原版 state 15 的票务与
联网礼物检查；事务恢复状态机保持原版。显示候选码的钩子既不载入、也不上传本地离线
`bankdata.bin`。

## 票务与联网礼物：固定测试开关

在 [`src/main.s`](src/main.s) 顶部修改以下值，然后重新编译：

```asm
.definelabel ONLINE_TICKET_CHECK_BYPASS, 0
```

| 会话模式 | `0`：默认正常检查 | `1`：模拟器测试时跳过 |
| --- | --- | --- |
| 离线 | 在 state 15 作业接口提供本地 999 天使用权结果，不请求在线活动数据 | 同左 |
| 下载 | 原版 state 15：票务、活动与联网礼物检查 | 使用与离线模式相同的本地 state 15 结果 |
| 解锁 | 原版 state 15：票务、活动与联网礼物检查 | 使用与离线模式相同的本地 state 15 结果 |

截至本次票务调整提交，Azahar 官方版本尚未实现 `am:net` 的
`GetRightsOnlyTicketData`（命令 `0x0821`，见[接口注册表](https://github.com/azahar-emu/azahar/blob/6280521bf26ef1393974cd8c898de29cf75f5752/src/core/hle/service/am/am_net.cpp#L115)）。
因此保留两种票务配置：`0` 执行原版检查；`1` 跳过原版票务查询，改用本地结果，
供缺少该接口的模拟器使用。本项目作者的 Azahar
[`pokebank` 测试分支](https://github.com/Wokann/azahar/tree/pokebank)
已补全并经联网测试确认该接口可正常运行，所以使用该分支或实机时，当前值保持
`0` 即可，无需跳过票务检查。离线模式始终使用本地结果，不受该值影响。

上述 Azahar 功能实现全部由 AI 生成，不符合
[Azahar AI 使用政策](https://github.com/azahar-emu/azahar/blob/master/AI-POLICY.md)
对完整或大部分 AI 生成贡献的接收要求，因此仅保留在个人测试分支，不向 Azahar
官方主分支提交。

两条路线始终包含在同一套代码中；该定义只决定
`[0x002A7E04, 0x002A7E05)` 的一个策略字节。state 15 的入口和状态推进保持原版，
只转接 `0x002B0444`（作业启动）、`0x002B0464`（取得结果）和 `0x002B1994`
（解除绑定）三个调用点。开关为 `0` 时，下载与解锁模式调用原版作业接口；离线模式
或开关为 `1` 时，使用本地作业结果。原版仍负责分配、构造、结果检查、字段回填、
界面清理与析构；本地路径没有绑定网络客户端，故解除绑定直接返回成功。

本地结果提供主机当前时间和当前时间加 999 天的到期日；原版函数据此计算剩余天数、
小时数和有效标志。当前时间本身不加 999 天，仍供本地里程使用。购票次数为 `-1`
（未知），不伪造购票奖励；保留已有 EC 账户字段，无免费活动时段，不启动系统 eShop
小程序或伪造其加载动画。作业完成标志与原版“票据有效且不少于 15 天”的成功分支
一致；主机时间获取失败或到期日超出原版年份范围时，走原版失败处理。

此开关只控制 state 15，不跳过 NNID 登录、其他网络请求或服务器校验，也不改变
下载后的退出规则、解锁事务处理或 state 12/13 的现有模式分派。它用于兼容缺少
票务接口的模拟器；实机和已实现该接口的模拟器使用 `0`。原版检查返回的错误仍
按原版处理，不会伪造联网成功。

## 离线模式：启动、恢复与首次创建

离线模式只强制完成必要的联网状态，不创建相应远端作业。启动时按以下顺序判断本地
文件：

```text
检查 bankdata.bin 长度及偏移 0x15C 的格式头
        ├── 有效 ─────────────────────────────► 既有记录模式
        └── 缺失或无效
                  │
                  ▼
             检查 bankdata.bak
                  ├── 有效 ─► 完整读取并验证 0xBB518 字节
                  │            复制为 bankdata.bin；保留 bak
                  │            不生成 .break
                  │            └───────────────► 既有记录模式
                  └── 缺失或无效
                            │
                            ▼
             将每个实际存在的无效文件复制到对应 .break
             （初次尝试后，每个文件最多再重试 3 次）
                            │
                            └──────────────────► 原版首次使用模式
```

主文件有效或能从有效备份恢复时绝不生成 `.break`；缺失文件也不会生成虚假的
`.break` 占位文件。如果保全复制共四次仍失败，原无效文件保持不动，但不会阻止首次
创建继续进行。两份文件都不存在时直接进入首次使用流程。

原版首次使用判断和提示仍负责整个创建流程。补丁只跳过远端记录 ID 子状态，随后让
原版空对象初始化器取得可用的主机／账户值、创建 100 个本地化银行盒子，并写入真实
创建日期。最后的远端创建调用会替换为经过检查的完整 `bankdata.bin` 直接写入；首次
写入失败时删除残缺输出。

运行时离线使用期限按主机时间加 999 天设置，它与里程时间相互独立。有效本地文件中
已有的身份字段和创建日期不会被重写。

## 离线模式：读取与使用银行

```text
功能选单：使用 Pokemon Bank
        │
        ▼
原版游戏软件检查与游戏选择
        │
        ▼
本地银行数据连接提示（至少 2 秒）
        │
        ▼
精确读取并验证 0xBB518 字节 bankdata.bin
        ├── 失败 ─► 原版错误路线
        └── 成功
              │
              ▼
恢复原版元数据复制与所选游戏回调
        │
        ▼
需要时执行原版本地里程状态与领取界面
        │
        ▼
原版银行盒子与游戏交互
```

完整文件只会在选择游戏后载入。补丁绕过共用同步状态中的远端请求部分，再恢复其原有
本地子状态。盒子显示、Pokemon 移动、检查和游戏交互仍使用原版代码。

原版本地里程计算继续保留。离线模式只在本次状态实例中跳过两轮联网礼物查询，不清除
持久化的更新礼物标志，以便以后在官方环境中仍可使用。独立的远端使用权／活动状态则
在本地完成。

等待界面、旋转动画和节奏音效仍由原版状态的初始化、更新与退出路径统一管理。合并
补丁只通过原状态对象报告本地工作完成，不再引入第二个界面或音效所有者；进入盒子前
由原版状态退出路径完成清理。

## 离线保存、提交与回滚

```text
原版完整银行序列化（0xBB518 字节）
        │
        ▼
写入 bankdata.tmp + 设置长度 + 刷新 + 核对实际写入量
        ├── 失败 ─► 报告保存失败；保留 bankdata.bin
        └── 成功
              │
              ▼
保存进度界面至少继续显示 2 秒
        │
        ▼
原版卡带／数字版游戏保存
        ├── 失败 ─► 删除 tmp；保留 bin 与 bak
        └── 成功
              │
              ▼
删除旧 bak ─► bin 改名为 bak ─► tmp 改名为 bin
        ├── 成功 ─► 正常本地断开流程
        └── 失败 ─► 尽可能恢复 bak
```

本地暂存写入是同步操作，之后进入非阻塞状态机延时；画面继续刷新，文件不会重复写入。
只有原版游戏保存结果成功后才允许提交。删除、改名、关闭、文件长度、实际写入量、恢复
和回滚结果都会检查。选择不保存并结束时，不会安装新的 `bankdata.bin`。

## 共用选单、文本与语言处理

| 功能选单项目 | 离线模式 | 下载模式 | 解锁模式 |
|---|---|---|---|
| 第一项 | 使用 Pokemon Bank | 下载银行数据到本地 | 进入强制解锁模式 |
| 关于 Pokemon Bank | 原版说明界面 | 原版说明界面 | 原版说明界面 |
| 确认支持代码 | 已禁用；返回功能选单 | 已禁用；返回功能选单 | 已禁用；返回功能选单 |
| Poke Mover/eShop | 已禁用；返回功能选单 | 已禁用；返回功能选单 | 已禁用；返回功能选单 |
| Pokemon HOME | 原版语言选择流程 | 原版语言选择流程 | 原版语言选择流程 |
| 返回 | 原版行为 | 原版行为 | 原版行为 |

原 HOME 项会在创建任何 HOME 联网或盒子状态前重定向到原版语言选择器。返回标题前，
补丁把待提交语言和日文汉字模式写入持久化设置对象，启动原生本地保存模式 0 并等待
完成，因此立即重启也能保留新语言。断开时使用空白条目，避免新字库绘制上一种语言的
残留文本。

原版联网、银行连接、保存和断开文本保持不变；模式专用文本以新增条目保存，只由负责
显示它的状态按模式选择。标题提示、选单说明、游戏选择提示、本地连接／保存文字和下载
完成提示均覆盖软件自带的十套语言档案：日文假名、日文汉字、英文、法文、意大利文、
德文、西班牙文、韩文、简体中文和繁体中文。

### 注入空间来源与边界

以下地址均为游戏运行时的虚拟地址，不是 IPS 文件偏移。范围统一采用
`[起点, 终点)`：包含起点，不包含终点。布局定义见 [`src/main.s`](src/main.s) 和
[`symbol.inc`](include/symbol.inc)，构建后的实际落点见
`bank/build/armips-symbols.txt`。

原版可执行镜像的段边界如下；本补丁不扩大 ExHeader 中的段大小，也不移动后续段。

| 原版段 | 起点 | 声明大小 | 声明内容终点 | 按 4 KiB 页映射的终点 | 权限 |
| --- | --- | --- | --- | --- | --- |
| `.text` | `0x00100000` | `0x00213910` | `0x00313910` | `0x00314000` | 可读、可执行 |
| `.rodata` | `0x00314000` | `0x00055370` | `0x00369370` | `0x0036A000` | 只读、不可执行 |
| `.data` | `0x0036A000` | `0x00041ACC` | `0x003ABACC` | `0x003AC000` | 可读写、不可执行 |

代码和数据使用的空间分为原址修改、禁用功能回收和原段末页填充，不能把它们都视为
原镜像中天然空闲的区域。

| 地址范围 | 空间来源与原用途 | 当前用途及边界约束 |
| --- | --- | --- |
| `main.s` 中分散的原址 hook | 原有函数入口、调用点或分支处的指令 | 修改跳转、条件或少量指令，必要时由包装函数重放被覆盖指令；不代表整段原函数可回收。 |
| `[0x00285BA8, 0x0028711C)` | 禁用后回收：HOME 专用盒子选择 UI 的输入、更新、构造和清理等函数；原范围 `0x1574`（5492 字节） | 放置 FS、Bankdata、离线流程、本地里程、本地票据及解锁显示的六个 C 对象，以及其后的票据作业包装；不包括普通盒子或共享函数。`0x0028711C` 是相邻正常 UI 函数的起点，不能越界。 |
| `[0x002A7BF0, 0x002A8404)` | 禁用后回收：state 27 的 HOME 操作控制及其创建、初始化、清理函数 | 汇编模式分派、包装、跳板和单字节票务开关使用到 `0x002A82E4`；从该处开始放置 Turtle 重定向后端，并继续使用下一行的回收区。 |
| `[0x002A8404, 0x002A8760)` | 禁用后回收：state 14 的 eShop 跳转界面及配套函数 | Turtle 后端的剩余部分；这两段回收区合计 `0xB70`（2928 字节），当前已用满。`0x002A8760` 是原版事务恢复入口，保留原样，不能覆盖。 |
| `0x002B0444`、`0x002B0464`、`0x002B1994`，各 4 字节 | 原址修改：state 15 作业启动、取结果及退出解除绑定的调用点 | 三条 `BL` 调用模式包装；离线模式始终提供本地结果，下载与解锁模式由固定测试字节选择原版或本地作业。 |
| `[0x002B0270, 0x002B1AD0)`，除上述三个调用点 | 保留：state 15 原函数体及配套函数 | 其余字节与原镜像一致，三个模式均使用原版状态推进、结果回填及清理；不作为荷载空间。原版票据作业函数本身也不改写。 |
| `[0x00313910, 0x00313A40)` | 原 `.text` 最后一页的填充 | 为 Luma LayeredFS 荷载避让 `0x130`（304 字节），本补丁不写入。`0x00313A40` 是本工程选定的避让边界，不是 Luma 固定地址。 |
| `[0x00313A40, 0x00313FC0)` | 原 `.text` 最后一页的填充；范围 `0x580`（1408 字节） | 放置尾部汇编和 `patch_paths.o`，实际使用到 `0x00313E2B`；后面是本工程尚未使用的填充。 |

下载入口也在三个模式中禁用。因此只回收这些功能专属的调用链，不回收它们使用的
公共 SDK、普通盒子或其他界面的共享函数。

当前 C 对象及尾部区的实际占用如下，包含对象之间的对齐填充。

| 内容 | 实际范围 | 占用 |
| --- | --- | --- |
| `fs_helpers.o` | `[0x00285BA8, 0x00286150)` | `0x5A8`（1448 字节） |
| `bankdata_redirect.o` | `[0x00286150, 0x002867AC)` | `0x65C`（1628 字节） |
| `offline_flow.o` | `[0x002867AC, 0x002868CC)` | `0x120`（288 字节） |

| 回收区中的汇编包装、跳板与票务开关 | `[0x002A7BF0, 0x002A82E4)` | `0x6F4`（1780 字节） |

`0x13E8`（5096 字节）；剩余 `[0x00286F90, 0x0028711C)` 为 `0x18C`（396 字节）。
这里仍是被禁用的旧 HOME
函数内容，不是天然零填充。尾部区剩余 `[0x00313E2B, 0x00313FC0)` 为
`0x195`（405 字节）；若放置 4 字节对齐的 ARM 代码，可用起点为
`0x00313E2C`，即 `0x194`（404 字节）。

`.text` 声明内容终点到映射终点只有 `0x6F0`（1776 字节），是按页映射留下的
最后一页余量，不是额外分配了一整页。Luma 在应用 IPS 后安装 LayeredFS，且不会
自动避开 IPS 已占用的范围：本工程因此单独保留上述 304 字节。该布局下 LayeredFS
的路径字符串使用 `.rodata` 尾部 `[0x00369370, 0x00369397)` 的 39 字节，
与 `.text` 中的执行荷载分开，本补丁不占用该处。相关机制可对照
[Luma 加载器](https://github.com/LumaTeam/Luma3DS/blob/master/sysmodules/loader/source/loader.c)
与 [LayeredFS 安装逻辑](https://github.com/LumaTeam/Luma3DS/blob/master/sysmodules/loader/source/patcher.c)。
更换 Luma 实现或原镜像段布局时，需要重新核对其荷载大小和落点，不能假定这条避让
边界对所有版本都成立。

`.rodata`、`.data` 的其他末页零值不能直接认定为空闲空间；它们也不具备执行权限。
本补丁没有为注入代码另行分配堆空间。增加荷载时应同时核对 `.area` 上限、实际构建
符号和相邻原函数，不能只凭连续零值或某个入口被跳过就扩大回收范围。

## 独立编译与安装

Bank 子项目不依赖 Mover 的源码或构建产物，可以单独完成代码编译、IPS 生成、十套语言
文本重建和静态验证。

需要准备 GNU Make、兼容 POSIX 的 shell、Python 3 和 devkitARM，并设置 `DEVKITARM`
环境变量。仓库自带 Windows 版 armips 与 Floating IPS；其他平台可通过 `ARMIPS` 和
`IPS_TOOL` 指定自行下载或编译的程序。

从用户自己的 Bank 本体 `00040000000C9B00` 提取输入：

1. 在 GodMode9 的 `Title manager` 中选择 Bank 本体并进入 `Open title folder`。
2. 选择可执行 `.app`，依次执行 `NCCH image options...` → `Extract .code`。
3. 再次选择同一 `.app`，执行 `NCCH image options...` → `Mount image to drive`，复制挂载
   分区中的完整 `romfs` 目录。
4. 按以下结构放入工程：

```text
bank/rom/
├── exefs/
│   └── 00040000000C9B00.dec.code
└── romfs/
    └── ...
```

基底代码必须为 `2,801,664` 字节，SHA-1 必须为
`5AB630856835DCF2DBDF9A62244DD19E46AE1C7C`。构建脚本会再次检查输入；代码镜像和
RomFS 不应提交或传播。需要使用其他 RomFS 路径时可显式覆盖 `ROMFS_SOURCE`。

从仓库根目录独立构建 Bank：

```sh
make -C bank clean
make -C bank
```

也可以进入子项目目录后构建：

```sh
cd bank
make clean
make
```

非 Windows 平台示例：

```sh
make -C bank ARMIPS=/path/to/armips IPS_TOOL=/path/to/flips
```

构建顺序为：把八个 C 编译单元分别编译成注入三个已验证区域的对象 → 输出各对象反汇编供检查
→ armips 导入对象并修改基底镜像 → Floating IPS 对比生成 `code.ips` → 重建十套语言
RomFS → 执行静态验证。完整输出为：

```text
release/00040000000C9B00/
├── code.ips
└── romfs/
```

校验器会检查基底哈希、载荷可执行范围、每个 ARM 钩子、被覆盖原指令、模式分派、IPS
逐字节还原结果和所有本地化文本。把生成的 `00040000000C9B00` 复制到
`SD:/luma/titles/`，启用 Luma 游戏补丁。实机使用前请备份 SD 卡和游戏存档。
