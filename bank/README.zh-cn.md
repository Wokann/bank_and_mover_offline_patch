# 离线、下载、解锁与原版合并补丁

原版程序的内存分布、状态表、网络路径、BankObject 与 bankdata 结构见
[`docs/code-analysis.zh-cn.md`](docs/code-analysis.zh-cn.md)。本文只说明当前补丁的设计、
实现与独立构建方法。

这是 Pokemon Bank v1.5 本体 `00040000000C9B00` 当前维护的补丁。它把旧版独立
下载补丁和独立离线补丁中仍然有效的功能与安全检查整合到一个可在运行时选择模式的
工程中。它不是把两个 IPS 直接拼接起来，而是在每个共用的联网、数据、文本和保存
钩子中按照本次会话模式分派行为。

上传补丁已经永久废止。本工程在下载模式下把服务器数据导入本地，并在离线模式下使用
相互独立的本地副本；不会把离线修改上传至官方服务。解锁模式会进入原版联网事务恢复
流程，但不会用本地 Bankdata 替换服务器银行。原版模式使用原存档和完整官方银行
流程，不会载入离线银行进行上传。

## 模式与建议使用流程

首次启动时标题界面默认显示**离线模式**。每按一次实体 **R** 键，会依次在**离线模式**、
**下载模式**、**解锁模式**和**原版模式**之间循环；原版 HOME 选单说明下方的模式文字会立即刷新。
按 **A**、**START** 或触摸下屏时，画面所示模式会锁定为本次会话模式；离开标题界面
后 R 键不再切换模式。返回标题时保留刚才使用的模式；重新启动软件才恢复默认离线。
模式选择只保存在运行内存中，不写入存档。

```text
标题界面（默认：离线模式）
        │
        ├── 按 R ──────────────► 下载模式
        ├── 再按 R ────────────► 解锁模式
        ├── 再按 R ────────────► 原版模式
        ├── 再按 R ────────────► 离线模式
        └── A / START / 触摸
                  │ 锁定当前显示模式
                  ├── 下载 ─► 官方服务器下载 ─► 本地文件
                  ├── 解锁 ─► 原版强制解锁路线
                  ├── 原版 ─► 原存档及完整官方流程
                  └── 离线 ─► 本地文件 ─► 正常使用 Bank
```

建议首次使用顺序：

1. 备份 SD 卡和已有的 `sd:/3ds/Bank/` 文件。
2. 切换到下载模式，进入功能选单第一项，让官方服务返回完整银行对象，无需选择游戏。
   没有可用游戏存档时，选择直接下载服务器银行数据。
3. 等待下载完成提示并返回标题界面。
4. 确认 `sd:/3ds/Bank/bankdata.bin` 已生成，之后使用离线模式正常操作银行。

如果没有任何可恢复的本地文件，离线模式也能通过原版首次使用初始化器创建新的本地
银行文件。但如果需要保留官方账户中已有的银行数据，仍建议先使用下载模式。

## 本地文件与基本约束

离线模式和下载模式共用同一套经过检查的 Bankdata 文件实现。仅离线模式重定向
Turtle 记录；其他三种模式在确认标题选择后使用原存档后端。

| 文件 | 用途 |
|---|---|
| `sd:/3ds/Bank/bankdata.bin` | 当前完整银行文件（`0xBB518` 字节） |
| `sd:/3ds/Bank/bankdata.tmp` | 提交前完整写入的暂存文件 |
| `sd:/3ds/Bank/bankdata.bak` | 提交过程中保留的上一份完整文件 |
| `sd:/3ds/Bank/bankdata.bin.break` | 无法识别的主文件逐字节保全副本 |
| `sd:/3ds/Bank/bankdata.bak.break` | 无法识别的备份文件逐字节保全副本 |
| `sd:/3ds/Bank/sav.bin` | 重定向后的完整本地记录镜像（`0x200` 字节） |
| `sd:/3ds/Bank/sav.tmp` | 本地记录替换前的完整暂存镜像 |

补丁会在需要时创建 `sd:/3ds` 和 `sd:/3ds/Bank`。完整写入会检查文件创建／打开、
长度设置、服务返回值、刷新行为和实际写入字节数；短写或写入失败绝不会被当作完整
银行文件接受。

`bankdata.tmp` 是必要的事务文件，用于避免失败写入直接替换最后一份正常主文件。
`bankdata.bak` 是上一代已提交文件，不是第二份同时使用的银行数据。`.break` 只在
实际存在的无效文件无法用于恢复时作为保全副本生成。

### 本地记录重定向

离线模式会把原版逻辑记录 `data:/turtle` 的持久化后端重定向至
`sd:/3ds/Bank/sav.bin`，但不会替换或直接解析外层的 `00000001.sav`。原版对象清空、
语言设置、事务字段更新、校验值生成、有效性校验、loaded 标志和上层初始化状态机均
保持不变；补丁只替换检查、读取、格式化和保存所使用的落盘后端。

```text
检查 sav.bin
    ├── 存在且为 0x200 字节 ─► 读取对象 ─► 原版校验器判定内容
    ├── 存在但长度或内容无效 ─► 原版首次使用初始化 ─► 写入 sav.bin
    └── 缺失
          ├── 完整 sav.tmp ─► 提升为 sav.bin
          └── 无可恢复 tmp ─► 只读尝试原版 data:/turtle
                                  ├── 有效 ─► 迁移为 sav.bin
                                  └── 缺失或无效 ─► 原版首次使用初始化
                                                        └── 写入 sav.bin
```

首次初始化仍由原版流程清空对象、应用所选语言并调用常规保存包装函数；重定向格式化
步骤只重置 `sav.bin`／`sav.tmp`，不伪造对象初始化，也不格式化原存档。成功得到
`sav.bin` 后，后续离线模式的本地记录读写都只指向该文件。SD 写入失败会作为保存失败
返回，不会改写原版存档作为补救。

`sav.bin` 是固定 `0x200` 字节的逻辑记录镜像，其中原版对象序列化长度为 `0x30`，
当前已确认字段占前 `0x2C` 字节。结构声明见
[`include/turtle_redirect.h`](include/turtle_redirect.h)。该记录可由原存档重新迁移或由
首次使用流程重建，因此只使用 `sav.tmp` 防止短写，不另建 `.bak` 或 `.break`。

选择模式前，公共启动／标题流程仍使用 SD 后端；需要时可只读迁移有效的原存档。
先等待原版公共提示视图的异步清理完成，再销毁标题视图并检查、重载所选后端：

| 选定模式 | 此后检查、读取、格式化及保存的记录 |
| --- | --- |
| 离线 | `sd:/3ds/Bank/sav.bin` |
| 下载／解锁／原版 | 原版逻辑 `data:/turtle`，保留原存档挂载、提交及事务处理 |

重载会清除上一份记录的 loaded 标志和待选语言缓存；有效记录使用自己的语言与汉字
设置。后续原生状态重新创建提示／菜单视图，使文本包和字体同步到所选记录的语言，
避免 SD 与原存档语言不同而复用旧界面资源。缺失或无效时先进入原版语言选择，再按
已选模式继续游戏检查及其初始化链。
不会把 SD 记录灌回原存档。返回标题时，会在创建标题 UI 前重新加载 SD 预览。
原存档模式不向 `sav.bin` 镜像同步，保存失败也不会改用另一个后端。

> **隐私提醒：** 从原版内部存档拷贝、用于离线使用的 `sav.bin` 可能包含个人或账户相关信息，请勿公开上传或随意分享。下载取得的 `bankdata.bin` 也应遵守同样的保护要求。

## 下载模式

下载模式保留原版启动、账户查询、首次服务器记录创建、票务检查、完整文件请求和
断开作业，使用原版 HOME 的不依赖所选游戏的下载器，但不进入 HOME 转移界面。
标题模式确认后，语言及原版初始化仍使用原版 Turtle 存档，不写入 `sav.bin`；
不选择或保存来源游戏。公共标题预览／迁移仍按前述规则使用 SD 记录。

```text
确认标题模式 → state 3 游戏检查
        ├── 无可用游戏：询问是否直接下载
        │       └── 否 ─► 原版清理 → 标题
        └── 有可用游戏／选择是
                ▼
原版 Turtle 检查／载入；需要时在原存档上完成初始化和保存
        │
        ▼
state 5 → 8 → 15 → 9：账户无银行时原版初始化并上传，等待创建成功
        │
        ├── 有可用游戏 ─► state 4：选择“下载银行数据到本地”
        └── 无可用游戏且已确认 ─► 直接继续
        │
        ▼
state 28：原版服务器连接并下载完整银行数据，无需选择游戏
        │
        ▼
原版成功回调装载当前格式，或将旧格式扩展为当前格式
        │
        ▼
在后续会话标志调整前，捕获装载后的 0xBB518 字节记录
        │
        ▼
写入并刷新 bankdata.tmp；核对长度和实际写入量
        ├── 失败 ─► 不改变原版回调结果
        └── 成功
              │
              ▼
旧 bin 轮换为 bak；tmp 改名为 bin
        ├── 失败 ─► 尽可能保留或恢复上一份文件
        └── 成功 ─► 标记本地捕获完成
                            │
                            ▼
跳过里程、盒子与保存界面
        │
        ▼
state 29：原版远端事务释放及界面清理 → state 20：断网
        │
        ▼
显示本地保存成功／失败提示并返回标题界面
```

只有完整对象装载后才会执行捕获，不会在网络接收过程中分块写入文件。钩子位于
`0x002D1248`，两条原版装载分支均已返回，但尚未调整本次会话标志。原版旧格式装载器
接收 `0xACA48` 字节并扩展为当前记录；补丁复制装载后的 `0xBB518` 字节，不对较短响应
按当前长度读取。成功回调还会再次检查会话模式与对象标志，只允许下载模式的 state 28
路线写入本地，其他路线无法覆盖 `bankdata.bin`。

下载模式不进入游戏选择、本地里程、银行盒子或保存界面。没有可用游戏存档时显示
下载确认；拒绝则按原版清理返回，接受则先完成原版 Turtle 检查／初始化，再继续正常
联网及首次创建检查。服务器已有银行
不会因为本地文件缺失而重新创建；服务器没有银行时先等待官方创建成功，再请求完整
服务器文件，不把上传前的本地初始化缓冲区当作下载结果。本地捕获失败时，
补丁不会伪造官方回调结果，也不会把失败静默标记成成功。

沿用已有的下载到 SD 路径提示（`0x61`）。临时写入和文件轮换全部成功时使用原下载完成
提示（`0x62`）；捕获失败则使用新增的本地 SD 保存失败提示（`0x74`）；尚未取得成功响应
并尝试捕获时保留原断网文本。state 29 保留远端请求、异步等待及界面销毁，再直接断网，
不进入 state 27 的 HOME 转移控制器。该收尾并非完全不向服务器发送请求。

### 启动与服务器数据的组合情况

Turtle 初始化、服务器银行首次创建、本地文件安装是三个不同阶段。是否进入 state 9
创建银行由服务器账户查询结果决定，不由本地 `bankdata.bin` 是否存在决定。

| 可用游戏存档 | 服务器银行 | 下载路线 |
| --- | --- | --- |
| 有 | 已存在，非空 | 原版启动检查 → 功能选单第一项 → state 28 下载。 |
| 有 | 已存在，空银行 | 同上；下载完整空记录，不进入 HOME 的空银行提示。 |
| 无 | 已存在，非空 | 接受直接下载询问 → Turtle 检查 → 原版联网 → state 28。 |
| 无 | 已存在，空银行 | 同一直接路线；零只宝可梦不会阻止捕获。 |
| 任意 | 尚未创建 | 原版首次使用说明及初始化 → 上传 → 等待真实成功回调 → state 28；有可用游戏时，创建和下载之间仍经过功能选单。 |
| 无 | 任意，用户选择取消 | 联网前按原版清理返回标题，不创建服务器银行，也不下载。 |

无游戏下载询问的按钮为“开始下载”和原版“取消”。原版模式仍使用原 HOME 转移确认标签。

原版 Turtle 有效时，state 3 正常载入，保留原语言及保存处理。缺失或无效时，走原版
初始化确认、格式化、初始化和保存链；拒绝初始化或原保存失败仍按原版错误／返回分支
处理。接受无游戏下载询问只设置原直达标志，不跳过这条链。下载模式确认后，原存档
缺失时不会拿已有 SD `sav.bin` 替代。

### 失败与中断情况

| 阶段 | 处理方式 |
| --- | --- |
| Turtle 初始化、账户／票务检查或联网请求失败 | 保留原提示和错误清理，不报告本地下载完成。公开票务策略保持 `0`。 |
| 服务器首次上传无法启动或回调失败 | 保留原失败分支，不把上传前的初始化缓冲区导出为下载文件。 |
| 完整下载失败，或服务器未返回成功的数据主体 | 保留原失败处理，不制造空银行，也不伪造本地成功。 |
| 装载对象头不可用，或临时文件的写入／长度／刷新／关闭检查失败 | 记录本地捕获失败，不改原回调结果，继续原清理。可能留下残缺 `.tmp`，不会仅因文件存在就将其安装为正式文件。 |
| 备份删除或改名失败 | 提示本地失败；现有轮换函数停止操作或尝试恢复旧 `.bin`。SD 持续不可用时，不能保证恢复成功。 |
| SD 副本成功后，state 29 远端释放失败 | 文件确实已保存，但仍保留原远端报错；本地完成不代表已解除服务器事务锁定。 |
| 下载／轮换期间关闭软件或断电 | 不会显示完成；下次下载重新查询服务器，不上传本地文件，也不把残留临时文件当作已完成下载。离线恢复继续使用原 `.bin/.bak` 规则。 |

下载完成路线全部跳过里程、盒子、常规保存和 HOME 转移；但原版 Turtle 的初始化保存
及服务器银行的首次上传仍保留。这条路线不会强制绕过服务器拒绝或事务锁定。

下载模式默认保留原版 state 15 的使用权、票务、活动和联网礼物检查，包括原版等待、
提示及失败处理。模拟器测试时可用下述单字节开关改为本地跳过；下载完成后跳过里程、
盒子和保存界面的规则不受该开关影响。

## 解锁模式

解锁模式是进入原版联网事务恢复流程的独立入口，不继承下载模式的 Bankdata 捕获、
下载后状态跳转或下载完成提示。

先确认所有卡带及数字版存档均无法与服务器匹配，再任选游戏，在确认时按住
L + A + START。未按组合键时仍显示原版不匹配提示；确认该提示后，原版恢复作业先
完成收尾与销毁，再重新进入功能选单第一项确认后的 state 10 游戏选择链，不返回选单，
也不直接复用旧的游戏选择界面。

原版所选游戏事务收尾完成后，按实际结果显示以下提示，并等待按键确认后正常断网退出，
均不进入里程和盒子：

- 无需恢复：“服务器状态正常，无需进入解锁模式。”
- 匹配存档后自动恢复成功：“已自动完成事务恢复。服务器锁定已解除。”
- 官方强制解锁成功：“强制解锁已完成。服务器锁定已解除。”

恢复成功提示要求原版提交／回滚确实返回成功，不能仅凭存档匹配或进入解锁界面判定。
联网失败、取消、候选值为空等情况保持各自原版处理。

```text
标题界面：解锁模式
        │
        ▼
功能选单：进入强制解锁模式
        │
        ▼
确认所有游戏均不匹配后，任选游戏，确认时按住 L + A + START
        │
        ▼
原版强制解锁挑战码状态
        ├── 服务器没有候选值 ─► 保留原版两行提示
        └── 存在候选值 ───────► 第三行显示第一个可接受的八位形式：
                                  “输入此解锁码: xxxxxxxx”
        │
        ▼
原版输入验证、回滚请求与所选游戏事务收尾
        │
        ▼
强制解锁完成提示 → 按键确认 → 原版断网并返回标题
```

服务器响应对象中保存了一组候选值；原版验证器会把输入值与每个候选值模
`100,000,000` 后的结果比较。补丁严格按同一规则显示第一个候选值，并由原版文本系统
补足前导零；不会自行生成解锁码、跳过校验、伪造成功或替换后续服务器操作。候选列表
为空时，界面仍使用未经修改的原版两行提示。

该模式仍共用项目级选单限制，但使用原版 Turtle 存储，默认保留原版 state 15 的票务与
联网礼物检查；事务请求与结果校验保持原版，仅调整上述提示后的分支。显示候选码的
钩子既不载入、也不上传本地离线
`bankdata.bin`。

## 票务与联网礼物：公开版与测试版

在 [`src/main.s`](src/main.s) 顶部修改以下值，然后重新编译：

源码默认采用公开策略 `0`；仅在个人测试允许缺接口时使用本地替代的情况下改为 `1`。

```asm
.definelabel ONLINE_TICKET_CHECK_BYPASS, 0
```

| 会话模式／环境 | `0`：公开版，必须正常检查（默认） | `1`：测试版，允许缺接口时自动替代 |
| --- | --- | --- |
| 离线，任意环境 | 本地 999 天使用权，不请求在线活动数据 | 同左 |
| 下载／解锁／原版，实机或未知环境 | 原版票务、活动与联网礼物检查 | 同左 |
| 下载／解锁／原版，已实现接口的 Azahar | 原版检查 | 同左 |
| 下载／解锁／原版，确认缺接口的 Azahar | 仍走原版，失败按原版报错；不提供伪造结果 | 自动选择本地票务结果 |
| 下载／解锁／原版，探测失败或正常票务错误 | 原版错误处理 | 原版错误处理，不自动放行 |

截至本次票务调整提交，Azahar 官方版本尚未实现 `am:net` 的
`GetRightsOnlyTicketData`（命令 `0x0821`，见[接口注册表](https://github.com/azahar-emu/azahar/blob/6280521bf26ef1393974cd8c898de29cf75f5752/src/core/hle/service/am/am_net.cpp#L115)）。
因此保留两种票务配置：`0` 不允许联网使用本地伪造结果，作为公开发行默认值；`1`
只在运行时确认 Azahar 缺少接口时自动使用本地结果，供作者测试。本项目作者的 Azahar
[`pokebank` 测试分支](https://github.com/Wokann/azahar/tree/pokebank)
已补全并经联网测试确认该接口可正常运行，所以使用该分支或实机时，当前值保持
`0` 即可，无需跳过票务检查。离线模式始终使用本地结果，不受该值影响。

上述 Azahar 功能实现全部由 AI 生成，不符合
[Azahar AI 使用政策](https://github.com/azahar-emu/azahar/blob/master/AI-POLICY.md)
对完整或大部分 AI 生成贡献的接收要求，因此仅保留在个人测试分支，不向 Azahar
官方主分支提交。

两条路线始终包含在同一套代码中；该定义只决定
`[0x003FEB68, 0x003FEB69)` 的一个策略字节。state 15 的入口和状态推进保持原版，
只转接 `0x002B0444`（作业启动）、`0x002B0464`（取得结果）和 `0x002B1994`
（解除绑定）三个调用点。初始化包装把作业、共享数据、会话模式和策略传给
`LocalTicket_InitializeSelected`，每个作业只选择一次后端，记录于 `0x003FAFF4`；
后续轮询与解除绑定沿用该结果，不在作业中途重新判断。原版仍负责分配、构造、结果检查、字段回填、
界面清理与析构；本地路径没有绑定网络客户端，故解除绑定直接返回成功。

本地结果提供主机当前时间和当前时间加 999 天的到期日；原版函数据此计算剩余天数、
小时数和有效标志。当前时间本身不加 999 天，仍供本地里程使用。购票次数为 `-1`
（未知），不伪造购票奖励；保留已有 EC 账户字段。免费活动窗口复用这两个日期，转换为
原版活动使用的十进制时间格式，由 state 15 计算免费标志及剩余时间，选单使用原版免费
使用文本。每次本地初始化均按主机时间重新生成窗口，不采用服务器的固定活动日期。
不启动系统 eShop 小程序或伪造其加载动画。作业完成标志与原版“票据有效且不少于 15 天”的成功分支
一致；主机时间获取失败或到期日超出原版年份范围时，走原版失败处理。

测试策略 `1` 复用加载器的 `GetSystemInfo(0x20000, 0)` 判别：只有返回成功、低位 ID
为 `2`、高位为 `0` 才认定为 Azahar。随后以非阻塞方式打开 `am:net`，向命令 `0x0821`
发送 title ID／ticket ID 均为 `0` 的只读查询，输出缓冲区仅 4 字节，不读取真实票据。
只有传输成功、精确响应头 `0x08210040`、结果为 `0`，且临时句柄关闭成功时，才选择
本地结果。这对应已核对版本的[未实现接口短响应](https://github.com/azahar-emu/azahar/blob/6280521bf26ef1393974cd8c898de29cf75f5752/src/core/hle/service/service.cpp#L155)。
完整响应、票据不存在、服务获取失败、传输失败或其他未知返回均保留原版；不会把一般
账号或联网故障当作缺接口。公开策略 `0` 不运行此探测，联网始终调用原版接口。

此策略不跳过 NNID、其他请求或服务器校验，也不改变下载退出、解锁事务、里程及盒子
分派。**测试策略不作为安全联网保证**。未发现 999 天到期日与显示用的使用权字段
直接序列化进 Bankdata 的通路；但本地主机当前日期会回填到共享对象，首次创建会将它
写入新 Bankdata 后上传，解锁／原版模式的原生里程与保存流程也可能回传据此计算的里程和
基点。已有银行的下载模式跳过里程／保存流程，但首次创建仍会上传。

服务器下载覆盖的是 Bankdata 主体，不会覆盖本次会话的票务当前日期；下一次原版
票务检查也不会撤销已经上传的 Bankdata 变更。仅凭客户端分析不能保证服务器会纠正
这些值。公开版保持 `0`，缺接口时接受原版报错，不将本地票务结果用于真实云端操作。

## 离线模式：启动、恢复与首次创建

离线模式只强制完成必要的联网状态，不创建相应远端作业。启动时按以下顺序判断本地
文件：

```text
检查 bankdata.bin 长度及偏移 0x15C 的格式头
        ├── 有效 ─────────────────────────────► 既有记录模式
        └── 缺失或无效
                  │
                  ▼
             检查 bankdata.bak
                  ├── 有效 ─► 完整读取并验证 0xBB518 字节
                  │            复制为 bankdata.bin；保留 bak
                  │            不生成 .break
                  │            └───────────────► 既有记录模式
                  └── 缺失或无效
                            │
                            ▼
             将每个实际存在的无效文件复制到对应 .break
             （初次尝试后，每个文件最多再重试 3 次）
                            │
                            └──────────────────► 原版首次使用模式
```

主文件有效或能从有效备份恢复时绝不生成 `.break`；缺失文件也不会生成虚假的
`.break` 占位文件。如果保全复制共四次仍失败，原无效文件保持不动，但不会阻止首次
创建继续进行。两份文件都不存在时直接进入首次使用流程。

原版首次使用判断和提示仍负责整个创建流程。补丁只跳过远端记录 ID 子状态，随后让
原版空对象初始化器取得可用的主机／账户值、创建 100 个本地化银行盒子，并写入真实
创建日期。最后的远端创建调用会替换为经过检查的完整 `bankdata.bin` 直接写入；首次
写入失败时删除残缺输出。

运行时离线使用期限按主机时间加 999 天设置，它与里程时间相互独立。有效本地文件中
已有的身份字段和创建日期不会被重写。

## 离线模式：读取与使用银行

```text
功能选单：使用 Pokemon Bank
        │
        ▼
原版游戏软件检查与游戏选择
        │
        ▼
本地银行数据连接提示（至少 2 秒）
        │
        ▼
精确读取并验证 0xBB518 字节 bankdata.bin
        ├── 失败 ─► 原版错误路线
        └── 成功
              │
              ▼
恢复原版元数据复制与所选游戏回调
        │
        ▼
需要时执行原版本地里程状态与领取界面
        │
        ▼
原版银行盒子与游戏交互
```

完整文件只会在选择游戏后载入。补丁绕过共用同步状态中的远端请求部分，再恢复其原有
本地子状态。盒子显示、Pokemon 移动、检查和游戏交互仍使用原版代码。

原版本地里程计算继续保留。离线模式只在本次状态实例中跳过两轮联网礼物查询，不清除
持久化的更新礼物标志，以便以后在官方环境中仍可使用。独立的远端使用权／活动状态则

等待界面、旋转动画和节奏音效仍由原版状态的初始化、更新与退出路径统一管理。合并
补丁只通过原状态对象报告本地工作完成，不再引入第二个界面或音效所有者；进入盒子前
由原版状态退出路径完成清理。

## 离线保存、提交与回滚

```text
原版完整银行序列化（0xBB518 字节）
        │
        ▼
写入 bankdata.tmp + 设置长度 + 刷新 + 核对实际写入量
        ├── 失败 ─► 报告保存失败；保留 bankdata.bin
        └── 成功
              │
              ▼
保存进度界面至少继续显示 2 秒
        │
        ▼
原版卡带／数字版游戏保存
        ├── 失败 ─► 删除 tmp；保留 bin 与 bak
        └── 成功
              │
              ▼
删除旧 bak ─► bin 改名为 bak ─► tmp 改名为 bin
```

本地暂存写入是同步操作，之后进入非阻塞状态机延时；画面继续刷新，文件不会重复写入。
只有原版游戏保存结果成功后才允许提交。删除、改名、关闭、文件长度、实际写入量、恢复
和回滚结果都会检查。选择不保存并结束时，不会安装新的 `bankdata.bin`。

## 原版模式

原版模式位于 R 键循环中的解锁模式之后。确认后重读原版 Turtle，使用原初始化、
事务恢复、票务与礼物检查、里程、盒子、保存及断开流程。原存档缺失时由该流程创建，
不从现有 SD 记录回填。完整功能选单、原始上屏文本、支持代码、Mover/eShop 和 HOME
功能均恢复；没有可用游戏存档时保留原版 HOME 询问。标题仍显示模式切换提示。

票务与下载／解锁共用公开／测试策略：`0` 必须正常检查；`1` 仅在确认 Azahar 缺少
接口时允许本地结果替代，不跳过其他官方操作。

这不是离线数据上传模式：不捕获或载入 `bankdata.bin`，也不在两份 Turtle 记录间同步。

### 注入空间来源与边界

地址均为运行时虚拟地址，范围采用 `[起点, 终点)`。定义见 [`src/main.s`](src/main.s)
及 [`symbol.inc`](include/symbol.inc)，实际落点见 `build/armips-symbols.txt`。
Bank 与 Mover 采用同一种固定原址扩容架构，但各自使用自己的段边界、启动和 SDK
地址；Bank 构建不引用 Mover 文件。

原版段与逻辑 BSS 边界：

| 原版区域 | 起点 | 声明大小 | 内容终点 | 页映射终点 | 权限 |
| --- | --- | --- | --- | --- | --- |
| `.text` | `0x00100000` | `0x213910` | `0x00313910` | `0x00314000` | 可读、可执行 |
| `.rodata` | `0x00314000` | `0x55370` | `0x00369370` | `0x0036A000` | 只读、不可执行 |
| `.data` | `0x0036A000` | `0x41ACC` | `0x003ABACC` | `0x003AC000` | 可读写、不可执行 |
| 逻辑 BSS | `0x003ABACC` | `0x4EE38` | `0x003FA904` | `0x003FB000` | 可读写、零初始化 |

逻辑 BSS 从声明的 `.data` 内容末端开始，并非从页映射末端开始。原版清零循环的
地址常量、构造函数遍历器及 `[0x00369050, 0x00369370)` 的 PREL32 构造表均保留。

扩容不移动原段或原变量：把原 BSS 显式补零放进镜像，随后添加分隔页与三页荷载。
ExHeader 的 `.data` 改为 `0x95` 页、大小 `0x95000`，BSS 大小为 `0`；原版
清零循环仍运行。镜像由 `0x2AC000` 增为 `0x2FF000` 字节，但运行时只比原版多映射
四页，即 `0x4000`（16 KiB）。

| `0x002B1B98`、`0x002B1BDC`，各 4 字节 | 标题退出的 UI 根对象读取及完成返回 | 等待原版公共提示视图清理，再销毁标题视图并重载所选记录与语言；原清理函数体保留。 |
| `[0x00313910, 0x00313A40)` | 原 `.text` 末页填充 | 为 Luma LayeredFS 避让 `0x130` 字节，不写入。 |
| `[0x00313A40, 0x00313B1C)` | 原 `.text` 末页填充 | 启动汇编和 `code_expansion.o`，合计 `0xDC` 字节。 |
| `[0x00313B1C, 0x00313FC0)` | 原 `.text` 末页填充 | 未使用可执行余量，`0x4A4` 字节。 |
| `[0x00313FC0, 0x00314000)` | 原 `.text` 末页填充 | 64 字节版本标识 `offline_patch_v1.0.0` 并补零。 |
| `[0x003ABACC, 0x003FA904)` | 原逻辑 BSS | 显式补零；保留原变量和原启动清零，不放荷载。 |
| `[0x003FAFF0, 0x003FB000)` | 原读写末页中、逻辑 BSS 之后的 16 字节 | 前 4 字节存会话模式、捕获结果（`0` 未尝试、`1` 已保存、`2` 失败）、R 键前态及标题选择；`+4` 存本次票务作业后端，`+5` 标记待完成的首次语言选择，`+6` 存本会话恢复结果（`0` 无、`1` 官方强制解锁成功、`2` 原版自动恢复成功），其余 9 字节保留。 |
| `[0x003FB000, 0x003FC000)` | 新增读写映射 | 零填充分隔页，不是未映射保护页。 |
| `[0x003FC000, 0x003FF000)` | 原 BSS 后新增三页 | 全部功能包装、C 后端和路径常量；实机由加载器启用执行权限。 |

离线、下载、解锁模式仍禁用或改道 HOME、支持代码与 eShop 入口，但不占用其函数体。
原版模式恢复这些原生路径；标题、功能、语言和 Turtle hook 按模式分派，不替换原存档
底层实现。

### 实机与 Azahar 共用加载器

发行使用同一套 `code.bps`、`exheader.bin` 与 `romfs/`。BPS 声明扩展后的目标
长度；Luma 根据新 ExHeader 分配加载空间，Azahar 的 BPS 加载器根据目标长度扩展
代码缓冲区。原段地址不移动，也不把整个 `.text` 延伸到其他原段。

启动加载器在原构造函数遍历之前执行：

1. `SVC 0x27` 把当前进程伪句柄转换为真实句柄。
2. `SVC 0x2A` 查询 `type=0x20000, param=0`，只有成功且返回 ID `2` 才认定为 Azahar。
3. `SVC 0x70` 对新增三页执行 `MEMOP_PROT=6`、权限 `RWX=7`。实机或已实现接口的
   模拟器必须正常返回成功。
4. 只对已识别的 Azahar，且未实现 SVC 导致 `r0` 原样保留输入句柄时，允许兼容继续。
   未知环境不允许这种兼容，其他非零返回仍按失败处理。
5. 关闭真实句柄。句柄或权限操作失败则停止，不进入新增页；成功恢复寄存器、栈及返回地址，继续原版
   构造函数遍历。

ExHeader 只修改必要的 `.data`／BSS 字段和 SVC 权限；当前输入只需补上 `0x70`。
其他能力描述和完整头部中的签名描述副本保留；这是 CFW 加载覆盖，不是重新签名的
官方 NCCH。票务测试策略复用同一环境判别函数，但另外检查票务接口响应；权限兼容
成功不代表票务接口可用，也不会自动启用联网本地结果。该探测不增加 ExHeader 服务权限。

公开依据见 [Luma 加载器](https://github.com/LumaTeam/Luma3DS/blob/master/sysmodules/loader/source/loader.c)、[Luma BPS 加载](https://github.com/LumaTeam/Luma3DS/blob/master/sysmodules/loader/source/bps_patcher.cpp) 和 [Azahar BPS 缓冲扩展](https://github.com/azahar-emu/azahar/blob/9e6f523a57fac9564ac0bf8286db3c3702d301ec/src/core/file_sys/patch.cpp)。环境识别对应 [Luma 查询实现](https://github.com/LumaTeam/Luma3DS/blob/master/k11_extension/source/svc/GetSystemInfo.c) 和 [Azahar SVC 实现](https://github.com/azahar-emu/azahar/blob/9e6f523a57fac9564ac0bf8286db3c3702d301ec/src/core/hle/kernel/svc.cpp)。

## 独立编译与安装

Bank 子项目不依赖 Mover 的源码或构建产物，可以单独完成代码编译、BPS／ExHeader 生成、十套语言
文本重建和静态验证。

需要准备 GNU Make、兼容 POSIX 的 shell、Python 3 和 devkitARM，并设置 `DEVKITARM`
环境变量。仓库自带 Windows 版 armips 与 Floating IPS；其他平台可通过 `ARMIPS` 和
`IPS_TOOL` 指定自行下载或编译的程序。

从用户自己的 Bank 本体 `00040000000C9B00` 提取输入：

1. 在 GodMode9 的 `Title manager` 中选择 Bank 本体并进入 `Open title folder`。
2. 选择可执行 `.app`，依次执行 `NCCH image options...` → `Extract .code`。
3. 再次选择同一 `.app`，执行 `NCCH image options...` → `Mount image to drive`，复制挂载
   分区中的完整 `romfs` 目录，同时复制挂载根目录的 `extheader.bin`。
4. 按以下结构放入工程：

```text
bank/rom/
├── exheader.bin
├── exefs/
│   └── 00040000000C9B00.dec.code
└── romfs/
    └── ...
```

将挂载得到的 `extheader.bin` 重命名为 `exheader.bin`。共用发行包使用完整 `0x800`
字节 ExHeader，它必须来自与代码相同的 Bank 本体。

基底代码必须为 `2,801,664` 字节，SHA-1 必须为
`5AB630856835DCF2DBDF9A62244DD19E46AE1C7C`。构建脚本会再次检查输入；代码镜像和
RomFS 和 ExHeader 不应提交或传播。需要使用其他 RomFS 路径时可显式覆盖 `ROMFS_SOURCE`。

从仓库根目录独立构建 Bank：

```sh
make -C bank clean
make -C bank
```

也可以进入子项目目录后构建：

```sh
cd bank
make clean
make
```

非 Windows 平台示例：

```sh
make -C bank ARMIPS=/path/to/armips IPS_TOOL=/path/to/flips
```

构建顺序为：编译九个 C 单元并输出反汇编 → 检查原代码和 ExHeader、补零并预留新增页
→ armips 注入加载器与功能对象 → Floating IPS 生成 `code.bps` 并复制配套 ExHeader
→ 重建十套语言
RomFS → 执行静态验证。完整输出为：

```text
release/00040000000C9B00/
├── code.bps
├── exheader.bin
└── romfs/
```

校验器检查基底哈希、ExHeader 精确改动、原构造与 BSS 边界、保留的原函数、加载器、
每个 ARM 钩子、原指令重放、模式分派、BPS 的三个 CRC／逐字节还原和全部本地化文本。
把完整 `00040000000C9B00` 复制到 `SD:/luma/titles/`，启用 Luma 游戏补丁；
Azahar 同样使用完整目录。两者都须移除同目录旧 `code.ips` 和 `code.bin`，不能混装。
构建只移除自身发行目录内生成的旧 IPS，不自动修改模拟器安装目录。
实机使用前请备份 SD 卡和游戏存档。
