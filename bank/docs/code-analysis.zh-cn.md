# Pokemon Bank 代码分析

本文记录受支持原版二进制的内存与数据结构、逐状态及事务分支，并对照当前补丁的差异。
当前维护补丁的
实现、事务规则和独立编译方式见 [`../README.zh-cn.md`](../README.zh-cn.md)。

## 目标与内存分布

- Title ID：`00040000000C9B00`
- 软件内部版本：v1.5
- 代码基址：`0x00100000`
- 解压代码 SHA-256：`2DCE4796F54807CF8A67F1CE6297BF472D969B30ED7A7E8E25C2A6C2BDC40ABF`

| 区域 | 虚拟地址 | 属性 |
|---|---|---|
| `.text` | `0x00100000–0x00314000` | 可读、可执行；实际内容结束于 `0x00313910` |
| `.rodata` | `0x00314000–0x0036A000` | 只读、不可执行 |
| `.data` | `0x0036A000–0x003AC000` | 可读写 |
| 逻辑 `.bss` | `[0x003ABACC, 0x003FA904)`，长度 `0x4EE38`；读写页映射至 `0x003FB000` | 可读写、零初始化 |
| 主线程栈 | 长度 `0x40000` | ExHeader 配置；SDK 后台线程另行分配栈 |

`.text` 的最后一个非零镜像字节位于 `0x00313910` 之前，因此映射为可执行的末页中有
`0x6F0` 字节填充。Ghidra 记录的最后指令/数据引用位置为 `0x003138EC`，最后函数结束于
`0x003138F3`。其后的 `.rodata` 不具备执行属性。

镜像在 `.rodata`（`0x00369370–0x0036A000`，`0xC90` 字节）和 `.data`
（`0x003ABACC–0x003AC000`，`0x534` 字节）末尾也有连续零值，但它们不等同于可执行空位。
Ghidra 的引用分别延伸到 `0x00369374` 和 `0x003ABFE0`，其中包括存储值为零的位置，因此不能
只依据原始零值扫描来分配空间。

仅增大 ExHeader 的 `.text` 大小会与起点为 `0x00314000` 的 `.rodata` 重叠。另一种扩容
方式是不移动原段和变量：将原 BSS 补零并纳入 `.data` 镜像，在其后新增页，再由启动
加载器调整新增页的执行权限。当前补丁的 BPS／ExHeader 布局与原函数保留范围见
[开发文档](../README.zh-cn.md#注入空间来源与边界)。

### 标题语言与用户选择

主机原存档 `data:/turtle` 是界面语言的唯一来源。启动 `0x002A47F4` 读取并校验原记录，
`0x0025C08C` 应用语言。记录缺失时先完成原版语言初始化，再进入标题；I/O 失败不授权格式化。

标题 L 复用原确认 `0x002D139C`，沿 `2 → 1 → 21 → 2` 返回标题。原存档保存成功后，
才同步所选用户的 SD 设置：缺失时复制完整有效的 `0x200` 字节，已存在时仅更新
`0x28–0x2B`，保留身份、事务、校验及未知尾部。切换模式或用户不重新选择界面语言或字库。

离线确认账户后，即使未切换用户，也先退役旧本地会话及正文缓存，再检查已结束日志对应
的银行正文及备份是否均已删除。确认缺失时先发布空银行基线，丢弃孤立的银行 tmp，
再进入原版首次创建；保留 `sav.bin` 内容及来源游戏存档。设置缺失仍按自身已发布依据恢复；
未结束、损坏的日志及设置／来源待处理文件不授权此重置。

当前模式为 START 上方的独立单行窗格，下方依次是 R 模式、L 语言与 HOME 提示。
使用原字号和整数坐标，模式／START／R／L／HOME 的下屏中心纵坐标为
`88/120/156/182/208`。START 与版权素材保持原位。布局及字体沿用原资源格式，
字体范围见[字库说明](../../common/docs/fonts.zh-cn.md)。

离线与下载模式在左上角以深灰色显示当前用户。标题或本地模式入口刷新用户表，浏览期间
使用内存列表；auto 为首项、最大编号为末项，不循环。十字键及左摇杆上下支持长按和加速，
C 摇杆不参与。最终选择由后台发布，入口等待确认后才采用该用户数据。
下载模式选择的是本地目标用户，不会切换官方联网账号。

不可用选项保留原名称并追加本地化禁用后缀。支持代码在各模式均可查看，仍使用原编码器
`0x002A4078`。仅观察 ACT／FRD 响应的错误或占位值，异常时追加“无效”，不替换身份、
不额外发请求；该标注不是官方账号认证或封禁检查。

正常 Bank 路径的核心状态链：

```text
0 → [1 → 21] → 2 → 3 → 5 → 8 → 15 → 9 → 4
4 --结果12--> 10 → 11 → [18] → 17 → 16 → 12
12 --有待领取内容--> 13 → 25
12 --无待领取内容--> 25
12 --要求回滚返回--> 19 → 20
25 --结果4--> 7                         保存
25 --结果21--> 19 → 20                 不保存
```

Pokémon HOME 是独立路径：

```text
功能选单：4 --结果23--> 28 → 29 → 27 → 19 → 20
HOME 直达：3 设置直达标志 → 5 → 8 → 15 → 9 → 28 → 29 → 27
```

state 28 与 state 16 使用相同更新函数，但工厂在 state 28 对象中设置模式字节 `+0x41=1`；其初始化函数会额外选择服务器连接消息。state 29 与 state 19 结构相同，都会调用 `0x001D5C28` 处理尚未结束的远端事务，但完成后的目的地分别是 HOME 控制状态 27 和普通断网状态 20。state 13 与它们无关，它是里程/奖励领取状态。

主业务顺序：

```text
初始游戏与账户确认
  → ACT/NNID 与网络会话
  → state 8 查询远端记录、账户模式和事务状态
  → state 15 检查账户使用权、票券或订阅状态
  → 新账户由 state 9 官方创建并上传初始 Bank 文件
  → 功能选单
  → 选择“使用宝可梦银行”及游戏
  → 事务恢复及 state 16 Bank 数据下载
  → state 12/13 判断并领取里程或奖励
  → Bank Box UI
  → 序列化、远端暂存、卡带保存、提交或回滚
  → 返回标题
```

## 网络状态

外层状态表显示，启动阶段的 state 8 完成后依次进入 state 15 使用权检查和 state 9 首次创建判断，随后进入 state 4 功能选单。state 8 调用远端接口虚表 `+0x11C`；其回调只复制小型远端记录描述并继续查询事务状态，不会把 `0xBB518` 数据指针传给 `0x002D11B0`。

选择“使用银行”后经过事务恢复并进入 state 16；HOME 路径则进入 state 28。state 16 与 state 28 共用 `0x002AF460`，调用远端接口虚表 `+0x16C`，并由 `0x002D11B0` 接收完整 Bank 数据体。

完整 Bank 文件请求链：

```text
0x002AF460 BankDataSyncState_Update（state 16 或 28）
  → 0x002A3550 发起完整数据请求
  → 0x002D11B0 BankRemote_DownloadSuccessCallback
  → Bank 对象载入
  → 同步随附元数据
  → 返回完成结果
```

`0x002D11B0` 的第 11 参数是完整数据指针，函数内由 `r7` 保存，并在 `0x002D1234` 传给对象虚表 `+0x0C`。文件长度由对象虚表 `+0x10` 返回。

数据同步状态 `0x002AF460`：

| 子状态 | 功能 |
|---:|---|
| 0 | 创建远端作业对象和回调上下文 |
| 1 | 请求完整文件及随附描述 |
| 2 | 等待完整数据回调；HOME 模式可从这里直接继续 |
| 3–9 | 应用并同步随附元数据 |
| 10/11/12 | 返回成功、普通失败或服务错误 |

### 首次使用时的 Bank 文件创建

state 9 的 `0x002AE568` 检查共享账户模式字节。只有该字节为 ASCII `'5'` 时才执行创建；其他账户直接跳过创建阶段。创建流程如下：

```text
state 15 完成账户使用权检查
  → state 9 内部阶段 4/5 取得官方初始化所需数据
  → 0x002AE8B0 初始化 100 个 Bank Box、附属表和日期字段
  → BankObject 虚表 +0x10 返回 0xBB518
  → BankObject 虚表 +0x08 序列化到新缓冲区
  → 0x002A37E0 提交初始 Bank 文件
  → 等待服务器成功回调后，state 9 才返回成功并进入功能选单
```

该路径没有调用本地 FS，也没有等待 Bank Box 的“保存记录”状态。`0x002A37E0` 自身建立上传数据源并调用远端接口，state 9 等待其异步成功回调；创建状态内没有调用后续普通保存使用的暂存、提交或回滚函数。因此正常完成首次创建后，即使随后从功能选单或盒子走“不保存并结束”，服务器上已经存在初始 Bank 文件。若首次创建上传失败，state 9 返回失败，下一次仍会再次进入无文件/创建分支。

网络文件传输采用控制面请求加 HPP/HTTP：

| 地址 | 功能 |
|---:|---|
| `0x00198A78` | HTTP 请求准备与启动 |
| `0x00199570` | HTTP 流式发送和接收线程 |
| `0x001C1EF8` | 构造含 `name="file"` 的 multipart 文件流 |
| `0x001C22F0` | 输出 multipart 前缀、文件体和后缀 |
| `0x00245414` | HTTPC 分块发送 |
| `0x002454A4` | 通知 POST 正文结束 |
| `0x002454C4` | 接收 HTTP 响应 |
| `0x002CC878` | 准备 BankObject GET |
| `0x002CC988` | 检查响应 `Content-Length` |
| `0x001B23E8` | 初始化 HPP POST 作业 |
| `0x001B2544` | 处理 HPP 结果、重定向和重试 |
| `0x001B2820` | 重建重试请求 |

HPP 中的四段资源是 `CACERT_PUBLIC_CA_5.der` 至 `_8.der`。HTTP 状态处理支持最多 5 次 `307` 重定向，`409/500` 可重试，错误响应缓存上限为 `0x2800`。

## BankObject 与 bankdata

Bank 对象虚表：`0x003626FC`。运行时对象头长 8 字节，文件内容对应 `obj_bank + 8`。

| 虚表偏移 | 地址 | 功能 |
|---:|---:|---|
| `+0x08` | `0x002CB870` | 序列化对象 `+8` |
| `+0x0C` | `0x0023650C` | 把输入文件载入对象 `+8` |
| `+0x10` | `0x002CB864` | 返回 `0xBB518` |
| `+0x14` | `0x00116294` | 初始化当前格式对象 |
| `+0x18` | `0x002BA490` | 载入 `0xACA48` 旧格式并升级 |
| `+0x1C` | `0x002CB84C` | 检查 `u16(data+0x15C)==2` |

运行时对象链：

```text
slot_address   = *(u32*)0x002ACEEC     ; 0x003AB938
root           = *(u32*)slot_address
manager        = *(u32*)(root + 0x1C)
obj_bank       = *(u32*)(manager + 0xCC)
bank_file_data = obj_bank + 8
```

对象使用前要求 `*(u32*)obj_bank == 0x003626FC`。磁盘文件固定为 `0xBB518` 字节；最低载入条件为 `u16(data+0x15C)==2` 和 `u16(data+0x15E)==100`。

### bankdata 结构

| 文件偏移 | 长度 | 内容 |
|---:|---:|---|
| `0x000000` | `0x17C` | 文件头、名称、版本和状态字段 |
| `0x00017C` | `100 × 0x1B56` | 100 个 Bank Box；每盒 30 个 `0xE8` 槽及盒级数据 |
| `0x0AAF14` | `30 × 0xE8` | Transfer Box 30 个槽 |
| `0x0ACA44` | `3000` | Bank 槽并行格式标签 |
| `0x0AD5FC` | `30` | Transfer Box 并行标签 |
| `0x0AD61A` | `2` | 保留或对齐 |
| `0x0AD61C` | `8 × 0x44` | 来源游戏概要 |
| `0x0AD83C` | `0x7260` | 图鉴类聚合数据 |
| `0x0B4A9C` | `4` | 本次存入、取出计数 |
| `0x0B4AA0` | `3000` | Bank 槽来源软件代码 |
| `0x0B5658` | `3000 × 8` | Bank 槽更新时间 |
| `0x0BB418` | `0x100` | 尾部标志和保留区 |

头部字段：`+0x000000` 为 64 位身份绑定值；`+0x000008` 为 10 个 UTF-16 名称缓冲区；`+0x000160` 为日期；`+0x000168/+0x00016C` 为远端内容编号；`+0x000170/+0x000174` 为计数；`+0x000178` 为 4 个标志字节。

当前格式的对象载入和序列化都是固定长度整块复制。bankdata 对象层未发现客户端校验和、MAC、压缩或解密函数；服务器上传端的内容规则不属于该对象 ABI。

### 槽位移动与更新时间

银行槽位的更新时间是 `0x0B5658` 开始的 3000 项 64 位数组，与宝可里程余额、
领取基点及票据到期日无关。原版先取得压缩日期，再通过 `0x001F2BD4` 转换为从
`2000-01-01` 起的秒数；数据对象的 8 字节头使运行时字段偏移成为 `0x0B5660`。

| 原版操作 | 日期调用点 | 时间戳处理 |
| --- | --- | --- |
| `0x001D86E0` 写入银行槽位 | `0x001D887C` | 写入新登记槽位的当前时间；传送盒／游戏存入银行可经过此处 |
| `0x001D95C8` 清空银行槽位 | `0x001D96E4` | 更新被清空槽位的时间；银行取出及替换操作也可能经过此处 |
| `0x002B9C94` 批量移动银行槽位 | `0x002B9DC4` | 给清空的来源槽使用当前时间，目的槽继承原记录的时间 |
| `0x002BA148` 银行内部单槽交换 | 不取新日期 | 宝可梦、格式标签、来源软件代码和既有时间戳一起交换 |

前三条路径原本调用 `0x001D3BF4`，传入根对象 `+0x138` 的联网上下文。
该函数检查日期输出指针，但不会先检查上下文是否为空；之后的 `0x0022E3E0`
需要有效的联网对象与锁。离线没有创建这个对象，因此不能沿用该时间查询。
这也解释了为什么传送盒存入银行会崩溃，而银行内部单个移动可以正常执行。

补丁只改上述三个 `BL` 调用点，由 `CombinePatch_SelectBankSlotDate` 按本次会话模式
分流：离线复用共用 `SystemTime_GetCurrentDate` 的主机当前日期，其他模式原参数不变地
调用原版 `0x001D3BF4`。本地日期不加 999 天；输出为空或日期不可用时返回失败，仍由
各原调用者执行其既有失败分支。槽位写入、清空、批量处理、时间戳转换与单槽交换的
其他指令不变，也不替换共享的联网上下文或互斥锁函数。

## 保存与上传

```text
0x002B2320 BankSave_SerializeAndStage
  → 0x002B2490 完成 0xBB518 序列化
  → 0x002B24A0 / 0x002A2504 远端暂存
  → 卡带和本地保存
  → 0x001D5D74 提交
  → 失败时 0x001D5C28 回滚
```

32 字节事务描述用于远端暂存、提交和回滚，不属于 bankdata。仅伪造 HTTPC 返回值不能完成保存，上层仍会等待 HTTP 状态、响应体、控制面结果和异步完成标志。

## 状态机、事务与补丁差异

文中的结论来自当前版本的反编译代码和补丁实际挂钩点。没有把外层状态结果码、HTTP
状态码和 Turtle 事务状态混为一谈：

- 外层状态编号为 `0–29`，当前状态保存在流程控制器中；
- 每个状态对象把业务结果写入对象偏移 `+0x30`，`0x002A5580` 据此选择下一状态；
- Turtle 记录偏移 `+0x1C` 的 `0/1/2` 是另一套持久化事务状态；
- HTTP `200/307/409/500` 等状态只属于更下层的传输作业。

### 外层控制器

| 地址 | 原版职责 |
|---:|---|
| `0x002A5580` | 根据当前状态编号和状态对象 `+0x30` 的结果码选择下一状态 |
| `0x002A593C` | 驱动状态对象的初始化、逐帧更新、结束和销毁 |
| `0x002A5A7C` | 为 `0–29` 创建对应状态对象；state 24 是结束哨兵，不创建对象 |

控制器还保存三个会改变分支的标志：

- 强制清理标志 `+0x1A`：置位后，任何当前状态都会先转入 state 20；
- 语言初始化标志 `+0x1B`：决定 state 0 后是否需要进入 state 1；
- HOME 直达标志 `+0x1C`：决定启动检查完成后进入功能选单还是直接进入 HOME 路径。

### 原版逐状态分支

下表是 `0x002A5580` 的实际转移规则。表中的结果码是当前状态对象 `+0x30` 的值；“其他”
表示该状态未明确接受的结果，通常会进入 state 20 清理，或进入 state 24 结束。

| 5 | `4 → 8`；`18 → 6`；`3/其他 → 20` | 建立网络/服务会话；版本过旧进入 state 6 |

state 12 表示存在待领取内容，在 state 13 表示领取完成。因此不能脱离当前 state 给结果码
指定一个全局名称。

### 原版具体场景

#### 已有语言的普通启动

```text
0 → 2 → 3 → 5 → 8 → 15 → 9 → 4
```

state 8 只查询远端记录是否存在、账户模式和事务概要，不下载 `0xBB518` 的完整 Bank
文件。state 15 处理使用权、票券、活动和在线礼物。state 9 对已有记录直接完成，对无记录
账户执行首次创建。

#### 首次启动与语言选择

```text
0 → 1 → 21 → 2
```

state 1 写入语言选择，state 21 使用与 state 20 相同的返回标题实现，但启用无提示变体。

#### 首次使用且服务器无 Bank 文件

```text
5 → 8（返回账户模式 '5'）→ 15 → 9
state 9：初始化 100 个盒子及附属字段
       → 序列化 0xBB518
       → 上传初始 Bank 文件
       → 4
```

初始文件在进入功能选单前已经上传。它不依赖稍后的 Bank Box“保存记录”流程；若该上传
失败，下次启动仍会进入首次创建分支。

#### 使用银行且没有未完成事务

```text
4 --结果12--> 10 → 11 → 18 → 17 → 16 → 12
12 --无需领取--> 25
```

state 11 根据账户模式和所选游戏记录选择恢复入口。state 18 检查当前用户 Turtle 记录，
state 17 检查所选游戏一侧的事务块。两边都没有未完成事务时，它们只完成一致性检查并继续。
state 16 此时才请求完整 Bank 文件。

#### 有本地里程或奖励

```text
16 → 12 --结果5--> 13 --结果5--> 25
```

state 12 判断是否需要显示领取流程，state 13 执行领取。没有待领取内容时，state 12 直接
返回结果 `6` 或 `12` 并进入 state 25。

#### 不保存结束

```text
25 --非结果4--> 19 → 20 → 2
```

state 19 处理仍存在的远端暂存事务，state 20 断开会话并返回标题。它与保存失败的
state 22 不是同一状态。

#### HOME 路径

```text
功能选单：4 --结果23--> 28 → 29 → 27 → 19 → 20
HOME 直达：3 --结果23--> 5 → 8 → 15 → 9 → 28 → 29 → 27
```

state 28 与 state 16 共用完整文件下载函数，但对象中的 HOME 模式字节使其走 HOME
专用后续分支。state 29 与 state 19 都清理未完成远端事务，但前者继续进入 state 27。

### 原版联网层次

| 层次 | 状态/函数 | 数据与用途 |
|---|---|---|
| 会话建立 | state 5 / `0x002AF1FC` | 建立互联网和服务会话，不传输完整 Bank 文件 |
| 账户概要 | state 8 / `0x002ACBDC` | 查询记录存在性、账户模式和小型事务描述 |
| 使用权 | state 15 / `0x002B0270` | 票券、订阅、活动和在线礼物状态 |
| 首次创建 | state 9 / `0x002AE568` | 初始化并上传完整 `0xBB518` 文件 |
| 完整下载 | state 16/28 / `0x002AF460` | 通过 `0x002D11B0` 接收完整 Bank 文件与随附描述 |
| 保存暂存 | state 7 / `0x002B2490` 后 | 上传序列化文件，服务器返回 32 字节事务描述 |
| 提交/回滚 | state 7、17、18、19、23、29 | 依据持久化事务状态提交或撤销远端暂存 |

HPP/HTTP 是这些业务状态之下的传输层。一个 HTTPC 调用成功不代表外层状态已经成功；
业务状态仍会等待响应体、控制面结果和异步完成标志。

### 原版 Turtle 事务记录

Turtle 是原版逻辑记录名 `data:/turtle`。已确认的序列化字段如下：

| 偏移 | 大小 | 内容 |
|---:|---:|---|
| `0x00` | 8 | 远端数据 ID |
| `0x08` | 8 | 未完成事务令牌/凭据 |
| `0x10` | 4 | 当前数据版本 |
| `0x14` | 4 | 更新版本 |
| `0x18` | 4 | 事务数据长度 |
| `0x1C` | 4 | 事务状态：`0` 无待处理、`1` 待回滚、`2` 待提交 |
| `0x20` | 4 | 完整性标记 `FEED` |
| `0x24` | 4 | 对序列化事务字段生成的校验值 |
| `0x28` | 2 | 语言 ID |
| `0x2A` | 2 | 日语汉字显示标志 |

事务状态不能脱离 `0x00–0x1B` 的描述字段解释。原版 state 18 会先比对远端元数据与
Turtle 描述：状态 `1` 调用远端回滚，状态 `2` 调用远端提交；描述不匹配时还会检查所选
游戏内的事务块。state 17 对所选游戏事务块执行同样的 `1=回滚、2=提交` 处理，成功后
清理对应游戏字段并再次保存游戏。

#### 原版正常保存

state 7 的关键内部阶段为：

```text
序列化完整 Bank 文件
  → 远端暂存，取得 32 字节事务描述
  → 把“状态 2 + 描述”写入所选游戏事务块
  → 保存所选游戏
  → 把“状态 2 + 描述”写入 Turtle
  → 保存 Turtle
  → 远端提交
  → 清理所选游戏事务字段并再次保存
  → 完成
```

如果所选游戏保存失败，原版改为把“状态 1 + 描述”写入 Turtle，保存 Turtle 后调用远端
回滚。若程序在中途退出，下一次使用时由 state 18 和 state 17 根据持久化的 `1/2` 恢复。

#### 离线保存事务

离线 state 7 保留原版状态机的游戏保存顺序，只替换远端文件操作：

```text

  → 原版子状态 6/7：把描述符及状态 1 写入来源、保存并轮询
  → 原版子状态 8/9：保存 Turtle 描述符及状态 0，之后进入原有后续流程

state 7：序列化 0xBB518，Stage 更新同会话的预留正文，不改变编号／版本／令牌
  → 回读 bankdata.tmp，持久化新的完整摘要，原版等待提示结束
  → 原版子状态 3/4：来源状态 2 + 描述符，保存并轮询
  → 原版子状态 5/6：保存完整 Turtle 描述符及状态 2
  → 子状态 9 的提交接口转向 RequestTransaction：确认原状态 2 请求，记录 COMMIT_DECIDED 并发布银行及备份
  → 保留 Turtle 状态 2 和描述符，不额外保存或强制改为 0
  → 原版子状态 13/14：只清来源 +0x08 的 64 位令牌，第二次保存并轮询
  → 原版成功提示；提交或清理失败保留原版错误及重启恢复路径

游戏保存失败
  → 原版子状态 7/8：保存 Turtle 状态 1 + 描述符
  → 子状态 11 的回滚接口转向 RequestTransaction，原版随后显示失败提示
```

本地服务生成原版布局的非零描述符，由原 setter 写入来源和 Turtle，不再跳过事务
字段赋值。state 11 的既有／未决模式恢复原分流：既有进入 state 17，未决进入 state 18。
state 18 先按 Turtle 编号／当前版本匹配，必要时再匹配所选游戏；状态 1 回滚、状态 2
提交、不匹配提示和组合键分支均使用原函数。state 17 随后处理来源令牌并保存。
离线 state 23 保留原版不匹配时识别的组合键、挑战值、数字键盘和回滚请求。
提供者 `0x002A2838` 将挑战值交给 `FsServer_Support`；服务核对未决预留，
生成三个不同的八位候选，由原分配器／容器及原观察者复制到 state 23。
提示沿用第三行显示第一候选；原键盘仍接受全部三个，输错重试、取消及请求失败
均走原版分支。通过后 `AuthorizeRollback` 再核对挑战、输入、事务及描述符，
只有授权的同一预留才接受回滚。挑战改变、事务改变或成功后重放均不继续授权。
成功后由原回调进入 state 17，继续原版来源令牌检查与保存；不直接改写另一份游戏存档。
这是本地密码协议，不实现官方算法，下载、解锁、原版模式仍使用官方请求及响应。
同会话的下载预留许可只在服务器上下文中保存；重启不凭日志或游戏版本重新授权暂存。

无预留的既有银行返回原 SDK 的已有状态 `2`；只有非零未决令牌返回 `4`，
不因服务首次创建而伪造锁定或空训练家元数据。前置记录查询不重复校验正文，
后续事务查询照常核对银行和参与文件。完整正文载入后直接计算同份内存快照的
CRC32，服务 I/O 使用可容纳完整银行的 1 MiB 缓冲，忙时回退 1 KiB 栈缓冲；日志已更新为版本 5。
状态／元数据及随后下载共用本次载入快照，仅正文提供标记实际下载。盒子操作不读取服务文件。
本地设置更新在连接服务器之前独立分派，使用 fs_system 的设置后端和现有事务记录，
不打开配置或扫描银行。原序列化／校验／保存成功与错误分支继续执行。

读取。新载入、来源选择、重新连接／重启及文件修改使相应视图失效，I/O 失败清空视图。
实际上传前重查主文件；外部编辑不在载入中即时同步，需重新载入才采用。实际短读、
关闭失败和新正文回读不符仍失败。
已结束事务和无服务记录的既有银行准备，从同一摘要读取流检查各盒分组／顺序；首次
登记及只读核对复用本次载入摘要，不另读全文或发送 100 次逐盒小读取。恢复和
未决阶段仍走原路径。同一原生票务作业共享配置及时间快照，新作业、显式重载／编辑、
购买／充值及地区变更时失效；下一次配置读取采用当前文本，不冻结全套配置。规范化配置按 512 字节合并
写入及验证，不省略源文件复核或中转检查。下载在本次原生载入内传递已验证的
正文快照，用于未修改银行的预留，不能授权对已被替换来源进行恢复。只读预留保留
原备份不动；实际上传前重新核对主文件，正文改变时先建立回滚快照。未修改的下载预留不提前
写重复 tmp，实际保存更新预留时才完整写入并回读。缺 tmp 的例外仅限 Bank 原生来源且
前后正文相同；已有损坏／不可读 tmp、其他来源和已修改正文仍拒绝。

新增入口钩子 `0x002B1CF8` 只在离线模式调用响应轮询包装。下载、解锁和原版模式

#### 本地日志格式与恢复依据

`/3ds/Bank/fakeServers/users/<userID>/transaction.bin` 是一份小端 `0x370` 字节记录，
对应共用的 [FsTransactionRecord](../../common/include/fakeServer/transaction.h)。两端分别编译同一独立服务器事务核心和文件系统实现，地址由各自的 SDK 地址表提供。

| 记录内偏移 | 大小 | 内容 |
|---|---:|---|
| `0x00` | `0x20` | LTX2、格式版本 5、记录大小、序号、内部事务序号、应用、操作、阶段 |
| `0x20` | `0x20` | 模式、参与文件、确认标志、来源类型、游戏代码、路径长度、预留 title ID |
| `0x40` | `0x220` | 272 个 UTF-16 单元的 NDS 路径；原生来源全零 |
| `0x260` | `0x20` | 原 SDK 布局的服务器描述符：编号、版本、长度、零对齐字、令牌 |
| `0x280` | `0x24` | 原版恢复显示资料：格式、姓名格式、13 单元训练家名、训练家 ID、游戏 ID |
| `0x2A4` | `0x04` | 零填充对齐 |
| `0x2A8` | `0x18` | bankBefore：存在标志、保留零、64 位长度、4 字节 CRC32、显式零保留字 |
| `0x2C0` | `0x18` | bankAfter |
| `0x2D8` | `0x18` | sourceBefore：仅 NDS 文件 |
| `0x2F0` | `0x18` | sourceAfter：NDS 第一次保存版本 |
| `0x308` | `0x18` | sourceClean：NDS 清理令牌后的版本 |
| `0x320` | `0x18` | turtleBefore |
| `0x338` | `0x18` | turtleCurrent：已发布版本 |
| `0x350` | `0x18` | turtleAfter：待发布目标 |
| `0x368` | `0x04` | 前 `0x368` 字节的 CRC32 |
| `0x36C` | `0x04` | 尾部零对齐保留字 |

整数保持小端；CRC32 四字节按高位在前存储。事务记录版本为 5，不持久化二进制配置，
旧配置快照不参与判断。旧 SHA-256 事务记录仍保全并拒绝，
不自动清空未决证据。`bankdata.bin`、
`sav.bin`、游戏存档和原 SDK 的描述符布局不变。CRC32 用于本地非对抗性的版本识别及
偶发损坏检查，不具备密码学认证或防碰撞保证。随机 `dataId`、令牌和挑战密码保持随机来源，
不由文件 CRC32 生成。配置中转标记改为 8 位十六进制 CRC32，合法用户配置值保留。

内部序号每次更新递增；内部事务号为首次记录序号。服务器 `dataId` 则为稳定非零随机
64 位值；每笔预留令牌随机生成且非零、不与上一笔相同，更新版本为当前版本加一。
原 SDK 请求的 `+0x14` 对齐字未被原调用填充，不参与匹配；令牌位于 SDK `+0x18`、
游戏事务块 `+0x08`，字段分别映射，不整块互拷。不使用文件时间或
原版 1/2 标记猜世代。先完整写 tmp、刷新、关闭及回读，将上一条正式日志保留为
`transaction.bak`，再改名发布并核对新 bin。有效主日志优先；仅 bin 缺失时从有效 bak
续办，不能自动提升 tmp。正式日志无效或未知版本时停止保全；无正式日志的纯暂存
按明确的本地策略放弃或结合已校验正文重建。bak 只保存
上一条已发布的小型日志，不是银行历史备份，不声称断电原子性。

首次 tmp 写入前建立零长度 `transaction.bak`。它不是权威数据，仅在主日志缺失且
原参与文件尚未有正式决定时允许重新判别；首份 tmp 创建、设长度或写入中断不会
因此永久锁住旧银行。暂存不作权威，银行接纳／备份恢复先发布新基线决定再清暂存。
设置基线标志位 `0x10` 不改变版本 5 的结构大小：已知 `turtleCurrent` 在后续银行／
来源事务和银行修复中持续继承，读取、写入及结束前核对完整设置文件。不符不重新
设基线、不覆盖可信 `sav.bak`。主设置确实缺失时可恢复摘要匹配当前基线的备份／暂存；
已结束事务且设置三份全失时，记录缺失、交原初始化，保留银行编号、版本及元数据。
未决设置全失或现存文件变化仍保全停止；正常格式化经记录的删除和重新初始化仍可完成。
首次无摘要设置先走原生格式校验，成功写入后建立基线；不能据此证明旧文件历史一致。恢复无法确定时保留相关文件，不清除未决原生事务。

阶段采用 PREPARING → SOURCE_PENDING → STAGED → COMMIT_DECIDED → PUBLISHED →
CLEANUP_PENDING → CLEANUP_READY → COMPLETED。银行／设置单文件无需来源保存。

只有正式文件缺失才检查上一版 `.bak`，不凭 `.tmp` 序号判定已发布。已结束或
不存在的旧令牌清理只在银行状态检查通过后确认，不提交或回滚当前预留。
原生保存事件也不替代 Gen5 文件实际 SavePoll、完整校验和发布。
日志不上传。单写入者、FS 刷新及设备持久化
仍是前提，不能把核心故障测试等同于实机断电保障。

### 实现边界

- Bankdata 本地载入验证固定长度、格式版本、盒数、组号及组内顺序；已有日志时还核对完整摘要，
  但无日志首次导入不能发现所有中部损坏，也不等同于服务器端内容规则验证。
- 下载模式仍依赖官方服务返回有效的账户、事务和完整文件数据。
- 解锁模式只能显示服务器响应中实际存在的候选值，不能保证服务器一定接受后续回滚。
- 离线模式生成本地描述符以复用原版状态机，不生成官方凭据；`transaction.bin` 管理
  文件发布与备份。原生游戏仍无完整快照，不保证跨存档原子性或双边回滚。
- 本文只记录当前二进制和当前补丁中已经落实的分支；服务器端未公开的检查不作确定结论。

## 本地服务接入

仅离线模式把银行、SD 设置及事务请求转向嵌入式服务。其他模式保留官方分派，下载模式
仅在明确导出时写本地文件；模拟器票务替代有独立能力判断，不替代官方认证或伪报 HOME 成功。

原下载状态 `0x002AF460` 保留 SDK 作业、观察者及 Bank 正文消费者。服务端持有完整响应，
客户端分帧复制至原下载缓冲，释放服务结果后才完成原作业。取消先解绑观察者并丢弃迟到结果，
界面析构不等待工作线程。

首次格式化进入原子状态 21，由 `0x002AC68C` 逐帧轮询 `FORMAT_TURTLE`。等待、成功与失败
沿 `0x002ABE08` 的原分支表处理。创建初始参数不依赖银行已经存在。原保存开始／轮询
`0x002B4AB4/0x002B4A20` 保留准备、结果与清理顺序，SD 设置发布交后台完成。

离线连接监控不查询尚未建立的官方会话，但仍处理本地错误及取消；在线模式保留原监控。

### 礼物与里程

原礼物回调 `0x002AB17C` 消费本地服务提供的正文。Gen6 写入来源游戏 Link 区并更新
其校验及银行内容编号；Gen7 沿原卡片插入、容量及重复处理。保存归普通银行／游戏事务，
不另设领取账本。

礼物查询 `0x002A9824` 在离线显示本地服务器连接文本。里程对话
`0x002AA990/0x002AAEC8` 仍使用立绘表 37、第 14 行，不用通用连接文本编号替换。
离线时间由本地服务按照主机时钟提供；在线继续使用官方服务响应中的时间。

### 个人主机地区

所选用户的地区及币种保存在 `user.conf`。明确数值保持固定，autoRegion 只在确认标题
选择后刷新，autoCurrency 从该个人地区推导币种；浏览经过用户不会修改其地区或余额。
Bank 不因此重写已有宝可梦的主机区域字段。
