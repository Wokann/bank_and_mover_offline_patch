# Pokemon Bank 代码分析

本文只记录对受支持原版二进制得到的静态分析结论，不描述补丁设计或构建步骤。原版逐状态
分支及其与当前补丁的对照见 [`state-machine.zh-cn.md`](state-machine.zh-cn.md)；当前维护补丁的
实现、事务规则和独立编译方式见 [`../README.zh-cn.md`](../README.zh-cn.md)。

## 目标与内存分布

- Title ID：`00040000000C9B00`
- 软件内部版本：v1.5
- 代码基址：`0x00100000`
- 解压代码 SHA-256：`2DCE4796F54807CF8A67F1CE6297BF472D969B30ED7A7E8E25C2A6C2BDC40ABF`

| 区域 | 虚拟地址 | 属性 |
|---|---|---|
| `.text` | `0x00100000–0x00314000` | 可读、可执行；实际内容结束于 `0x00313910` |
| `.rodata` | `0x00314000–0x0036A000` | 只读、不可执行 |
| `.data` | `0x0036A000–0x003AC000` | 可读写 |
| 逻辑 `.bss` | `[0x003ABACC, 0x003FA904)`，长度 `0x4EE38`；读写页映射至 `0x003FB000` | 可读写、零初始化 |
| 线程栈 | 长度 `0x40000` | ExHeader 配置 |

`.text` 的最后一个非零镜像字节位于 `0x00313910` 之前，因此映射为可执行的末页中有
`0x6F0` 字节填充。Ghidra 记录的最后指令/数据引用位置为 `0x003138EC`，最后函数结束于
`0x003138F3`。其后的 `.rodata` 不具备执行属性。

镜像在 `.rodata`（`0x00369370–0x0036A000`，`0xC90` 字节）和 `.data`
（`0x003ABACC–0x003AC000`，`0x534` 字节）末尾也有连续零值，但它们不等同于可执行空位。
Ghidra 的引用分别延伸到 `0x00369374` 和 `0x003ABFE0`，其中包括存储值为零的位置，因此不能
只依据原始零值扫描来分配空间。

仅增大 ExHeader 的 `.text` 大小会与起点为 `0x00314000` 的 `.rodata` 重叠。另一种扩容
方式是不移动原段和变量：将原 BSS 补零并纳入 `.data` 镜像，在其后新增页，再由启动
加载器调整新增页的执行权限。当前补丁的 BPS／ExHeader 布局与原函数保留范围见
[开发文档](../README.zh-cn.md#注入空间来源与边界)。

正常 Bank 路径的核心状态链：

```text
0 → [1 → 21] → 2 → 3 → 5 → 8 → 15 → 9 → 4
4 --结果12--> 10 → 11 → [18] → 17 → 16 → 12
12 --有待领取内容--> 13 → 25
12 --无待领取内容--> 25
12 --要求回滚返回--> 19 → 20
25 --结果4--> 7                         保存
25 --结果21--> 19 → 20                 不保存
```

Pokémon HOME 是独立路径：

```text
功能选单：4 --结果23--> 28 → 29 → 27 → 19 → 20
HOME 直达：3 设置直达标志 → 5 → 8 → 15 → 9 → 28 → 29 → 27
```

state 28 与 state 16 使用相同更新函数，但工厂在 state 28 对象中设置模式字节 `+0x41=1`；其初始化函数会额外选择服务器连接消息。state 29 与 state 19 结构相同，都会调用 `0x001D5C28` 处理尚未结束的远端事务，但完成后的目的地分别是 HOME 控制状态 27 和普通断网状态 20。state 13 与它们无关，它是里程/奖励领取状态。

主业务顺序：

```text
初始游戏与账户确认
  → ACT/NNID 与网络会话
  → state 8 查询远端记录、账户模式和事务状态
  → state 15 检查账户使用权、票券或订阅状态
  → 新账户由 state 9 官方创建并上传初始 Bank 文件
  → 功能选单
  → 选择“使用宝可梦银行”及游戏
  → 事务恢复及 state 16 Bank 数据下载
  → state 12/13 判断并领取里程或奖励
  → Bank Box UI
  → 序列化、远端暂存、卡带保存、提交或回滚
  → 返回标题
```

## 网络状态

外层状态表显示，启动阶段的 state 8 完成后依次进入 state 15 使用权检查和 state 9 首次创建判断，随后进入 state 4 功能选单。state 8 调用远端接口虚表 `+0x11C`；其回调只复制小型远端记录描述并继续查询事务状态，不会把 `0xBB518` 数据指针传给 `0x002D11B0`。

选择“使用银行”后经过事务恢复并进入 state 16；HOME 路径则进入 state 28。state 16 与 state 28 共用 `0x002AF460`，调用远端接口虚表 `+0x16C`，并由 `0x002D11B0` 接收完整 Bank 数据体。

完整 Bank 文件请求链：

```text
0x002AF460 BankDataSyncState_Update（state 16 或 28）
  → 0x002A3550 发起完整数据请求
  → 0x002D11B0 BankRemote_DownloadSuccessCallback
  → Bank 对象载入
  → 同步随附元数据
  → 返回完成结果
```

`0x002D11B0` 的第 11 参数是完整数据指针，函数内由 `r7` 保存，并在 `0x002D1234` 传给对象虚表 `+0x0C`。文件长度由对象虚表 `+0x10` 返回。

数据同步状态 `0x002AF460`：

| 子状态 | 功能 |
|---:|---|
| 0 | 创建远端作业对象和回调上下文 |
| 1 | 请求完整文件及随附描述 |
| 2 | 等待完整数据回调；HOME 模式可从这里直接继续 |
| 3–9 | 应用并同步随附元数据 |
| 10/11/12 | 返回成功、普通失败或服务错误 |

### 首次使用时的 Bank 文件创建

state 9 的 `0x002AE568` 检查共享账户模式字节。只有该字节为 ASCII `'5'` 时才执行创建；其他账户直接跳过创建阶段。创建流程如下：

```text
state 15 完成账户使用权检查
  → state 9 内部阶段 4/5 取得官方初始化所需数据
  → 0x002AE8B0 初始化 100 个 Bank Box、附属表和日期字段
  → BankObject 虚表 +0x10 返回 0xBB518
  → BankObject 虚表 +0x08 序列化到新缓冲区
  → 0x002A37E0 提交初始 Bank 文件
  → 等待服务器成功回调后，state 9 才返回成功并进入功能选单
```

该路径没有调用本地 FS，也没有等待 Bank Box 的“保存记录”状态。`0x002A37E0` 自身建立上传数据源并调用远端接口，state 9 等待其异步成功回调；创建状态内没有调用后续普通保存使用的暂存、提交或回滚函数。因此正常完成首次创建后，即使随后从功能选单或盒子走“不保存并结束”，服务器上已经存在初始 Bank 文件。若首次创建上传失败，state 9 返回失败，下一次仍会再次进入无文件/创建分支。

网络文件传输采用控制面请求加 HPP/HTTP：

| 地址 | 功能 |
|---:|---|
| `0x00198A78` | HTTP 请求准备与启动 |
| `0x00199570` | HTTP 流式发送和接收线程 |
| `0x001C1EF8` | 构造含 `name="file"` 的 multipart 文件流 |
| `0x001C22F0` | 输出 multipart 前缀、文件体和后缀 |
| `0x00245414` | HTTPC 分块发送 |
| `0x002454A4` | 通知 POST 正文结束 |
| `0x002454C4` | 接收 HTTP 响应 |
| `0x002CC878` | 准备 BankObject GET |
| `0x002CC988` | 检查响应 `Content-Length` |
| `0x001B23E8` | 初始化 HPP POST 作业 |
| `0x001B2544` | 处理 HPP 结果、重定向和重试 |
| `0x001B2820` | 重建重试请求 |

HPP 中的四段资源是 `CACERT_PUBLIC_CA_5.der` 至 `_8.der`。HTTP 状态处理支持最多 5 次 `307` 重定向，`409/500` 可重试，错误响应缓存上限为 `0x2800`。

## BankObject 与 bankdata

Bank 对象虚表：`0x003626FC`。运行时对象头长 8 字节，文件内容对应 `obj_bank + 8`。

| 虚表偏移 | 地址 | 功能 |
|---:|---:|---|
| `+0x08` | `0x002CB870` | 序列化对象 `+8` |
| `+0x0C` | `0x0023650C` | 把输入文件载入对象 `+8` |
| `+0x10` | `0x002CB864` | 返回 `0xBB518` |
| `+0x14` | `0x00116294` | 初始化当前格式对象 |
| `+0x18` | `0x002BA490` | 载入 `0xACA48` 旧格式并升级 |
| `+0x1C` | `0x002CB84C` | 检查 `u16(data+0x15C)==2` |

运行时对象链：

```text
slot_address   = *(u32*)0x002ACEEC     ; 0x003AB938
root           = *(u32*)slot_address
manager        = *(u32*)(root + 0x1C)
obj_bank       = *(u32*)(manager + 0xCC)
bank_file_data = obj_bank + 8
```

对象使用前要求 `*(u32*)obj_bank == 0x003626FC`。磁盘文件固定为 `0xBB518` 字节；最低载入条件为 `u16(data+0x15C)==2` 和 `u16(data+0x15E)==100`。

### bankdata 结构

| 文件偏移 | 长度 | 内容 |
|---:|---:|---|
| `0x000000` | `0x17C` | 文件头、名称、版本和状态字段 |
| `0x00017C` | `100 × 0x1B56` | 100 个 Bank Box；每盒 30 个 `0xE8` 槽及盒级数据 |
| `0x0AAF14` | `30 × 0xE8` | Transfer Box 30 个槽 |
| `0x0ACA44` | `3000` | Bank 槽并行格式标签 |
| `0x0AD5FC` | `30` | Transfer Box 并行标签 |
| `0x0AD61A` | `2` | 保留或对齐 |
| `0x0AD61C` | `8 × 0x44` | 来源游戏概要 |
| `0x0AD83C` | `0x7260` | 图鉴类聚合数据 |
| `0x0B4A9C` | `4` | 本次存入、取出计数 |
| `0x0B4AA0` | `3000` | Bank 槽来源软件代码 |
| `0x0B5658` | `3000 × 8` | Bank 槽更新时间 |
| `0x0BB418` | `0x100` | 尾部标志和保留区 |

头部字段：`+0x000000` 为 64 位身份绑定值；`+0x000008` 为 10 个 UTF-16 名称缓冲区；`+0x000160` 为日期；`+0x000168/+0x00016C` 为远端内容编号；`+0x000170/+0x000174` 为计数；`+0x000178` 为 4 个标志字节。

当前格式的对象载入和序列化都是固定长度整块复制。bankdata 对象层未发现客户端校验和、MAC、压缩或解密函数；服务器上传端的内容规则不属于该对象 ABI。

## 保存与上传

```text
0x002B2320 BankSave_SerializeAndStage
  → 0x002B2490 完成 0xBB518 序列化
  → 0x002B24A0 / 0x002A2504 远端暂存
  → 卡带和本地保存
  → 0x001D5D74 提交
  → 失败时 0x001D5C28 回滚
```

32 字节事务描述用于远端暂存、提交和回滚，不属于 bankdata。仅伪造 HTTPC 返回值不能完成保存，上层仍会等待 HTTP 状态、响应体、控制面结果和异步完成标志。
