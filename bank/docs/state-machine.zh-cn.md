# Pokemon Bank 原版状态机与补丁差异

本文记录受支持原版二进制中的外层状态机、联网与事务分支，并逐项说明当前合并补丁在
下载模式、离线模式、解锁模式和原版模式下的差异。内存布局、函数地址和数据结构总览见
[`code-analysis.zh-cn.md`](code-analysis.zh-cn.md)。

文中的结论来自当前版本的反编译代码和补丁实际挂钩点。没有把外层状态结果码、HTTP
状态码和 Turtle 事务状态混为一谈：

- 外层状态编号为 `0–29`，当前状态保存在流程控制器中；
- 每个状态对象把业务结果写入对象偏移 `+0x30`，`0x002A5580` 据此选择下一状态；
- Turtle 记录偏移 `+0x1C` 的 `0/1/2` 是另一套持久化事务状态；
- HTTP `200/307/409/500` 等状态只属于更下层的传输作业。

## 外层控制器

| 地址 | 原版职责 |
|---:|---|
| `0x002A5580` | 根据当前状态编号和状态对象 `+0x30` 的结果码选择下一状态 |
| `0x002A593C` | 驱动状态对象的初始化、逐帧更新、结束和销毁 |
| `0x002A5A7C` | 为 `0–29` 创建对应状态对象；state 24 是结束哨兵，不创建对象 |

控制器还保存三个会改变分支的标志：

- 强制清理标志 `+0x1A`：置位后，任何当前状态都会先转入 state 20；
- 语言初始化标志 `+0x1B`：决定 state 0 后是否需要进入 state 1；
- HOME 直达标志 `+0x1C`：决定启动检查完成后进入功能选单还是直接进入 HOME 路径。

## 原版逐状态分支

下表是 `0x002A5580` 的实际转移规则。表中的结果码是当前状态对象 `+0x30` 的值；“其他”
表示该状态未明确接受的结果，通常会进入 state 20 清理，或进入 state 24 结束。

| 当前 state | 结果码与下一 state | 对应场景 |
|---:|---|---|
| 0 | `5 → 1`（未选语言）；`5 → 2`（已有语言）；`6/其他 → 24` | 版本检查完成后决定是否需要语言初始化 |
| 1 | `5 → 21`；`6/其他 → 24` | 语言选择完成后，经无提示返回状态进入标题 |
| 2 | `4 → 3`；`3/其他 → 24` | 标题界面开始使用，或结束应用 |
| 3 | `4 → 5`；`23 → 5` 并设置 HOME 直达；`3/其他 → 20` | 游戏软件确认及普通入口／HOME 直达分流 |
| 4 | `12 → 10`；`13 → 14`；`23 → 28`；`3/其他 → 20` | 功能选单：使用银行、其他功能、HOME 或结束 |
| 5 | `4 → 8`；`18 → 6`；`3/其他 → 20` | 建立网络/服务会话；版本过旧进入 state 6 |
| 6 | 任意完成结果 `→ 20` | 版本过旧提示后清理返回 |
| 7 | `20 → 22`；`3/4 → 20`；其他 `→ 20` | 保存事务完成或进入保存失败处理 |
| 8 | `4 → 15`；`3/其他 → 20` | 查询远端记录、账户模式和事务概要 |
| 9 | `4 → 4`；HOME 直达时 `4 → 28`；`3/其他 → 20` | 已有记录则跳过；首次使用则创建成功后继续 |
| 10 | `5 → 11`；`19 → 4`；`6/其他 → 20` | 选择游戏成功、取消回选单或失败退出 |
| 11 | `9 → 18`；`10 → 17`；`11/其他 → 20` | 根据账户模式与所选游戏记录决定恢复路径 |
| 12 | `5 → 13`；`6/12 → 25`；其他 `→ 19` | 有待领取内容、无需领取或终止本次使用 |
| 13 | `5 → 25`；其他 `→ 19` | 领取完成后进入盒子；失败或取消走不保存结束 |
| 14 | 任意完成结果 `→ 4` | eShop/其他菜单功能结束后回功能选单 |
| 15 | `4 → 9`；`3/其他 → 20` | 使用权、票券、活动和在线礼物检查 |
| 16 | `4 → 12`；`20 → 22`；`3/其他 → 20` | 完整 Bank 数据下载成功、持久化失败或普通失败 |
| 17 | `4 → 16`；`20 → 22`；`3/其他 → 20` | 所选游戏侧事务恢复成功后下载 Bank 数据 |
| 18 | `4 → 17`；`22 → 23`；`3/其他 → 20` | 当前用户 Turtle 事务恢复成功、需要强制恢复或失败 |
| 19 | 任意完成结果 `→ 20` | 不保存结束前释放/回滚远端事务 |
| 20 | 任意完成结果 `→ 2` | 正常断网、清理并返回标题 |
| 21 | 任意完成结果 `→ 2` | 语言选择后的无提示返回标题变体 |
| 22 | 任意完成结果 `→ 20` | 保存失败提示后清理返回 |
| 23 | `9 → 18`；`4 → 17`；`14 → 24`；`3/其他 → 20` | 强制恢复后的重试、继续另一侧恢复或终止 |
| 24 | — | 外层流程结束哨兵 |
| 25 | `4 → 7`；其他（包括 `21`）`→ 19` | Bank Box：保存，或不保存结束 |
| 26 | 任意完成结果 `→ 0` | 图鉴类辅助入口完成后重新检查版本 |
| 27 | 任意完成结果 `→ 19` | HOME 操作结束后走不保存清理 |
| 28 | `4 → 29`；`3/其他 → 20` | HOME 模式下载完整 Bank 数据 |
| 29 | `4 → 27`；`3/其他 → 20` | HOME 前释放/回滚远端事务 |

同一个数值结果在不同状态中含义不同。例如结果 `5` 在 state 10 表示游戏选择成功，在
state 12 表示存在待领取内容，在 state 13 表示领取完成。因此不能脱离当前 state 给结果码
指定一个全局名称。

## 原版具体场景

### 已有语言的普通启动

```text
0 → 2 → 3 → 5 → 8 → 15 → 9 → 4
```

state 8 只查询远端记录是否存在、账户模式和事务概要，不下载 `0xBB518` 的完整 Bank
文件。state 15 处理使用权、票券、活动和在线礼物。state 9 对已有记录直接完成，对无记录
账户执行首次创建。

### 首次启动与语言选择

```text
0 → 1 → 21 → 2
```

state 1 写入语言选择，state 21 使用与 state 20 相同的返回标题实现，但启用无提示变体。

### 首次使用且服务器无 Bank 文件

```text
5 → 8（返回账户模式 '5'）→ 15 → 9
state 9：初始化 100 个盒子及附属字段
       → 序列化 0xBB518
       → 上传初始 Bank 文件
       → 4
```

初始文件在进入功能选单前已经上传。它不依赖稍后的 Bank Box“保存记录”流程；若该上传
失败，下次启动仍会进入首次创建分支。

### 使用银行且没有未完成事务

```text
4 --结果12--> 10 → 11 → 18 → 17 → 16 → 12
12 --无需领取--> 25
```

state 11 根据账户模式和所选游戏记录选择恢复入口。state 18 检查当前用户 Turtle 记录，
state 17 检查所选游戏一侧的事务块。两边都没有未完成事务时，它们只完成一致性检查并继续。
state 16 此时才请求完整 Bank 文件。

### 有本地里程或奖励

```text
16 → 12 --结果5--> 13 --结果5--> 25
```

state 12 判断是否需要显示领取流程，state 13 执行领取。没有待领取内容时，state 12 直接
返回结果 `6` 或 `12` 并进入 state 25。

### 不保存结束

```text
25 --非结果4--> 19 → 20 → 2
```

state 19 处理仍存在的远端暂存事务，state 20 断开会话并返回标题。它与保存失败的
state 22 不是同一状态。

### HOME 路径

```text
功能选单：4 --结果23--> 28 → 29 → 27 → 19 → 20
HOME 直达：3 --结果23--> 5 → 8 → 15 → 9 → 28 → 29 → 27
```

state 28 与 state 16 共用完整文件下载函数，但对象中的 HOME 模式字节使其走 HOME
专用后续分支。state 29 与 state 19 都清理未完成远端事务，但前者继续进入 state 27。

## 原版联网层次

| 层次 | 状态/函数 | 数据与用途 |
|---|---|---|
| 会话建立 | state 5 / `0x002AF1FC` | 建立互联网和服务会话，不传输完整 Bank 文件 |
| 账户概要 | state 8 / `0x002ACBDC` | 查询记录存在性、账户模式和小型事务描述 |
| 使用权 | state 15 / `0x002B0270` | 票券、订阅、活动和在线礼物状态 |
| 首次创建 | state 9 / `0x002AE568` | 初始化并上传完整 `0xBB518` 文件 |
| 完整下载 | state 16/28 / `0x002AF460` | 通过 `0x002D11B0` 接收完整 Bank 文件与随附描述 |
| 保存暂存 | state 7 / `0x002B2490` 后 | 上传序列化文件，服务器返回 32 字节事务描述 |
| 提交/回滚 | state 7、17、18、19、23、29 | 依据持久化事务状态提交或撤销远端暂存 |

HPP/HTTP 是这些业务状态之下的传输层。一个 HTTPC 调用成功不代表外层状态已经成功；
业务状态仍会等待响应体、控制面结果和异步完成标志。

## 原版 Turtle 事务记录

Turtle 是原版逻辑记录名 `data:/turtle`。已确认的序列化字段如下：

| 偏移 | 大小 | 内容 |
|---:|---:|---|
| `0x00` | 8 | 远端数据 ID |
| `0x08` | 8 | 未完成事务令牌/凭据 |
| `0x10` | 4 | 当前数据版本 |
| `0x14` | 4 | 更新版本 |
| `0x18` | 4 | 事务数据长度 |
| `0x1C` | 4 | 事务状态：`0` 无待处理、`1` 待回滚、`2` 待提交 |
| `0x20` | 4 | 完整性标记 `FEED` |
| `0x24` | 4 | 对序列化事务字段生成的校验值 |
| `0x28` | 2 | 语言 ID |
| `0x2A` | 2 | 日语汉字显示标志 |

事务状态不能脱离 `0x00–0x1B` 的描述字段解释。原版 state 18 会先比对远端元数据与
Turtle 描述：状态 `1` 调用远端回滚，状态 `2` 调用远端提交；描述不匹配时还会检查所选
游戏内的事务块。state 17 对所选游戏事务块执行同样的 `1=回滚、2=提交` 处理，成功后
清理对应游戏字段并再次保存游戏。

### 原版正常保存

state 7 的关键内部阶段为：

```text
序列化完整 Bank 文件
  → 远端暂存，取得 32 字节事务描述
  → 把“状态 2 + 描述”写入所选游戏事务块
  → 保存所选游戏
  → 把“状态 2 + 描述”写入 Turtle
  → 保存 Turtle
  → 远端提交
  → 清理所选游戏事务字段并再次保存
  → 完成
```

如果所选游戏保存失败，原版改为把“状态 1 + 描述”写入 Turtle，保存 Turtle 后调用远端
回滚。若程序在中途退出，下一次使用时由 state 18 和 state 17 根据持久化的 `1/2` 恢复。

## 当前补丁与原版的状态差异

| 节点 | 原版 | 下载模式 | 离线模式 | 解锁模式 |
|---|---|---|---|---|
| state 3 无可用游戏记录 | 提示后询问是否直接转移至 HOME | 询问是否直接下载服务器银行；确认后按原版直达入口联网 | 保留无记录／图鉴两页提示，按键确认后返回标题 | 同离线模式 |
| state 4 第一项 | 结果 `12 → 10`，选择游戏 | 结果 `12 → 28`，不选择游戏 | 保留原版入口 | 保留原版入口 |
| Turtle 存储后端 | 原版 `data:/turtle` 存储 | 确认模式后使用原存档后端 | 重定向到 `sd:/3ds/Bank/sav.bin` | 确认模式后使用原存档后端 |
| state 5 | 真实联网 | 保留原版 | 本地完成会话状态，不创建远端作业 | 保留原版 |
| state 8 | 查询服务器账户概要 | 保留原版 | 根据本地 `bankdata.bin/.bak` 判定已有数据或首次创建 | 保留原版 |
| state 15 | 远端使用权/活动检查 | 公开策略 `0` 保留原版；测试策略 `1` 仅在确认 Azahar 缺接口时使用本地结果 | 始终本地提供运行所需票券字段；禁用在线活动礼物 | 与下载模式使用同一策略 |
| state 9 | 服务器首次创建 | 保留原版创建、上传及子状态 7 的异步成功等待 | 创建本地初始 `bankdata.bin` | 保留原版创建和上传 |
| state 11 | 选择恢复路径 | 不进入 | 保留判断，但结果 `9` 直接改去 state 17，不进入 state 18 | 保留原版 |
| state 18 | 当前 Turtle 远端事务恢复与游戏匹配 | 不进入 | 不进入 | 保留原版请求、校验与组合键；不匹配提示确认后，清理完成再重建 state 10 |
| state 23 | 官方强制解锁挑战码及回滚 | 正常路径不进入 | 正常路径不进入 | 显示服务器第一个候选值；成功结果 `4 → 17` 标记本次已完成官方强制解锁，其他原版分支不变 |
| state 17 | 所选游戏远端事务恢复 | 不进入 | 保留原 UI/等待节奏，但不发远端提交或回滚 | 完成原版事务及游戏保存后，按无需恢复／自动恢复／强制解锁显示结果；确认后断网 |
| state 16 | 从服务器下载完整文件 | 不进入 | 从 `bankdata.bin` 载入完整对象 | 正常路径不进入 |
| state 28 | 不依赖游戏的完整文件下载 | 保留原版 `+0x41=1`，成功回调捕获已装载的当前格式记录 | 正常路径不进入 | 正常路径不进入 |
| state 29 | HOME 前远端释放及界面清理 | 保留原版作业与销毁，成功后改去 state 20，不进入 state 27 | 正常路径不进入 | 正常路径不进入 |
| state 12/13 | 本地里程加在线礼物 | 下载完成后跳过 | 保留本地里程；只跳过联网礼物查询 | 正常路径不进入 |
| state 25 | 正常 Bank Box | 下载完成后不进入 | 保留原版 Bank Box | 正常路径不进入 |
| state 7 | 远端暂存、游戏保存、提交/回滚 | 正常路径不会进入；若进入则保留原版 | 暂存、提交和回滚改为本地文件事务 | 保留原版 |
| state 19/20 | 远端释放、断网 | state 29 完成释放后直接进入 state 20 断网 | 本地清理并返回标题 | 保留原版 |

下载模式保留真实联网、首次创建、票务与联网礼物检查，使用原版 HOME 的完整文件下载
路线，但不进入 HOME 操作界面。它不选择游戏，也不进入依赖所选游戏的 state 11/18/17/16。
`+0x41=1` 使原版下载器从完整响应直接完成，不更新所选游戏的元数据或游戏／Turtle
事务记录。state 29 的远端释放和界面销毁仍执行，随后直接断网：

```text
有可用游戏：state 4 第一项 --结果12--> 28 → 29 → 20 → 2
无可用游戏：state 3 确认 --结果23--> 5 → 8 → 15 → 9 → 28 → 29 → 20 → 2
```

state 9 仅在服务器尚无银行时初始化并上传；进入子状态 7 后必须等待原版成功回调，
再请求完整服务器文件。上传失败仍走原版错误清理，不把上传前的内存对象当作下载结果。
下载进度和本地成功提示分别使用已有追加条目 `0x61/0x62`，本地捕获失败使用 `0x74`。
HOME、支持代码和 Mover/eShop
选单入口继续禁用或改道。下载与解锁模式在标题确认后重读原版 Turtle；其他保留的原版
初始化／保存操作使用原存档后端，不写入 `sav.bin`。

### 下载确认、响应与本地安装

1. state 3 检查可用游戏。无游戏时下载模式显示追加询问 `0x73`，按钮为“开始下载”
   （追加文本 `0x75`）及原版“取消”；取消通过结果 3 返回。原版模式仍使用 HOME 转移标签。
   确认先设置原版 `+0x44=1`，转入子状态 `0x12` 的 Turtle 检查，并不是直接联网。
   原载入／初始化及保存等待成功后，才给出结果 23。
2. 原账户、票务和首次创建状态正常运行。已有服务器银行跳过创建；尚无银行则初始化
   并上传，子状态 7 等待真实上传回调。本地文件是否存在不决定服务器建档分支。
3. 有游戏时由 state 4 的结果 12 转入 state 28；无游戏时由原直达标志令 state 9 的
   结果 4 转入 state 28，不需要所选游戏的事务恢复。
4. 完整响应回调 `0x002D11B0` 先通过 `SizedObject_LoadBody` 或
   `BankFile_LoadLegacyBody` 装载。旧格式分支把 `0xACA48` 字节复制到已经初始化的
   对象，并将版本改为 2。捕获钩子 `0x002D1248` 位于两条装载分支之后、原版保留上次
   会话标志的处理之前。
5. C 捕获函数确认装载对象的原 vtable、版本 2 和 100 个盒子，零只宝可梦同样有效。
   从对象 `+8` 复制完整 `0xBB518` 字节，复用现有临时写入与轮换函数。
6. 会话字节 `0x003FAFF1` 与原状态对象的响应标志独立：0 表示未尝试捕获，尝试前先置 2，
   写入及安装全部成功后才置 1。失败不改变原成功响应标志，也不省略原元数据更新。
7. state 28 的原直达标志跳过所选游戏的元数据／保存阶段；state 29 保留远端释放、
   回调、等待、音效及界面销毁。下载模式只将其成功去向从 HOME state 27 改为 state 20；
   本地捕获失败也继续清理，并使用新失败提示。

已有空银行照常下载，不触发 state 27 的空银行提示；首次建立的空银行先等官方创建成功，
再下载。请求失败仍走原错误处理，不制造假的空文件。state 29 远端释放失败时，即使本地
副本已经安装，也保留原远端报错。SD 错误及中断／重试情况见子项目 README 的分支表。
这些结论经客户端代码检查，不代表首次建档或服务器拒绝情况已经完成端到端联网测试。

原版模式对应表中的“原版”列，包括原版首次建档界面节奏、全部菜单功能、原始文本和
无游戏时的 HOME 询问。不捕获或载入本地 Bankdata；票务与下载／解锁共用公开／测试
策略，`0` 必须取得原版结果，`1` 仅在确认 Azahar 缺接口时允许本地替代。
标题界面仍显示模式提示。

公共启动／标题阶段使用 SD 预览。标题退出动画结束后，等待原版公共提示视图异步清理
完成，再销毁标题视图。随后检查并重载所选记录，清除上一后端
的 loaded 标志和待选语言缓存；应用其语言和字体后，后续状态重新创建提示／菜单视图，

### 离线保存事务

离线 state 7 保留原版状态机的游戏保存顺序，只替换远端文件操作：

```text
序列化 0xBB518
  → 写入 bankdata.tmp
  → 保留 Turtle 0x00–0x1B，只把 0x1C 设置为 2 并通过原版序列化器保存
  → 本地提交：轮换 bankdata.bin/.bak，再把 Turtle 0x1C 清零并保存

游戏保存失败
  → 保留 Turtle 0x00–0x1B，只把 0x1C 设置为 1 并保存
  → 本地回滚：删除 bankdata.tmp，再把 Turtle 0x1C 清零并保存
```

本地暂存不会生成服务器的 32 字节事务描述，因此补丁不再把空描述覆盖到 Turtle；它只
通过原版 setter 改变 `0x1C`，并继续使用原版对象序列化和校验值生成路径。

如果一次旧补丁或异常退出留下 `sav.bin+0x1C = 1/2`，离线入口不会执行原版 state 18：
state 11 的对应分支被改到 state 17，随后本地 state 16 载入成功时把状态恢复为 `0` 并保存。
若用户在到达本地载入前退出，状态暂时保留，但下一次完成这条离线路径时仍会清零。

## 实现边界

- Bankdata 本地载入验证固定长度、格式版本和盒数；它不等同于服务器端内容规则验证。
- 下载模式仍依赖官方服务返回有效的账户、事务和完整文件数据。
- 解锁模式只能显示服务器响应中实际存在的候选值，不能保证服务器一定接受后续回滚。
- 离线模式不尝试解释或伪造远端事务描述；`bankdata.tmp/.bin/.bak` 是独立的本地文件事务。
- 本文只记录当前二进制和当前补丁中已经落实的分支；服务器端未公开的检查不作确定结论。
