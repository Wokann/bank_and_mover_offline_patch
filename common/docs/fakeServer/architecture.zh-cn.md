# 嵌入式本地服务器架构

[共用功能](../../README.zh-cn.md) · [配置与目录](../../../configTemplate/templateForCopy/Bank/readme_fakeServer.zh-cn.md)

本地服务器是一套分别编译进 Bank、Mover 的 C 模块，不是独立网络进程，也不监听 HTTP。
它在 SD 卡上管理本地银行和个人配置，通过内存中的请求与响应连接原客户端。
官方服务器与本地服务器是两个独立后端；本地文件不会自动同步或上传至官方服务器。

## 职责划分

| 部分 | 负责内容 |
| --- | --- |
| Bank／Mover 客户端 | 原状态机、界面、宝可梦转换、原生存档读写及回调 |
| `common/src/fakeServer/` | 账户选择、配置、使用权、礼物、逐槽筛选、银行与事务决策 |
| `common/src/fs_system/` | 文件读写、保护性发布、来源镜像、系统设置及后台线程适配 |
| 各软件的 `include/fs_sdk.h` 等地址表 | 对应软件自己的 SDK 入口，不能在两端互换 |

公开业务接口为 [`fakeserverapi.h`](../../include/fakeServer/fakeserverapi.h)。
业务模块接收值与文件操作接口，不直接控制界面，也不借用已释放的客户端对象。

## 一次会话的数据流程

1. 标题显示用户表；确认 START 后绑定选定用户。需要自动刷新地区或币种时在此时应用，
   仅浏览经过其他用户不更新其个人资料。
2. 连接及票务请求读取所需基础配置。首次创建的初始参数请求不要求银行文件已经存在。
3. 下载请求读取并校验银行正文，再通过原 SDK 下载对象交付给客户端。
4. 客户端在自己的内存对象中编辑盒子。没有新的服务请求时，不因每帧更新或逐槽处理反复读 SD。
5. 保存请求把完整正文交给本地服务器，核对当前版本并暂存；来源游戏仍由客户端原保存流程处理。
6. 原提交／回滚请求推进同一份持久事务记录，发布银行并在原回调确认后清理令牌及工作文件。

Mover 在传送时另提交一次整盒筛选请求。服务端只加载所选 NDS 或 VC 的规则和词表，
处理完释放相关动态内存；客户端继续执行原本的本地检查和转换。

## 后台任务与响应生命周期

`async_task`、`request_broker`、`native_transport` 和 `service_worker` 共同管理后台任务。
提交时复制请求数值、路径及必要正文；工作线程不持有界面字符串或宝可梦对象指针。
界面每帧非阻塞轮询，锁忙或结果尚未完成时保留原等待状态与动画。

银行下载正文由原 SDK 分配并持有，每帧最多交付 64 KiB。必须完整复制、释放服务结果后，
才调用 SDK 完成入口；之后由原观察者、正文消费者及析构处理对象。
取消时先解绑观察者，再取消本地任务和 SDK 作业；界面析构不等待后台线程。
同一地址上的新请求不能收到已经取消的旧结果。

票务适配沿原 EC 作业入口、完成与释放顺序执行。不同原调用方的同步／异步 ABI 保留，
不能把每个底层文件函数都改成立即返回的异步接口。原同步等待不会依赖下一帧界面才能完成。
目录模板服务不受支持时直接完成失败，不把未启动的作业留在等待状态。

服务线程有独立 64 KiB 栈；1 MiB 任务正文缓冲与 1 MiB 存储 I/O 缓冲分开。
Mover 另有 512 KiB Gen5 工作镜像。动态规则与词池使用可释放的堆内存；内存不足返回失败，
不进入无限分配等待。后台化保持界面响应，不代表消除了 SD 操作本身的耗时。

## 读取、校验与缓存

银行载入以同一份实际字节完成结构检查和 CRC32。一次载入内，后续正文读取优先复用
已经验证的内存视图；日志、设置和配置仍各自读取，不把大正文缓存当作事务依据。
重新选择来源、重新连接、重启、文件修改或不确定的 I/O 结果会使相关观察失效。

真正保存前重新核对主银行及所选来源，避免以旧内存镜像覆盖外部替换的数据。
写入、刷新、关闭后回读完整目标，再建立新的观察。同长度外部改动不会即时反映到
已经交付的内存正文；重新连接才能载入，不能同时由多个程序写同一用户目录。

CRC32 用于本地版本识别与偶发损坏检查，不提供抗恶意篡改认证。
银行 `dataId`、事务令牌与挑战候选由随机源生成，不由 CRC32 推算。
原版宝可梦和游戏存档的校验／加密保持原流程。

## 配置增删与实时重载

[`server.conf`](../../../configTemplate/templateForCopy/Bank/fakeServers/shared/readme_server.zh-cn.md)
保存共享政策；[`user.conf`](../../../configTemplate/templateForCopy/Bank/fakeServers/users/readme_user.zh-cn.md)
保存个人使用券、余额及地区；[`client.conf`](../../../configTemplate/templateForCopy/Bank/client/readme_client.zh-cn.md)
保存用户注册表及当前选择。缺失基础字段按默认顺序补齐，已有合法值保留。
礼物与 Mover 附加配置由玩家提供，缺失不自动创建。

各业务请求读取当前所需文本。同一票务作业共享自己的快照；免费活动请求独立取得时间、
地区和政策，不依赖票务作业先运行。后续配置编辑不重新解释已返回结果、已暂存正文或已记录的提交决定。

`FsServer_EditConfiguration` 提供基础配置的批量键／段编辑，不是游戏内编辑菜单。
配置发布先写暂存、校验和回读，再保留旧主文件并改名发布；相同内容不写入。
姓名词表、礼物和筛选规则保持只读；用户汉化许可仅在内存中将
`rule.BanUnicodeChinese` 视为关闭，不修改共享规则，也不生造缺失配置。

基础配置使用 [`protected_file`](../../include/fs_system/protected_file.h) 的公共发布机制。
主文件缺失时可读取其备份；孤立暂存不是正式内容。I/O 失败不等于文件缺失。
普通配置备份不能代替银行或游戏事务恢复。完整文件清单见
[写入文件与保护策略](../../../configTemplate/templateForCopy/Bank/readme_fakeServer.zh-cn.md#写入文件与保护策略)。

## 保存、恢复和回滚

每个用户的 `fakeServers/users/<用户ID>/transaction.bin` 协调银行、客户端设置及所选数字来源，
不是礼物领取账本。记录包含随机描述符、版本、阶段、参与文件摘要和来源路径。
原生游戏的事务匹配仍由客户端执行，不添加一套猜测官方状态的存档块摘要。

正常提交阶段为：

```text
PREPARING → SOURCE_PENDING → STAGED → COMMIT_DECIDED → PUBLISHED
          → CLEANUP_PENDING → CLEANUP_READY → COMPLETED
```

具体操作可跳过不适用的参与方阶段；已经记录提交决定后只向前完成。
未决事务仍需原匹配／保存回调，不因一个文件存在或摘要相同就伪报保存成功。
回滚和强制回滚使用各自明确记录的决定；重复调用不能把已完成事务重新当作未决工作。

| 文件 | 发布与保留 |
| --- | --- |
| `bankdata.bin/.bak/.tmp` | 实际修改才保留旧主银行为备份；完成后不把新版反写到备份。只读进入不轮替。 |
| `transaction.bin/.bak/.tmp` | 保留上一条已发布决定；主日志缺失才考虑有效备份，暂存日志不作恢复依据。 |
| `sav.bin/.bak/.tmp` | 使用设置专用事务保护，保留修改前副本及完整摘要。语言同步只改语言字段。 |
| 所选 `x.sav/x.bak/x.tmp` | 同名来源文件位于同一目录；原保存和清令牌保存均确认后清理 bak/tmp，中断时保留。 |

合法日志优先于文件时间或暂存序号。无效、未知或不可读的主日志不会被当作“没有日志”。
本地日志格式为 CRC32 v5；旧 SHA-256 日志不兼容，也不自动删除。
格式详情见 [Bank 日志布局](../../../bank/docs/code-analysis.zh-cn.md#本地日志格式与恢复依据)。

### 删除、损坏和手动换入的处理边界

以下规则针对本地服务器；官方模式仍走官方事务。

| 文件情况 | 处理 |
| --- | --- |
| 有效日志及匹配银行 | 沿已有预留、提交或回滚状态续办。 |
| 无正式日志，主银行结构正常 | 以主银行登记新基线，再清理不再适用的银行／日志暂存。 |
| 无正式日志，只有合法银行备份 | 作为新银行接纳并登记基线，不声称还原了旧事务。 |
| 主银行与已记录的前后版本都不同 | 按手动替换接纳新银行、放弃旧服务预留；不恢复已从旧游戏删去的宝可梦。 |
| 主银行缺失／损坏，存在日志确认的备份 | 仅按已记录摘要及事务阶段恢复，不能随意取较旧文件覆盖。 |
| 银行全部缺失、旧日志有效 | 登记空基线；Bank 走首次创建，Mover 下载失败并要求先启动 Bank。 |
| 无正式日志且仅剩 tmp | 放弃纯暂存；Bank 按无数据初始化，Mover 不代建银行。损坏正式日志不适用此规则。 |
| 设置缺失 | 有匹配当前基线副本时恢复；已结束事务且三份均缺失时交原初始化；未决且无法恢复时停止。 |
| 来源存档被替换或工作文件不匹配 | 保留文件并停止不安全写入，不写向其他来源，也不扫描其他游戏来猜测恢复目标。 |

多种损坏同时存在时不能只套用最宽松的一行。替换新银行不能恢复上一次传输，
强制解锁也可能造成宝可梦丢失。文件回读与刷新不构成跨存档原子性或真实断电持久化保证，
重要数据仍需独立备份。

## Mover 可选判定和词表

NDS 与 VC 分别使用 `checkPokemon.conf` 和 `checkName.conf`。全局关闭时跳过后续内容；
一次请求只加载所选来源，按实际内容和可用内存分配，非法词条只跳过该条。

`checkPokemon.conf` 的每个 `rule` 使用 `enabled`、`action` 和以分号结束的 `condition`，
条件支持跨字段 `&&`、`||`、括号和换行。`checkName.conf` 使用 NGWord 表达式及精确白名单。
这些是本项目的可配置规则，不等于官方完整检测服务。

服务返回逐槽数值，客户端按原流程处理：

| 结果 | Gen5 | VC |
| --- | --- | --- |
| 允许 | `0` | `0` |
| 空槽 | `20` | `20` |
| 拒绝 | `1` | `1` |
| 改昵称／OT／两者 | `250/251/252` | `253/254/255` |

`user.conf` 的 `[custom]` 属于当前账户，两个选项默认关闭。`allowFanTranslationCHN`开启时使用指定美版／韩版 VC 汉化码表，保留
Gen5 已有的 UTF-16 中文，并仅在当前账户内存中关闭 Unicode 汉字拒绝规则；普通筛选和 NGWord 仍有效。
VC 英、法、意、德、西文来源使用美版汉化表，并保留各语言原单字节字符的解读；
韩版金银独立使用韩版表，日文不转码。两条汉化路径均支持单双字节混排，
选择依据是原版所选游戏的版本／语言分类，不是姓名内容或主机地区。
`enableMoverv1.2` 也默认关闭，仅切换离线 RGBY 的旧性别、闪光和姓名转换机制。
详细字段、编码范围及数据来源见
[宝可梦筛选说明](../../../configTemplate/templateForCopy/Bank/fakeServers/shared/mover/readme_checkPokemon.zh-cn.md)与
[姓名规则说明](../../../configTemplate/templateForCopy/Bank/fakeServers/shared/mover/readme_checkName.zh-cn.md)。

## 礼物与原版接收

`gift.conf` 先读取全局开关，再检查各活动开关、日期、地区和素材。
活动名由玩家定义；六批预设按时间使用 `01_` 至 `06_` 前缀并默认开启。
PL6 与配置的 WC6/WC7 内容由服务端组装，原客户端负责采用、重复处理、提示及正常保存。
不另建领取账本，不额外阻挡原版允许的重复领取。

Gen6 Link 区和 Gen7 卡片槽的格式、容量及可承载字段各不相同，不能把任意卡片直接
当作完整服务器响应。支持范围与预设来源见
[礼物配置](../../../configTemplate/templateForCopy/Bank/fakeServers/shared/gifts/readme_gift.zh-cn.md)。

## 功能边界

- 本地服务器不提供官方账户认证、官方客服口令算法或本地银行上传。
- HOME 转移不接入本地服务；在线模式保留原远端流程。模拟器缺失接口时的票务替代有独立能力判断。
- 支持代码由原客户端从主机身份生成；本地只标注明显无效的身份响应，不伪造账号。
- 同一用户目录不支持多进程同时写入；不同设备复制数据时仍需保持银行与来源存档一致。
- 文件自动恢复依赖可用记录，不能重建已经删除且无副本的数据。
