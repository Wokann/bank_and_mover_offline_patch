# 跨语言字库补全

[English](fonts.md)

## 覆盖范围

Bank 和 Mover 的 `romfs/a/0/2/3` 包含三份主字库：共用字库（含日文、韩文和西文）、
简体中文字库、繁体中文字库。各语言的主字库均补齐以下字符：

- 默认银行、群组、盒子名称，包括“银行／銀行、群组／群組、盒子”。
- 项目十套名称资源中第 1～807 号宝可梦名字所需的字符。
- 三份原字库已有的非 CJK 字符，覆盖原版假名、拉丁文、韩文、标点和专用字符。

原版输入与转换表 `a/0/0/3` 的全部语言子文件另行校验：合计 471 个非空、非结束符字符，
三份补全后的主字库均可表示。键盘和输入规则不变，不因此增加中文输入法或额外可输入字符。
较小的辅助字库继续保留上下箭头补字；数字字库不改。

这不是完整 Unicode／全量 CJK 字体。任意汉化版、外部手填用户名、昵称或群组名仍可能
包含上述范围以外的字；不会把缺字自动替换成外形相似的其他字符。

## 构建与内存

补字只在 PC 构建资源时执行。字形完全来自用户提供的两端原字库：有完全相同的像素、
边缘采样和字宽时复用现有字形，否则复制原生像素到新字格，不缩放或重新绘字。
保留全部原字符的字形编号、字宽及完整采样边缘；不改变游戏存档里的文本编码。
名称 JSON 只用于收集所需字符，不采用其中人工解码的 `glyph_map` 推定字形。

普通空字格不足时重排图集，限定为 3DS 支持的二次幂尺寸；纹理总字节及绘制图页数量
均不得增加。字符表中的空洞直接补入原 TABLE，不能仅在链尾追加一张会被原表遮挡的映射。
所有 FINF、TGLP、CWDH、CMAP 偏移及链表都重新校验。

运行时仍沿原路径把当前字体整体载入内存，切换字体时先释放旧字体；不是逐字从 SD 读取。
补字不增加后台作业、配置文件、存档写入或新的字体堆。共用字库只增加少量映射／字宽数据，
简繁字库利用更紧凑的图集减少纹理占用。图鉴等同时使用多份字体的场景仍需计入各份资源，
不能把“主界面当前字体”当作所有场景的完整内存预算。

## 完整性要求

资源完整性要求包括全部原字格及边缘逐像素一致、原字宽和编号保留、名称与键盘字符覆盖、
原生链表查找、TABLE 空洞、重复构建一致性、纹理上限及缺少字形时的构建失败保护。
这不替代实际模拟器／实机上的语言切换和界面显示验证。

## 格式依据

原字体素材、原版字体切换／图鉴管理代码及输入表结构是主要依据。
下列独立开源实现用于交叉核对格式，不作为外来字形来源：

- [libctru：CFNT、字宽、纹理和字符映射结构](https://github.com/devkitPro/libctru/blob/master/libctru/include/3ds/font.h)。
- [libctru：字符查找、映射链与图页定位](https://github.com/devkitPro/libctru/blob/master/libctru/source/font.c)。
- [citro3d：纹理尺寸检查与 A4 格式](https://github.com/devkitPro/citro3d/blob/master/source/texture.c)。

上述格式交叉检查不能单独证明具体游戏界面的完整运行效果；图集重排还以本地原资源
逐像素校验为依据，最终显示效果需在对应软件中验证。
