# 在线与离线合并补丁

原版程序的内存分布、网络路径、BankObject 与传送盒结构见
[`docs/code-analysis.zh-cn.md`](docs/code-analysis.zh-cn.md)。本文只说明当前补丁的设计、
实现与独立构建方法。

构建保留原版启动初始化函数，将新增功能放到原 BSS 后的独立页。同一份 `code.bps`
及配套 `exheader.bin` 同时用于 Luma 和 Azahar：BPS 声明扩容后的镜像长度，启动
辅助函数自动处理权限修改。实机必须成功执行 SVC `0x70`；只有明确识别为 Azahar，
且未实现调用保留输入进程句柄时，才允许兼容运行。不再使用布局开关，也没有覆盖
初始化区的回退路径。静态检查不能替代实机或模拟器全流程测试，具体边界见分析文档。

这是 Poke Mover v5.5.0 本体 `00040000000C9C00` 当前维护的补丁。它把已经验证的
独立离线功能与官方联网银行／事务流程合并在一起；第五世代来源重定向由两种模式共用。

Poke Mover 没有下载模式。它既不会创建新的本地银行，也不会下载本工程所用的本地
文件。请先使用 Pokemon Bank 合并补丁的下载模式取得
`sd:/3ds/Bank/bankdata.bin`，或通过 Bank 离线模式的首次初始化生成该文件，再使用
Poke Mover 的离线模式。已经废弃的 Mover 独立下载实验不属于正式流程。

上传补丁也已经永久废止。离线传送只提交到本地银行文件，本工程不会把它上传至官方
服务。

## 模式选择

首次启动时标题界面默认显示**离线模式**。按实体 **R** 键可在**离线模式**和**在线模式**之间
切换。模式文字位于 HOME 选单说明下方，使用与 Bank 补丁相同的按键字形，并会立即
刷新。返回标题时保留刚才使用的模式；重新启动软件才恢复默认离线。选择只保存在
运行内存中，不写入存档。

按 **A**、**START** 或触摸下屏时，当前显示模式会锁定为本次会话模式。离开标题
界面后 R 键不再切换模式。

```text
标题界面（默认：离线模式）
        │
        ├── 按 R ──────────────► 在线模式
        ├── 再按 R ────────────► 离线模式
        └── A / START / 触摸
                  │ 锁定当前显示模式
                  ├── 离线 ─► 本地 bankdata.bin 与本地事务
                  └── 在线 ─► 官方联网与服务器流程
```

## 银行与联网流程严格隔离，来源重定向共用

各个运行时钩子都会先读取已经锁定的会话标志。离线模式进入本地实现；
在线模式则精确重放被覆盖指令，或恢复原函数后续路线，包括：

- 网络可用性与连接作业；
- 票据处理；
- 第五世代及第一／二世代合法性请求；
- 服务器银行数据下载；
- 传送资格与候选构造状态；
- 远端暂存、提交、回滚和断开连接。

上述隔离只针对银行后端、联网事务、票据和合法性服务。第五世代来源发现及被选中
数字版 `.sav` 的读写是两种模式共用的输入层；它不会把在线模式切换到本地银行。

因此，在线模式不会读取、写入、创建、改名或删除本地的 `bankdata.bin`、`bankdata.tmp`
或 `bankdata.bak`，
并保留官方服务器流程及对应联网提示；但若用户选择 SD 上的第五世代来源，在线模式会
按同一套重定向逻辑读写 `sd:/roms/nds/saves/` 中对应的 `.sav`。

公开版票务策略应为 `0`：在线模式必须使用原版票务，缺接口时按原版报错。测试
策略 `1` 仅在确认 Azahar 缺少票务接口时自动使用本地结果；已有实现、实机和未知
环境均保留原版。该测试配置不能证明服务器许可已通过，也不保证本地结果不会影响
后续云端操作。NNID、宝可梦远端检查、下载及远端保存仍走原版。

原版消息条目保持不变。LayeredFS 档案追加两条标题模式文本、四条离线连接／保存
文本，以及从原版七种游戏语言资源复制的 28 个第五世代游戏名。连接／保存文本只在
离线模式替换，按 ROM 语言显示的游戏名则由两种模式共用。软件自带的十套界面语言
资源都会重建并验证。

## 共用界面语言

两种模式都会在原版启动绑定消息资源与字库之前，读取 `sd:/3ds/Bank/sav.bin` 中的
语言 ID 和日语假名／汉字设置。文件须恰好为 `0x200` 字节，且语言 ID 属于支持范围。
文件缺失、不可读或语言无效时，保留原来的启动回退逻辑，包括根据主机设置选择语言。

Mover 原生语言选择确认后，也会将设置同步写回已有的完整 `sav.bin`。更新保留其他
全部字节，包括事务元数据、校验值与文件尾部。语言字段 `0x28–0x2B` 不在原版校验的
`0x00–0x1F` 输入范围内，无须重新计算校验。Mover 不会创建缺失的 Bank 记录，也不会
写入 Bank 的原始存档档案。

先将更新后的完整记录写入并关闭 `sav.tmp`，再删除 `sav.bin` 并将临时文件改名。
替换之前失败会保留原记录；删除之后若改名失败，则保留完整临时文件供 Bank 的
现有机制恢复。这些设置不新增 `.bak` 或 `.break`。共用语言文件与按模式区分的
Bankdata 后端互不影响。

## 离线模式使用条件与本地文件

离线模式使用与 Pokemon Bank 相同的文件：

```text
sd:/3ds/Bank/bankdata.bin
```

该文件必须已经是长度恰好为 `0xBB518` 字节的有效当前格式银行对象。Poke Mover
不会执行 Bank 的缺失文件恢复或首次使用创建；文件缺失、不可读、长度错误或格式无效
都会进入错误路线。

开始新一次传送前，本地传送盒必须为空。补丁绝不会覆盖已有的传送盒内容。上实机测试
前请备份 `bankdata.bin`。

## 共用来源发现与离线传送路线

### 两种模式共用的第五世代来源发现

在线模式和离线模式都会在原版实体卡带检测与校验结束后，逐帧枚举
`sd:/roms/nds/` 中的普通文件。
扩展名 `.nds` 不区分大小写；文件名由 FS 的 UTF-16 接口传递，因此 ASCII 文件名也作为
UTF-16 的子集正常工作。每个 ROM 只读取头部 `0x10` 字节，并用 `0x0C–0x0F` 的游戏
代码识别 Black（`IRB?`）、White（`IRA?`）、Black 2（`IRE?`）或 White 2（`IRD?`）。

ROM `sd:/roms/nds/<name>.nds` 对应
`sd:/roms/nds/saves/<name>.sav`。存档必须能以“读＋写、禁止创建”方式打开，随后还要
通过原版异步存档载入、冗余面选择和完整性校验。补丁不自行修复校验值，也不会只凭
文件名把候选加入列表。

每个游戏只保留一个有效来源：

1. 通过原版校验的实体卡带锁定该游戏，任何数字版都不能替换它；卡带无效时仍会继续
   扫描数字版。
2. 数字版按游戏代码最后一字节采用 `J > O > F > I > D > S > K` 的优先级；遇到更高
   优先级且存档有效的副本会替换当前候选。
3. 同语言的多个有效副本保留最先扫描到的一个；无效副本不占位，后面的同语言副本仍会
   被尝试。
4. 只有四个游戏都已有有效卡带或有效 `J` 版时才提前停止，否则一直枚举到目录末尾。

目录不存在时按“没有 SD 数字版来源”继续原版流程；目录已经打开后若枚举 IPC 失败，
则丢弃本轮尚未提交的扫描结果并进入原版的无可用软件错误路线，不会把错误误判成正常
目录末尾并显示不完整列表。自定义目录扫描和存档校验阶段每帧仍调用原版加载画面更新，
因此不会冻结加载动画。文件及目录关闭在服务关闭请求失败后仍尝试释放内核句柄，
并返回最先出现的错误，避免连续扫描大量候选时泄漏句柄。

最终最多先加入四个第五世代逻辑来源，再由原版流程继续加入 VC 来源。由于原版固定
数组只能容纳 40 项，补丁在 `0x0024149C` 重放原有计数写入，并在“第五世代来源数＋VC
来源数”达到 40 时结束 VC 枚举；未达到上限时不改变原版循环。选择数字版后，补丁会
固定相应 UTF-16 存档路径；真正传送时重新打开并再次经过原版校验。此后若读写失败，
沿当前模式原有的错误／回滚路线退出，不会在事务中途自动换到其他副本。

第五世代游戏名按所选卡带或 ROM 游戏代码中的语言显示，不再跟随 Mover 界面语言：
`J` 日语、`O` 英语、`F` 法语、`I` 意大利语、`D` 德语、`S` 西班牙语、`K` 韩语。
实体卡带在原生校验完成后读取游戏代码；SD 来源沿用扫描时记录的代码。软件自带的
四套正文字体均包含这些原版游戏名所需的字符。界面语言、训练家姓名／ID、来源
优先级及原版 VC 游戏名选择均不变。游戏代码无法读取或识别时，保留原版按界面语言
显示的游戏名。

下面的银行连接、验证与保存状态流只描述离线模式；在线模式在完成同一套来源选择后，
继续原版联网、服务器银行及事务流程。

```text
来源游戏选择（有效实体卡带／本地第五世代 ROM／原版 VC）
        │
        ▼
通用“正在连接中”提示
        │
        ├── 在本地报告网络可用
        └── 不创建远端连接作业
        │
        ▼
进入原版票务状态，在作业接口内提供“主机当前时间 + 999 天”的本地票据
        │
        ▼
连接本地离线银行数据（至少 2 秒）
        │
        ▼
原版来源存档读取、筛选与 Pokemon 转换
        │
        ├── 第五世代：空槽写入原版结果 20；非空槽继续原版本地校验
        └── 第一／二世代：清除旧服务器结果；继续原版空槽与本地校验
                                              │
                                              ▼
                          清除残留远端事务并在本地完成检查状态
                                              │
                                              ▼
                           载入并验证完整 bankdata.bin
                                ├── 无效／缺失 ─► 报错
                                ├── 传送盒非空 ─► 原版消息 5；保留文件
                                └── 传送盒为空 ─► 原版确认界面
```

票据步骤只提供 Mover 运行时所需的使用期限日期、剩余天数／小时数和有效标志；它
不是宝可里程计算。本补丁的 Mover 端没有本地宝可里程累计或奖励流程。

### 票务分支：公开版与自动检测测试版

`main.s` 中的 `ONLINE_TICKET_CHECK_BYPASS` 只写出一个策略字节，两条路线始终保留：

源码默认采用公开策略 `0`；仅在个人测试允许缺接口时使用本地替代的情况下改为 `1`。

| 会话模式／环境 | 策略字节 | 票据作业／免费活动查询 |
|---|---:|---|
| 离线，任意环境 | `0` 或 `1` | 本地结果，不创建票务联网客户端或系统商店作业 |
| 在线，任意环境 | `0`（公开默认） | 原版检查及回调；不允许缺接口时伪造成功 |
| 在线，确认缺接口的 Azahar | `1`（测试） | 自动选择本地结果，其余联网流程不变 |
| 在线，接口已实现、实机或未知环境 | `1` | 原版检查及回调 |
| 在线，探测失败或普通票务错误 | `1` | 原版错误处理，不启用本地替代 |

截至本次票务调整提交，Azahar 官方版本尚未实现 `am:net` 的
`GetRightsOnlyTicketData`（命令 `0x0821`，见[接口注册表](https://github.com/azahar-emu/azahar/blob/6280521bf26ef1393974cd8c898de29cf75f5752/src/core/hle/service/am/am_net.cpp#L115)）。
因此保留两种票务配置：`0` 不允许联网使用本地伪造结果，作为公开发行默认值；`1`
只在运行时确认 Azahar 缺少接口时自动使用本地结果，供作者测试。本项目作者的 Azahar
[`pokebank` 测试分支](https://github.com/Wokann/azahar/tree/pokebank)
已补全并经联网测试确认该接口可正常运行，所以使用该分支或实机时，当前值保持
`0` 即可，无需跳过票务检查。离线模式始终使用本地结果，不受该值影响。

上述 Azahar 功能实现全部由 AI 生成，不符合
[Azahar AI 使用政策](https://github.com/azahar-emu/azahar/blob/master/AI-POLICY.md)
对完整或大部分 AI 生成贡献的接收要求，因此仅保留在个人测试分支，不向 Azahar
官方主分支提交。

修改该值后重新编译即可，不需要另一套源码。原版票务状态 `0x00249600` 的入口、
界面等待、作业构造、结果回填、有效性判断、退出与析构全部保留；仅转接四处调用：

| 原址调用点 | 原接口 | 本地替代 |
|---|---|---|
| `0x00249754` | `TicketJob_Initialize` | 初始化本地作业日期与结果字段 |
| `0x00249774` | `TicketJob_Poll` | 报告作业完成且期限有效 |
| `0x00249818` | `MoverCampaign_Request` | 将本地当前时间至到期日的窗口交给原版活动回调 |
| `0x00249CEC` | `TicketJob_Unbind` | 未创建联网客户端，无需解绑；随后仍执行原版析构 |

策略字节位于 `0x00365428`。每次作业初始化选择一次后端，存于 `0x00363FF8`；轮询、
免费活动和解绑沿用该结果，不在中途重复探测或切换。公开策略 `0` 不运行探测。
测试策略 `1` 复用 `GetSystemInfo(0x20000, 0)` 的 Azahar ID `2` 判断，然后非阻塞打开
`am:net`，发送 title ID／ticket ID 为 `0`、缓冲区 4 字节的只读查询。仅精确成功短响应
`0x08210040`、传输成功且关闭句柄成功才认定缺接口，见已核对版本的
[未实现接口处理](https://github.com/azahar-emu/azahar/blob/6280521bf26ef1393974cd8c898de29cf75f5752/src/core/hle/service/service.cpp#L155)。
完整响应、票据不存在、账号错误、服务失败及未知响应不触发本地替代。

**测试策略不作为安全联网保证**。与 Bank 不同，Mover 不将本地票务日期送入里程
计算；在线 Bankdata 主体由服务器载入，未发现本地票务日期或使用权显示字段序列化
进该主体的通路。但本地结果仍会改变客户端的使用权／活动判断，不能视为真实服务器
许可已通过。公开版保持 `0`，缺接口时接受原版失败，不将伪造票务用于真实联网操作。

本地作业分别填入真实主机当前日期和 999 天后的到期日期，原版函数据此计算剩余
天数 `999`、总小时数 `23976` 和有效标志。已有账户字段保持原值，购买次数保持
未知 `-1`，不伪造购票历史或购票奖励。本地活动结果把同一窗口及匹配的请求标识、
有效 CRC 交给未修改的原版回调，由其计算剩余时间并设置免费／有效标志，补丁不手动
写入这些输出；每次本地初始化均按主机时间重新生成窗口，不采用
服务器的固定活动日期。日期越界或作业分配失败进入原版错误退出，不会假装成功。
更详细的字段和分支对照见
[`票务状态与本地结果`](docs/code-analysis.zh-cn.md#票务状态与本地结果)。

原版候选转换状态继续负责读取来源游戏、筛选记录并构造传送候选。离线模式绕过两处
服务器合法性请求后，会补齐原版后续状态机依赖的逐槽结果。第五世代分类器按原版
标志及分块顺序只读解码，核对记录校验和：明确排除标记、校验错误或超出支持范围的
种族使用通用拒绝结果 `1`；完整且种族为 `0` 的空槽使用 `20`；其余 `1–649` 的
非空候选使用 `0`，继续原版本地检查。不要求空槽完全匹配某个模板，不修改来源
记录、名字、控制标志或校验和。来源读取失败进入原版读取错误提示和退出链，不
假装取得空槽或有效候选。VC 的空对象／道具／蛋判定不变，只清除全部 30 项旧结果。
离线模式不会复现未知的服务器专属合法性规则或名字规范化判定。

### 第五世代在线与离线的顺序

| 阶段 | 在线 | 离线 |
|---|---|---|
| 来源读取 | 校验整份来源存档并选择冗余保存面 | 保持原版 |
| 提交前 | 取得 30 条原始记录，尚未执行 14 项检查或传送转换 | 从同一记录缓冲区只读解码并检查记录完整性 |
| 逐槽结果 | 向服务器提交原始记录，验证响应并取得逐槽结果 | 完整填入 `0`、`20` 或 `1`；来源缺失整体报错 |
| 提交后 | 空槽跳过，拒绝结果汇总警告，其余进入 14 项检查 | 从同一原版后处理入口继续 |
| 转换与确认 | 检查通过后转换，加入内存传送盒并记录来源槽，显示警告及确认 | 保持原版，分类器不清空来源槽 |
| 保存 | 远端暂存、来源游戏保存、远端提交或回滚 | 沿用下文的本地 bankdata 事务 |

`0` 不是最终传送批准。前置分类也不会重做后面的传送条件判断；完整执行顺序、
字段与算法见[逐槽传送判定](docs/code-analysis.zh-cn.md#逐槽传送判定)。

### 保留的 14 项本地检查

所有检查都执行后再合并失败位；分类器不替代这些规则。

| 序号 | 检查 | 原版处理 |
|---:|---|---|
| 1 | 蛋标志 | 有蛋标志则拒绝传送 |
| 2 | 酋雷姆合体形态 | 禁止合体形态传送 |
| 3 | 携带道具 | 非致命；提示并移除道具 |
| 4 | 原训练家名字检查位置 | 本地函数固定返回成功，不新增名字处理 |
| 5 | 昵称检查位置 | 本地函数固定返回成功，不新增名字处理 |
| 6 | 物种与来源版本组合 | 按原版允许表检查，失败拒绝 |
| 7 | 活动标志与指定来源训练家 ID | 按原版组合检查，失败拒绝 |
| 8 | 捕获／获得等级 | 零值拒绝 |
| 9 | 孵化地点、获得等级与来源世代 | 不一致时拒绝 |
| 10 | 非孵化获得记录的最低捕获等级 | 低于物种最低要求时拒绝 |
| 11 | 语言 ID | 检查支持语言及原版特殊来源例外 |
| 12 | 来源版本 | 零值拒绝 |
| 13 | 旧来源版本与迁移／相遇地点 | 不符合原版组合时拒绝 |
| 14 | 旧来源版本与隐藏特性标志 | 不相容时拒绝 |

未通过检查的记录只从本次传送候选中排除，保留在来源存档；不会被分类器重置为空槽。

进入离线远端状态检查时，补丁还会清除同一进程中先前在线模式尝试可能留下的事务
参数，并把银行状态设为已确认的就绪值。这只隔离离线会话；在线模式仍由服务器重新
填充这些字段。

载入 `bankdata.bin` 前，补丁会先用原版传送槽对象保留候选。完整验证本地银行后，
只有传送盒为空才会恢复候选。原版槽写入操作会同时更新每个 `0xE8` 字节记录及其
并行标签；补丁不会用原始槽字节覆盖已有内容。既有账户身份字段保持不变。

## 离线保存事务

```text
用户确认传送
        │
        ▼
原版完整银行序列化（0xBB518 字节）
        │
        ▼
写入 bankdata.tmp + 设置长度 + 刷新 + 核对实际写入量
        ├── 失败 ─► 中止；保留 bankdata.bin
        └── 成功
              │
              ▼
保存进度界面至少继续显示 2 秒
        │
        ▼
原版来源游戏保存
        ├── 失败 ─► 删除 tmp；保留 bin 与 bak
        └── 成功
              │
              ▼
删除旧 bak ─► bin 改名为 bak ─► tmp 改名为 bin
        ├── 成功 ─► 原版断开路线
        └── 失败 ─► 尽可能恢复 bak
```

本地暂存、提交和回滚只替换对应的远端事务。暂存写入是同步操作，之后进入非阻塞的
两秒状态机延时；画面继续刷新，文件不会写入两次。只有原版来源游戏保存成功后才会
提交。文件关闭、长度、实际写入量、删除、改名、恢复和回滚结果都会检查。

没有可传送 Pokemon 或用户取消时，原版“不传送”路线保持不变；其最后一次远端事务
会在本地完成，再进入原版断开流程。

## 离线显示与计时

- 初始联网文字改成通用的“正在连接中……”。
- 本地银行数据连接提示至少显示两秒，之后才继续来源存档读取与转换。
- 保存提示会明确表示正在写入本地离线银行数据；完整暂存写入后至少继续显示两秒。
- 断开提示使用通用文本；已有的本地首阶段仍为 1.5 秒，并且不创建远端断开作业。

等待界面、旋转动画和节奏音效仍只由原版状态函数管理。离线更新通过原状态对象报告
工作完成，之后由原版状态退出路径统一清理。

## 独立编译与安装

Mover 子项目不依赖 Bank 的源码或构建产物，可以单独完成代码编译、BPS 生成、十套语言
文本重建和静态验证。运行时的离线模式仍要求 SD 卡上已有由 Bank 下载或初始化的
`sd:/3ds/Bank/bankdata.bin`。

需要准备 GNU Make、兼容 POSIX 的 shell、Python 3 和 devkitARM，并设置 `DEVKITARM`
环境变量。仓库自带 Windows 版 armips 与 Floating IPS；其他平台可通过 `ARMIPS` 和
`IPS_TOOL` 指定自行下载或编译的程序。

从用户自己的 Mover 本体 `00040000000C9C00` 提取输入：

1. 在 GodMode9 的 `Title manager` 中选择 Mover 本体并进入 `Open title folder`。
2. 选择可执行 `.app`，依次执行 `NCCH image options...` → `Extract .code`。
3. 再次选择同一 `.app`，执行 `NCCH image options...` → `Mount image to drive`，复制挂载
   分区中的完整 `romfs` 目录，以及根目录的 `extheader.bin`；将后者重命名为
   `exheader.bin` 放到下述位置。
4. 按以下结构放入工程：

```text
mover/rom/
├── exheader.bin
├── exefs/
│   └── 00040000000C9C00.dec.code
└── romfs/
    └── ...
```

基底代码必须为 `2,269,184` 字节，SHA-1 必须为
`583859C1E874D11650EFBDDE51F470ECF96900C4`。构建脚本会再次检查输入；代码镜像和
RomFS 不应提交或传播。需要使用其他 RomFS 路径时可显式覆盖 `ROMFS_SOURCE`。

构建还需要从同一本体取得的原始 `exheader.bin`（`0x400` 或 `0x800` 字节），
不能使用其他游戏、更新数据或已修改的 ExHeader。也可用 `EXHEADER=/path/to/exheader.bin`
指定输入；工具不会修改它。

从仓库根目录独立构建 Mover：

```sh
make -C mover clean
make -C mover
```

也可以进入子项目目录后构建：

```sh
cd mover
make clean
make
```

非 Windows 平台示例：

```sh
make -C mover ARMIPS=/path/to/armips IPS_TOOL=/path/to/flips
```

构建顺序为：编译各功能 C 对象并输出 `.s` 反汇编 → 准备扩容镜像与 ExHeader →
armips 导入对象并修改基底镜像 → Floating IPS 对比生成 `code.bps` →
重建十套语言 RomFS → 执行静态验证。
本地票务模块和 TLS／SVC 原语采用 ARM；文件系统、来源扫描、本地逐槽分类、Bankdata
与离线状态模块采用 Thumb，并通过显式跨状态入口调用。
完整输出为：

```text
release/00040000000C9C00/
├── code.bps
├── exheader.bin
└── romfs/
```

安装时必须成套使用 `code.bps`、`exheader.bin` 和 `romfs/`，移除同一补丁目录里的旧
`code.ips` 或 `code.bin`，避免重复应用补丁或载入其他基底镜像。BPS 还会校验原代码
是否为受支持版本。构建会移除自身 Mover 发行目录中生成的旧 `code.ips`。

默认发行目录仍为 `release/00040000000C9C00/`。text 页尾加载器通过 `DuplicateHandle`
取得真实进程句柄，查询 `GetSystemInfo(0x20000, 0)`，再对 `0x00365000–0x00368000`
调用 `ControlProcessMemory`（操作 `6`、权限 `7`）。SVC 返回 `0` 时正常继续；唯一允许
的非零兼容情况是环境查询成功、模拟器 ID 为 `2`、高 32 位为 `0`，且 SVC 返回值恰好
等于输入进程句柄。实机和未知环境仍严格检查返回值；负值和其他任何非零结果都中止
启动。句柄创建与关闭必须成功，恢复寄存器后继续原版构造函数遍历。原段起点、BSS
变量地址、Luma 预留和版本标识位置不移动。票务测试策略复用环境判别函数，但独立
探测票务接口；权限兼容成功不代表票务可用，也不自动启用联网本地结果。

原版 Azahar 可以通过 BPS 装载，不需要实现 SVC `0x70`；该兼容路径依赖它宽松的取指
行为，不代表真正取得执行权限。[Wokann/azahar 的 svc112 分支](https://github.com/Wokann/azahar/tree/svc112)
则正常执行权限修改。两者都将同一套 `code.bps`、完整 `0x800` 字节的 `exheader.bin`
和 `romfs/` 放入用户目录的 `load/mods/00040000000C9C00/`。Azahar 不会从模拟 SD 的
`sdmc/luma/titles/` 读取 ExHeader 覆盖；GodMode9 挂载导出的 `extheader.bin` 是完整
`0x800` 字节输入。静态构建检查不能替代端到端测试。

从 Magikoopa 实机方案、自用模拟器的装载／SVC 修复、OOT 项目的双布局参考到最终
统一 BPS 的探索经过、方案差异与兼容边界，见
[扩容方案的探索与对比](docs/code-analysis.zh-cn.md#扩容方案的探索与对比)。

校验器会检查基底哈希、载荷可执行范围、每个 ARM 钩子、被覆盖原指令、离线／在线模式
分派和续接点、BPS 逐字节还原与三个 CRC，以及所有原版和新增本地化文本。把生成的
`00040000000C9C00` 复制到 `SD:/luma/titles/`，启用 Luma 游戏补丁。实机使用前请备份
SD 卡和来源游戏存档。

## 与其他卡带重定向补丁的关系

本补丁现在直接接管原版的三处 NDS 卡带 I/O 入口，并内置更完整的多 ROM 扫描、来源
优先级和原版存档校验。因此，原先为
[DreamRadarCartRedirect 的 Transporter Redirect Patch](https://github.com/zaksabeast/DreamRadarCartRedirect/blob/b518a9868c23c69fe94c2818a9e600fd09c24a92/transporter.s)
保留的 `0xE0` 载荷区已经取消。两份补丁会修改相同入口，**不能再用 IPS 合并器直接
叠加**；使用本补丁时不要再安装该外部 Transporter 重定向补丁。
