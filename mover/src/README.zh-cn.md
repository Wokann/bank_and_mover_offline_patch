# 原版与离线合并补丁

原版程序的内存分布、网络路径、BankObject 与传送盒结构见
[`../docs/code-analysis.zh-cn.md`](../docs/code-analysis.zh-cn.md)。本文只说明当前补丁的设计、
实现与独立构建方法。

这是 Poke Mover v5.5.0 本体 `00040000000C9C00` 当前维护的补丁。它把已经验证的
独立离线功能与精确返回原版程序的运行时路线合并在一起。

Poke Mover 没有下载模式。它既不会创建新的本地银行，也不会下载本工程所用的本地
文件。请先使用 Pokemon Bank 合并补丁的下载模式取得
`sd:/3ds/Bank/bankdata.bin`，或通过 Bank 离线模式的首次初始化生成该文件，再使用
Poke Mover 的离线模式。已经废弃的 Mover 独立下载实验不属于正式流程。

上传补丁也已经永久废止。离线传送只提交到本地银行文件，本工程不会把它上传至官方
服务。

## 模式选择

标题界面默认显示**离线模式**。按实体 **R** 键可在**离线模式**和**原版模式**之间
切换。模式文字位于 HOME 选单说明下方，使用与 Bank 补丁相同的按键字形，并会立即
刷新。

按 **A**、**START** 或触摸下屏时，当前显示模式会锁定为本次会话模式。离开标题
界面后 R 键不再切换模式。

```text
标题界面（默认：离线模式）
        │
        ├── 按 R ──────────────► 原版模式
        ├── 再按 R ────────────► 离线模式
        └── A / START / 触摸
                  │ 锁定当前显示模式
                  ├── 离线 ─► 本地 bankdata.bin 与本地事务
                  └── 原版 ─► 官方联网与服务器流程
```

## 两种模式严格隔离

旧离线补丁涉及的每个钩子都会先读取已经锁定的会话标志。离线模式进入本地实现；
原版模式则精确重放被覆盖指令，或恢复原函数后续路线，包括：

- 网络可用性与连接作业；
- 票据处理；
- 第五世代及第一／二世代合法性请求；
- 服务器银行数据下载；
- 传送资格与候选构造状态；
- 远端暂存、提交、回滚和断开连接。

因此，原版模式不会读取、写入、创建、改名或删除 `sd:/3ds/Bank/` 下的任何文件，
并完整保留原版服务器流程与原版文本。

原版消息条目保持不变。LayeredFS 档案只追加两条标题模式文本和四条离线连接／保存
文本；运行时钩子仅在离线模式选择这些新增条目。软件自带的十套语言资源都会重建并
验证。

## 离线模式使用条件与本地文件

离线模式使用与 Pokemon Bank 相同的文件：

```text
sd:/3ds/Bank/bankdata.bin
```

该文件必须已经是长度恰好为 `0xBB518` 字节的有效当前格式银行对象。Poke Mover
不会执行 Bank 的缺失文件恢复或首次使用创建；文件缺失、不可读、长度错误或格式无效
都会进入错误路线。

开始新一次传送前，本地传送盒必须为空。补丁绝不会覆盖已有的传送盒内容。上实机测试
前请备份 `bankdata.bin`。

## 离线传送路线

```text
原版来源游戏选择
        │
        ▼
通用“正在连接中”提示
        │
        ├── 在本地报告网络可用
        └── 不创建远端连接作业
        │
        ▼
按主机当前时间设置“当前时间 + 999 天”的运行时离线票据
        │
        ▼
连接本地离线银行数据（至少 2 秒）
        │
        ▼
原版卡带读取、筛选与 Pokemon 转换
        │
        ├── 第五世代：空槽写入原版结果 20；非空槽继续原版本地校验
        └── 第一／二世代：清除旧服务器结果；继续原版空槽与本地校验
                                              │
                                              ▼
                          清除残留远端事务并在本地完成检查状态
                                              │
                                              ▼
                           载入并验证完整 bankdata.bin
                                ├── 无效／缺失 ─► 报错
                                ├── 传送盒非空 ─► 原版消息 5；保留文件
                                └── 传送盒为空 ─► 原版确认界面
```

票据步骤只提供 Mover 运行时所需的使用期限日期、剩余天数／小时数和有效标志；它
不是宝可里程计算。本补丁的 Mover 端没有本地宝可里程累计或奖励流程。

原版候选转换状态继续负责读取来源游戏、筛选记录并构造传送候选。离线模式绕过两处
服务器合法性请求后，会补齐原版后续状态机依赖的最小逐槽结果：第五世代中与程序内置
完整空槽模板完全一致的记录使用原版专门跳过的结果码 `20`，其他记录使用 `0` 并继续
经过原版本地检查。本地检查涵盖蛋、合体形态、来源／活动组合、等级与地点一致性、
语言／来源值，以及旧来源与隐藏特性标志的一致性；第五世代携带道具会被提示并移除，
而不是直接作为致命失败。VC 转换本身会先跳过空对象，再在本地拒绝蛋与携带道具的
候选，因此只需把 30 个结果清零。这样既不会把空槽误报成“无法传送”，也不会隐藏
仍被保留的非空记录本地检查。离线模式不会复现仅由远端提供的合法性与名字规范化判定。

进入离线远端状态检查时，补丁还会清除同一进程中先前原版模式尝试可能留下的事务
参数，并把银行状态设为已确认的就绪值。这只隔离离线会话；原版模式仍由服务器重新
填充这些字段。

载入 `bankdata.bin` 前，补丁会先用原版传送槽对象保留候选。完整验证本地银行后，
只有传送盒为空才会恢复候选。原版槽写入操作会同时更新每个 `0xE8` 字节记录及其
并行标签；补丁不会用原始槽字节覆盖已有内容。既有账户身份字段保持不变。

## 离线保存事务

```text
用户确认传送
        │
        ▼
原版完整银行序列化（0xBB518 字节）
        │
        ▼
写入 bankdata.tmp + 设置长度 + 刷新 + 核对实际写入量
        ├── 失败 ─► 中止；保留 bankdata.bin
        └── 成功
              │
              ▼
保存进度界面至少继续显示 2 秒
        │
        ▼
原版来源游戏保存
        ├── 失败 ─► 删除 tmp；保留 bin 与 bak
        └── 成功
              │
              ▼
删除旧 bak ─► bin 改名为 bak ─► tmp 改名为 bin
        ├── 成功 ─► 原版断开路线
        └── 失败 ─► 尽可能恢复 bak
```

本地暂存、提交和回滚只替换对应的远端事务。暂存写入是同步操作，之后进入非阻塞的
两秒状态机延时；画面继续刷新，文件不会写入两次。只有原版来源游戏保存成功后才会
提交。文件关闭、长度、实际写入量、删除、改名、恢复和回滚结果都会检查。

没有可传送 Pokemon 或用户取消时，原版“不传送”路线保持不变；其最后一次远端事务
会在本地完成，再进入原版断开流程。

## 离线显示与计时

- 初始联网文字改成通用的“正在连接中……”。
- 本地银行数据连接提示至少显示两秒，之后才继续原版卡带读取与转换。
- 保存提示会明确表示正在写入本地离线银行数据；完整暂存写入后至少继续显示两秒。
- 断开提示使用通用文本；已有的本地首阶段仍为 1.5 秒，并且不创建远端断开作业。

等待界面、旋转动画和节奏音效仍只由原版状态函数管理。离线更新通过原状态对象报告
工作完成，之后由原版状态退出路径统一清理。

## 源码布局

| 文件 | 作用 |
|---|---|
| `main.s` | 标题模式锁定，以及每个离线钩子的模式分派 |
| `fs_helpers.c` | 本地载入与事务共用的带检查 SD 归档／文件原语 |
| `bankdata_redirect.c` | 本地 Bankdata 载入、传送槽保留、资格状态，以及防崩溃临时写入、提交与回滚 |
| `local_ticket.c` | 运行时离线票据与主机日历计算 |
| `local_validation.c` | 重建第五世代空槽结果，并隔离第五世代／VC 的逐槽服务器结果 |
| `offline_flow.c` | 相互独立的网络、断开、远端检查、无传送与保存延时状态更新 |
| `patch_paths.c` | 共用的 SD 路径常量 |
| `patch_messages.py` | 为十套语言档案追加并验证标题／离线文本 |
| `message_archive.py` | 自包含的 GARC 与加密消息文件编解码器 |
| `verify_patch.py` | 验证基底哈希、代码区域、钩子、原版重放、IPS 还原与资源 |
| `Makefile` | 编译各功能对象、注入已审计代码区域、创建 IPS、重建文本并写出发行目录 |

## 独立编译与安装

Mover 子项目不依赖 Bank 的源码或构建产物，可以单独完成代码编译、IPS 生成、十套语言
文本重建和静态验证。运行时的离线模式仍要求 SD 卡上已有由 Bank 下载或初始化的
`sd:/3ds/Bank/bankdata.bin`。

需要准备 GNU Make、兼容 POSIX 的 shell、Python 3 和 devkitARM，并设置 `DEVKITARM`
环境变量。仓库自带 Windows 版 armips 与 Floating IPS；其他平台可通过 `ARMIPS` 和
`IPS_TOOL` 指定自行下载或编译的程序。

从用户自己的 Mover 本体 `00040000000C9C00` 提取输入：

1. 在 GodMode9 的 `Title manager` 中选择 Mover 本体并进入 `Open title folder`。
2. 选择可执行 `.app`，依次执行 `NCCH image options...` → `Extract .code`。
3. 再次选择同一 `.app`，执行 `NCCH image options...` → `Mount image to drive`，复制挂载
   分区中的完整 `romfs` 目录。
4. 按以下结构放入工程：

```text
mover/rom/
├── exefs/
│   └── 00040000000C9C00.dec.code
└── romfs/
    └── ...
```

基底代码必须为 `2,269,184` 字节，SHA-1 必须为
`583859C1E874D11650EFBDDE51F470ECF96900C4`。构建脚本会再次检查输入；代码镜像和
RomFS 不应提交或传播。需要使用其他 RomFS 路径时可显式覆盖 `ROMFS_SOURCE`。

从仓库根目录独立构建 Mover：

```sh
make -C mover clean
make -C mover
```

也可以直接调用子项目：

```sh
make -C mover/src clean
make -C mover/src all
```

非 Windows 平台示例：

```sh
make -C mover ARMIPS=/path/to/armips IPS_TOOL=/path/to/flips
```

构建顺序为：在保留模块内内联的前提下，把各功能 C 模块分别编译成对象并为每个对象
输出 `.s` 反汇编供检查 → armips 将多个对象连续导入已审计的可执行尾部并修改基底
镜像 → Floating IPS 对比生成 `code.ips` → 重建十套语言 RomFS → 执行静态验证。
完整输出为：

```text
release/00040000000C9C00/
├── code.ips
└── romfs/
```

校验器会检查基底哈希、载荷可执行范围、每个 ARM 钩子、被覆盖原指令、离线／原版模式
分派和续接点、IPS 逐字节还原结果，以及所有原版和新增本地化文本。把生成的
`00040000000C9C00` 复制到 `SD:/luma/titles/`，启用 Luma 游戏补丁。实机使用前请备份
SD 卡和来源游戏存档。

## Transporter Redirect Patch 兼容性

本补丁为 [DreamRadarCartRedirect 的 Transporter Redirect Patch](https://github.com/zaksabeast/DreamRadarCartRedirect/blob/b518a9868c23c69fe94c2818a9e600fd09c24a92/transporter.s)
保留了原址钩子 `0x0021A7E0–0x0021A7E4`、`0x0021AA0C–0x0021AA24`、
`0x0021AB50–0x0021AB68`，以及尾部载荷区 `0x0028DD00–0x0028DDE0`。
这些字节在本补丁的输出中与受支持的原版镜像完全相同，且构建校验器会阻止以后的
载荷误入该范围。因此，对同一个 v5.5.0 基底分别生成两份 IPS 后，可用支持
非重叠记录的 IPS 合并工具组合。这个预留只保证与上述已审计版本的地址兼容；
本项目不内置或重新发行该外部补丁。
