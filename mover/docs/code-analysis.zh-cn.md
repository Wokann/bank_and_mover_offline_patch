# Poke Mover 代码分析

本文记录受支持原版二进制的流程分析，以及离线适配与原版的执行顺序对照。补丁的
构建方式和事务规则见 [`../README.zh-cn.md`](../README.zh-cn.md)。

## 目标与内存分布

- Title ID：`00040000000C9C00`
- 版本：v5.5.0
- 代码基址：`0x00100000`
- 解压代码 SHA-256：`001C20ADA74016507C969BB44A0A50F8EDF803EC06A3FC46834263BA8DF0FD2F`

| 区域 | 虚拟地址 | 属性 |
|---|---|---|
| `.text` | `0x00100000–0x0028E000` | 可读、可执行；实际内容结束于 `0x0028D1AC` |
| `.rodata` | `0x0028E000–0x002EC000` | 只读、不可执行 |
| `.data` | `0x002EC000–0x003293FC`，装载页延伸至 `0x0032A000` | 可读写 |
| `.bss` | 逻辑范围 `0x003293FC–0x003638A4` | 可读写、零初始化 |
| RW 页尾填充 | `0x003638A4–0x00364000` | 可读写、零初始化 |
| 线程栈 | 长度 `0x40000` | ExHeader 配置 |

ExHeader 声明的 `.text` 内容结束于 `0x0028D1AC`，最后一页映射结束于
`0x0028E000`。Ghidra 记录的最后指令/数据引用位置为 `0x0028D188`，最后函数结束于
`0x0028D18F`。页尾余量足够时，Luma 会在应用 IPS 之后，从声明的内容末尾安装
LayeredFS 荷载。本项目保留 `0x0028D1AC–0x0028D2DC` 的 `0x130` 字节不写入，
再将自身荷载起点对齐至 `0x0028D2E0`。已检查的 Luma 荷载为 `0x114` 字节；
以后若其增大，需要重新检查预留量。参见官方的
[安装逻辑](https://raw.githubusercontent.com/LumaTeam/Luma3DS/master/sysmodules/loader/source/patcher.c)
和[荷载汇编](https://raw.githubusercontent.com/LumaTeam/Luma3DS/master/sysmodules/loader/source/romfsredir.s)。

本项目尾部荷载可用区域为 `0x0028D2E0–0x0028DFC0`；末尾
`0x0028DFC0–0x0028E000` 的 `0x40` 字节保留给版本标识。内置第五世代来源
重定向接管原生卡带 I/O 钩子，不再为外部 Transporter Redirect Patch 保留
`0xE0` 区域；汇编区域边界与静态验证仍保护 Luma LayeredFS 和版本标识。

`0x00261C74–0x00262C10` 属于仍被调用的原版全局注册初始化函数，不能作为回收空洞。
启动流程进入 `0x00102ADC` 后，会遍历 `0x002EB744–0x002EBA58` 的 PREL32 构造表。
其中 `0x002EB7BC` 的表项存储 `0xFFF764B8`，与表项地址相加后得到 `0x00261C74`。
这个间接调用不会出现在直接分支或绝对指针搜索中。当前模式包装、共用 FS 和
NDS 扫描器覆盖了这个初始化函数，但原构造表项仍未改变。这是已知启动风险，
不是安全代码空洞；关闭异常处理器后能继续执行也不能证明安全。
原版票务作业和免费活动函数均不被回收。

| 荷载区域 | 内容 | 实际结束／余量 |
|---|---|---|
| 初始化函数覆盖区 `0x00261C74–0x00262C10` | ARM 模式分派与原版跳板、共用 FS、NDS 扫描器 | `0x00262BB8`／`0x58` 字节 |
| text 页尾 `0x0028D2E0–0x0028DFC0` | ARM 入口、本地票务、Bankdata、离线状态、路径、本地分类、UTF-16 FS | `0x0028DFA6`／`0x1A` 字节 |

票务模块仍采用 ARM；其他功能模块采用 Thumb。共用 TLS／SVC 原语保留为禁止内联的
ARM 函数，采用地址间接调用；ARM 分派通过 `BX/BLX` 明确切换状态，验证器会拒绝
目标文件导入器产生的不安全立即数 Thumb→ARM 调用。
卡带读写入口、列表虚表与来源选择处属于原址钩子；后续原版函数体由跳板继续
调用，不用于存放新代码。原版 data/BSS 地址保持不变。

扫描器按需从原版堆分配 `0xE60` 字节上下文；指针使用 `0x00363FF0`，三个模式
字节使用 `0x00363FF4` 起的空间。这些地址位于逻辑 BSS 末尾 `0x003638A4`
之后、RW 页末尾 `0x00364000` 之前，不再使用原版 BSS 资源指针表中的
`0x00329FF8/0x00329FFC`。来源扫描不读取模式字节，由在线与离线两种模式共用。

四处票务钩子属于原址 `BL` 替换，仍占原来各 4 字节；其余票务状态和作业字节不变。

`.rodata`（`0x002EBA58–0x002EC000`，`0x5A8` 字节）和镜像中
`0x003293FC–0x0032A000` 的 `0xC04` 字节零填充不可执行；后者属于运行时逻辑
BSS 起始部分，不是空闲 data。静态零值不代表没有引用。
仅增大 ExHeader 的 `.text` 大小会与现有 `.rodata` 映射重叠，不能直接把 text
向后延伸；当前补丁不扩展原可执行映射。

## 票务状态与本地结果

原版票务状态为 `0x00249600`，局部子状态保存在状态对象 `+0x10`。两种模式都保留
该函数及回调 `0x0024991C`、清理 `0x00249CD8`，仅转接以下作业调用：

| 调用点 | 原函数 | 离线或测试开关 `1` | 在线模式开关 `0` |
|---|---|---|---|
| `0x00249754` | `0x0023D3C0` 初始化 | 填充本地作业字段，失败返回 `0` | 原调用及参数不变 |
| `0x00249774` | `0x0023E230` 轮询 | 返回完成并写成功结果 | 原调用及参数不变 |
| `0x00249818` | `0x0023BE4C` 免费活动请求 | 无活动，子状态设为 `3` | 原请求与异步回调不变 |
| `0x00249CEC` | `0x0023E63C` 解绑 | 未绑定客户端，返回后继续析构 | 原解绑不变 |

包装函数只使用调用者临时寄存器 `r12` 判断模式与策略，尾调用不改变原 `BL` 的
返回地址或栈。仅本地初始化分支从状态 `+0x28` 取共享数据作为 `r1`，本地活动
分支以状态对象作为 `r0`；原版分支保留原参数。

| 子状态／节点 | 原版流程 | 本地结果流程 |
|---|---|---|
| `0` | 更新界面，等待下一阶段 | 不变 |
| `1` | 等待界面准备，分配并构造 `0x158` 字节作业，初始化客户端 | 保留等待、分配和构造，只替换客户端初始化 |
| `2` | 轮询作业；成功后计算期限、拷贝账户与购票次数、设置有效标志、注册活动回调 | 同一结果处理和注册流程，只替换轮询及活动请求 |
| `6` | 等待免费活动回调；回调转入 `3` | 本地活动结果直接转入 `3`，不伪造回调报文 |
| `3` | 检查期限与免费活动：可用转 `7`，不可用转 `4` | 同一判断；本地有效期限、无活动转 `7` |
| `4/5` | 显示不可用提示并等待确认，随后进入错误退出 | 保留，不强行放行 |
| `7` | 设置完成阶段 `3`，返回成功退出 | 不变 |
| `8` | 设置错误阶段 `2`，返回结束 | 本地日期越界或分配失败也走此路线 |
| 清理 | 解绑、虚函数析构、清空作业指针、移除回调及释放活动资源 | 只免除未绑定客户端的解绑；其余仍执行原版 |

本地结果写入原作业，不直接覆盖共享数据中的期限结果：

| 作业字段 | 本地值及含义 |
|---|---|
| `+0xB8` 当前日期 | 主机当前时间，按原版 8 字节日期布局保存 |
| `+0x70` 到期日期 | 当前日期加 `999` 天，保留时分秒；不冒充当前时间 |
| `+0xB0` 账户字段 | 从共享数据 `+0x30` 保留现值，不生成账户编号 |
| `+0x78–0x8B` 五项购票次数 | `-1`，表示本地无购票历史 |
| `+0x04`、`+0xA0` | 系统商店结果、匹配目录数为 `0` |
| `+0xA4` 作业子状态 | 初始化 `0`，轮询成功后 `10` |
| `+0xA8/+0xA9/+0xAA` | 初次商店标志 `0`、期限已知 `0→1`、取消标志 `0` |
| SDK 指针、容器、字符串 | 保留原版构造值，不创建票务联网客户端 |

原版天数／小时数函数 `0x001DB83C`、`0x0023DFA8` 使用当前日期和到期日期，算出
`999` 天和总计 `23976` 小时；原状态回填共享数据 `+0x3C/+0x40`，并通过原版
有效性判断写入 `+0x44 = 1`。年度购票次数回填为 `-1`，免费活动标志 `+0x335`
为 `0`。此过程不涉及本地宝可里程，也不改变 Bankdata 事务或宝可梦检查。

`ONLINE_TICKET_CHECK_BYPASS` 默认 `0`，只在在线模式决定是否使用上述测试结果；
离线模式始终走本地接口。`1` 不替代 NNID 验证、其他服务器请求或远端许可，因此
仅用于模拟器测试，不能证明实际服务器同意传送。

## 来源列表与第五世代卡带接口

`0x00244D2C` 是来源列表状态更新函数，其虚表入口位于 `0x002E6620`。状态对象中与
来源枚举直接有关的字段如下：

| 对象偏移 | 内容 |
|---:|---|
| `+0x08` | 第五世代来源／存档上下文 |
| `+0x10` | 列表状态编号 |
| `+0x38` | 列表 UI 对象 |
| `+0x3C` | 40 项来源 ID 数组 |
| `+0x64` | 当前来源数量 |
| `+0x66` | 当前游标 |
| `+0x68` | 异步读取工作区 |
| `+0x78` | VC 枚举器 |

来源 ID `1–4` 分别表示 Black、White、Black 2、White 2，`5` 起进入 VC 路线。
原版列表先检测、读取并校验当前实体卡带，再从状态 3／4 追加 VC 来源；总容量固定为
40。选择处 `0x00244870` 以 `sourceId < 5` 区分第五世代与 VC。

共用扫描器最多可先加入四个第五世代来源，因此补丁在原版 VC 计数写入点
`0x0024149C` 重放 `strh r0,[r6,#0x58]`，再检查第五世代与 VC 的合计数。合计达到 40
时让原版循环在下一次递增后退出；未达到 40 时不改变循环状态。该容量保护同样在两种
模式中执行，避免覆盖固定数组。

第五世代来源读取和最终保存通过三个独立入口完成：

| 地址 | 原版作用 |
|---:|---|
| `0x0021A7E0` | 按偏移读取卡带存档 |
| `0x0021AA0C` | 读取卡带游戏代码 |
| `0x0021AB50` | 按偏移写回卡带存档 |

原版异步存档载入由 `0x0019ADEC` 启动、`0x0019AD60` 轮询，并在
`0x0019AA30` 执行格式与冗余存档面判定。当前补丁复用这套上层状态和校验；在任一模式
选中数字来源时，把上述三个底层入口转接到对应 SD 存档。实体卡带在任一模式中都经
精确跳板重放原函数序言并进入未修改函数体。模式差异只从后续银行、联网、合法性服务
及事务状态开始。

## 网络状态

完整文件经 `0x0025C978 MoverDownload_ConsumeBankData` 载入。该函数先备份 30 个候选传送槽；下载文件的 Transfer Box 为空时，再恢复候选数据。

`0x00248D3C` 所在 state 1 在请求函数返回后会把状态写为 2；异步下载回调会直接把父状态推进到 3 或 7。

网络传输函数：

| 地址 | 功能 |
|---:|---|
| `0x0018AA38` | HTTP 请求准备与启动 |
| `0x0018B58C` | HTTP 流式发送和接收线程 |
| `0x0020815C` | 构造含 `name="file"` 的 multipart 文件流 |
| `0x00208554` | 输出 multipart 前缀、文件体和后缀 |
| `0x00215208` | HTTPC 分块发送 |
| `0x00215308` | 通知 POST 正文结束 |
| `0x00215328` | 接收响应 |
| `0x0025AF1C` | 准备 BankObject GET |
| `0x0025B02C` | 检查响应 `Content-Length` |
| `0x001F8D5C` | 初始化 HPP POST 作业 |
| `0x001F8EB8` | 处理 HPP 结果、重定向和重试 |
| `0x001F9194` | 重建重试请求 |

HPP 中的四段资源是 `CACERT_PUBLIC_CA_5.der` 至 `_8.der`，不是 bankdata。底层 HTTPC 返回成功不能替代上层 HTTP 状态、响应体、控制面完成结果和异步状态。

## 逐槽传送判定

### 完整判定层次

一次传送并不是只执行一组“合法性检测”，而是依次经过四层：

1. 来源存档必须能正常读取并通过原版完整性检查；第五世代还会选择可用的冗余存档面。
2. 第五世代在线模式把 BOX1 的 30 条原始记录（含空槽）提交给远端服务；此时尚未执行
   14 项本地检查或传送格式转换。VC 则先转换候选。客户端验证响应后，取得与
   30 个槽位一一对应的 32 位结果码。该结果码表示通过、空槽／跳过、服务器拒绝，
   或要求修正昵称／原训练家名。服务器内部究竟执行了哪些检查并不存在于客户端代码中，
   客户端只负责消费这些结果码。
3. 远端结果允许继续处理的第五世代候选还要执行 14 项原版本地检查；VC 则使用另一条
   较短的本地判定链。
4. 通过的候选还要满足本地 `bankdata.bin` 有效且传送盒为空，才能写入传送盒。

第五世代已确认的远端结果语义为：`0` 表示允许继续，`20` 表示空槽，除 `20` 外非零且
小于 `250` 的值表示服务器拒绝，`250`、`251`、`252` 分别要求修正昵称、原训练家名或两者。
VC 使用 `0`、`20` 以及对应的名字修正码 `253`、`254`、`255`；其他非零结果会被拒绝。
因此这里的“远端信息”是逐槽判定码，不是另一份宝可梦数据，也不是第五世代 14 项本地
检查生成的失败位。

本次补丁只替代第 2 层在离线模式中无法取得的数组：第五世代只读检查记录完整性后，
有效空槽写入 `20`、非空候选写入 `0`、明确异常写入通用拒绝结果 `1`；VC 在先行
跳过空对象后把逐槽结果写为 `0`。第 1、3、4 层仍走原版流程。
所以离线模式仍会执行本地检测，但会失去仅由服务器提供的拒绝判定和名字修正。

### 第五世代的远端结果与本地结果

反编译函数 `0x002455D0` 的状态 4 会遍历 30 个固定 `0x88` 字节记录。共享流程对象
`+0x48` 保存逐槽的 32 位结果。主要分支可整理为以下等价伪代码：

```c
for (slot = 0; slot < 30; slot++) {
    result = slot_result[slot];

    if (result == 20)
        continue;                       // 原版空槽，不设置警告
    if (result != 0 && result < 250) {
        mark_remote_rejection();
        continue;
    }

    apply_known_remote_name_fixes(result); // 250、251、252
    failures = run_all_14_local_checks(candidate[slot]);
    handle_nonfatal_item_and_name_bits(&failures);

    if (failures == 0)
        convert_and_enqueue(candidate[slot]);
    else
        mark_local_rejection(failures);
}
```

14 项检查由 `0x002AFFE0` 的“函数地址 + 失败位”表驱动，全部执行后再合并处理，没有
遇到第一项失败便提前停止：

| 失败位 | 检查入口 | 实际本地检查 | 失败后的最终效果 | 本次补丁 |
|---:|---:|---|---|---|
| `0x0001` | `0x00242F8C` | 蛋标志必须关闭 | 致命；设置蛋类错误 | 不改 |
| `0x0002` | `0x00243028` | 酋雷姆不能是合体形态 | 致命；设置专用错误 | 不改 |
| `0x0004` | `0x00242FA0` | 是否携带道具 | 非致命；调用方清除此位，随后提示并移除道具 | 不改 |
| `0x0008` | `0x00243124` | 原训练家名检查位置 | **固定返回成功**：指令仅为 `r0=1; return`，不会本地产生失败 | 不改 |
| `0x0010` | `0x002432E0` | 昵称检查位置 | **固定返回成功**：指令仅为 `r0=1; return`，不会本地产生失败 | 不改 |
| `0x0020` | `0x00243050` | 物种与来源版本是否属于允许组合 | 致命；归入通用无法传送 | 不改 |
| `0x0040` | `0x0024320C` | 活动标志与指定来源训练家 ID 是否一致 | 致命；归入通用无法传送 | 不改 |
| `0x0080` | `0x002431FC` | 捕获／获得等级不能为零 | 致命；归入通用无法传送 | 不改 |
| `0x0100` | `0x002432E8` | 孵化地点、获得等级与来源世代的一致性 | 致命；归入通用无法传送 | 不改 |
| `0x0200` | `0x00243390` | 非孵化获得的记录不得低于物种最低捕获等级 | 致命；归入通用无法传送 | 不改 |
| `0x0400` | `0x00242FB4` | 语言 ID 必须受支持；保留一个特殊来源例外 | 致命；归入通用无法传送 | 不改 |
| `0x0800` | `0x00243018` | 来源版本不能为零 | 致命；归入通用无法传送 | 不改 |
| `0x1000` | `0x0024312C` | 旧来源版本必须与迁移／相遇地点组合一致 | 致命；归入通用无法传送 | 不改 |
| `0x2000` | `0x00243318` | 旧来源版本不能带有不相容的隐藏特性标志 | 致命；归入通用无法传送 | 不改 |

调用方会显式清除 `0x0004`、`0x0008`、`0x0010` 三个位：携带道具会被移除；两项
名字位预留了修正分支，但对应的本地检查函数固定成功，因此正常情况下不会由本地链
触发。在线模式中，远端结果 `250` 表示修正昵称、`251` 表示修正原训练家名、`252`
表示两者都修正；这些是独立于两项固定成功本地函数的远端行为。

### VC 的本地判定

VC 使用反编译函数 `0x002463D8`，没有调用上面的 14 项表。其顺序可整理为：

```c
for (slot = 0; slot < 30; slot++) {
    if (converted_candidate_is_null(slot))
        continue;
    if (source_had_item[slot]) {
        mark_item_rejection();
        continue;
    }
    if (source_was_egg[slot]) {
        mark_egg_rejection();
        continue;
    }

    result = slot_result[slot];
    if (result == 20)
        continue;
    if (result != 0 && result != 253 && result != 254 && result != 255) {
        mark_remote_rejection();
        continue;
    }
    if (result == 254 || result == 255)
        normalize_original_trainer_name();
    if (result == 253 || result == 255)
        normalize_nickname();
    enqueue_converted_candidate(slot);
}
```

因此，VC 在本地明确检查的是空对象、携带道具和蛋；更广泛的合法性判定及 `253–255`
名字修正码来自远端。它不会执行第五世代的 14 项本地表。

### 本次补丁实际调整的位置

在线模式会提交 30 个候选，验证返回签名后覆盖完整逐槽结果数组。来源记录访问函数
`0x0019A6D8` 直接定位选中的存档保存面及 BOX1，不规范化空记录。`0x002B3FD4` 是
原版成功传送后清除来源槽时使用的写入模板，不能作为所有输入空槽的唯一判据。

第五世代离线适配在原请求点 `0x00245728` 完成以下只读分类：

1. 保留此前的原版整份存档校验和冗余保存面选择。候选来源不可用时设置读取错误
   子状态 `13`，从 `0x00246368` 返回本帧；随后由原版错误提示、等待确认及退出路径
   处理，不进入逐槽转换。
2. 按原版记录头读取 PID、控制标志、校验和及 64 个 16 位记录体字。控制标志带
   原版排除位 `0x04` 时写入拒绝结果 `1`。
3. 按控制位 `0x02` 判断记录体是否已经解码。未解码时以头部校验和值为种子，逐字
   执行 `seed = seed * 0x41C64E6D + 0x6073`（32 位回绕），再异或 `seed >> 16`。
   解码仅使用临时值，不改写来源记录、控制标志或校验和。
4. 解码字之和的低 16 位必须与记录头校验和一致，否则写入拒绝结果 `1`。这项记录
   校验与整份存档块校验相互独立，不重新计算后覆盖来源校验值。
5. 使用 `(PID >> 13) & 31` 和原版 `0x002B42E4` 分块排列表定位种族。校验正常且
   种族为 `0` 时写入 `20`；种族为 `1–649` 时写入 `0`；其余种族写入 `1`。不要求
   空槽其余字段全零或匹配模板，不提前对空槽执行等级、语言、来源版本或名字规则。
6. 成功覆盖全部 30 项结果后，从 `0x00245800` 接回原版本地链。`1` 只作为本地
   通用拒绝值使用，不表示已复刻某个服务器专属错误码或完整合法性算法。

### 在线与离线的执行顺序对照

| 顺序 | 第五世代在线模式 | 第五世代离线模式 |
|---|---|---|
| 读取来源 | 原版读取、存档块校验、冗余保存面选择 | 保持不变 |
| 准备 30 槽 | 取得并复制原始 `0x88` 字节记录，包含空槽 | 从同一缓冲区只读检查完整性和种族 |
| 获取逐槽结果 | 发出远端请求，等待并验证响应，取得 30 项结果 | 本地填入 `0`、`20` 或 `1`；整体读取失败进入原版错误链 |
| 开始后处理 | 清除内存候选槽、警告和来源槽映射 | 接回同一原版入口 |
| 消费结果 | `20` 无警告跳过；拒绝值设置警告；允许值继续 | 使用同一分支 |
| 准备非空候选 | 复制记录到临时副本，处理远端名字修正，并确保解码和分块定位 | 原版复制、解码和定位不变；不生成名字修正码 |
| 本地判定 | 执行全部 14 项检查，合并并处理失败位 | 保持不变，见上方完整检测表 |
| 转换及入盒 | 通过者转换后加入内存传送盒，记录对应来源槽 | 保持不变 |
| 确认及保存 | 显示警告与确认，随后执行原版保存事务 | 保持现有本地 bankdata 保存事务，不由分类器修改来源记录 |

分类结果 `0` 只表示允许继续本地检查，不表示已经允许传送。被前置或本地检查拒绝
的记录不会进入成功候选映射；“无法传送”是从本次候选列表排除，不是清空来源槽。
只有成功候选在后续确认传送流程中由原版来源游戏保存逻辑处理。

其他适配保持如下：

- 在 VC 远端请求点 `0x002460B8`，离线模式把 30 项结果全部写为 `0`，然后从
  `0x002461D0` 继续。VC 已经先跳过空对象，所以不需要伪造结果 `20`。
- 每次进入离线路径都覆盖全部 30 项，防止从标题切换模式后继承同一进程中在线模式
  留下的结果。
- 在线模式仍从两个钩子返回原始远端请求流程；14 个第五世代检查函数、失败位后处理、
  VC 的空对象／道具／蛋判断及候选写入均未修改。

离线模式保留全部原版本地检查，并补足可在本地确定的记录完整性与空槽分类；它不
复现未知的服务器专属拒绝规则或名字修正。清除离线会话残留的远端事务参数属于状态
隔离，不是宝可梦合法性检测。

## BankObject 与 bankdata

Mover Bank 对象虚表：`0x002E6DD0`。文件内容对应对象 `+8`，固定长度 `0xBB518`。

| 虚表偏移 | 地址 | 功能 |
|---:|---:|---|
| `+0x08` | `0x0025AE44` | 序列化完整文件 |
| `+0x0C` | `0x0024D868` | 载入完整文件 |
| `+0x10` | `0x0025AE38` | 返回 `0xBB518` |
| `+0x18` | `0x0024D898` | 载入 `0xACA48` 旧格式并升级 |
| `+0x1C` | `0x0025AE20` | 检查 `u16(data+0x15C)==2` |

Mover 和 Bank 使用相同的完整文件格式。程序识别的当前格式长度为 `0xBB518`、版本为 `2`、盒数为 `100`。

### Transfer Box

| 文件偏移 | 长度 | 内容 |
|---:|---:|---|
| `0x0AAF14` | `30 × 0xE8` | 30 个传送槽主体 |
| `0x0AD5FC` | `30` | 30 个并行标签 |

| 地址 | 功能 |
|---:|---|
| `0x0019A224` | 载入一个传送槽及标签 |
| `0x0019A6F4` | 写入记录和标签并执行原程序规范化 |
| `0x0019A7E0` | 清空槽和标签 |
| `0x0019A858` | 判断槽是否含有效记录 |
| `0x0024D624` | 统计 30 个有效槽 |

传送区未发现单独的服务器记录 ID 或签名生成函数。原程序同时处理 `0xE8` 槽主体和 1 字节标签；`0x0025C978` 的处理顺序为备份候选槽、载入完整对象、在下载 Transfer Box 为空时恢复候选槽。

## 保存

`0x0024A0C4` 序列化完整 `0xBB518` 对象后执行远端更新、卡带保存和提交/回滚。

| 地址 | 原程序行为 |
|---:|---|
| `0x0024A240` | 发起远端暂存并等待异步结果 |
| `0x0024A3E4` | 卡带保存成功后发起远端提交 |
| `0x0024A420` | 卡带保存失败后发起远端回滚 |

三处分支均通过异步完成标志推进外层状态机。Mover 序列化和上传的是与 Bank 相同的完整文件格式。
