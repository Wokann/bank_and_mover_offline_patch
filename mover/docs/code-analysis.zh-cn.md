# Poke Mover 代码分析

本文记录受支持原版二进制的流程分析，以及离线适配与原版的执行顺序对照。补丁的
构建方式和事务规则见 [`../README.zh-cn.md`](../README.zh-cn.md)。

## 目标与内存分布

- Title ID：`00040000000C9C00`
- 版本：v1.5
- 代码基址：`0x00100000`
- 解压代码 SHA-256：`001C20ADA74016507C969BB44A0A50F8EDF803EC06A3FC46834263BA8DF0FD2F`

| 区域 | 虚拟地址 | 属性 |
|---|---|---|
| `.text` | `0x00100000–0x0028E000` | 可读、可执行；实际内容结束于 `0x0028D1AC` |
| `.rodata` | `0x0028E000–0x002EC000` | 只读、不可执行 |
| `.data` | `0x002EC000–0x003293FC`，装载页延伸至 `0x0032A000` | 可读写 |
| `.bss` | 逻辑范围 `0x003293FC–0x003638A4` | 可读写、零初始化 |
| RW 页尾填充 | `0x003638A4–0x00364000` | 可读写、零初始化 |
| 线程栈 | 长度 `0x40000` | ExHeader 配置 |

ExHeader 声明的 `.text` 内容结束于 `0x0028D1AC`，最后一页映射结束于
`0x0028E000`。Ghidra 记录的最后指令/数据引用位置为 `0x0028D188`，最后函数结束于
`0x0028D18F`。页尾余量足够时，Luma 会在应用代码补丁之后，从声明的内容末尾安装
LayeredFS 荷载。本项目保留 `0x0028D1AC–0x0028D2DC` 的 `0x130` 字节不写入，
再将自身荷载起点对齐至 `0x0028D2E0`。已检查的 Luma 荷载为 `0x114` 字节；
以后若其增大，需要重新检查预留量。参见官方的
[安装逻辑](https://raw.githubusercontent.com/LumaTeam/Luma3DS/master/sysmodules/loader/source/patcher.c)
和[荷载汇编](https://raw.githubusercontent.com/LumaTeam/Luma3DS/master/sysmodules/loader/source/romfsredir.s)。

本项目尾部荷载可用区域为 `0x0028D2E0–0x0028DFC0`；末尾
`0x0028DFC0–0x0028E000` 的 `0x40` 字节保留给版本标识。内置第五世代来源
重定向接管原生卡带 I/O 钩子，不再为外部 Transporter Redirect Patch 保留
`0xE0` 区域；汇编区域边界与静态验证仍保护 Luma LayeredFS 和版本标识。
所有功能对象使用下面的新增页布局。共用模块在启动期缓存环境、权限和票务能力；
票务检查等到原生服务和 TLS 就绪后才执行，不能仅凭环境识别判定票务可用。

`0x00261C74–0x00262C10` 属于仍被调用的原版全局注册初始化函数，不能作为回收空洞。
启动流程进入 `0x00102ADC` 后，会遍历 `0x002EB744–0x002EBA58` 的 PREL32 构造表。
其中 `0x002EB7BC` 的表项存储 `0xFFF764B8`，与表项地址相加后得到 `0x00261C74`。
这个间接调用不会出现在直接分支或绝对指针搜索中。整个初始化函数与构造表都要求
与原镜像逐字节相同。原版票务作业和免费活动函数均不被回收。

| 荷载区域 | 内容 | 实际结束／余量 |
|---|---|---|
| text 页尾 `0x0028D2E0–0x0028DFC0`：已映射可执行填充 | 启动跳板与自动识别环境的 `common/fs_system/runtime_environment.o` | `0x0028D56C`／`0xA54` 字节 |
| 原 RW 页尾 `0x00363FE0–0x00363FF0`，逻辑 BSS 之后 | 环境／SVC／票务能力及票务返回码缓存 | 16 字节，不覆盖原对象或模式存储 |
| 新增代码 `0x00365000–0x0038E000`：扩展 data，启动后可执行 | 模式包装、原版跳板、功能、fakeServer 与异步传输 | 编译尾端随构建变化；以 `CombinePatch_OfflinePayloadUsedEnd` 与 `CombinePatch_CodeEnd` 核对余量 |
| 新增上下文 `0x0038E000–0x00492000` | 服务数据及独立 1 MiB I/O 缓冲 | 预留 `0x104000`，ARM 对象 `0x101660`，规则、词池和解析工作区另按实际内容分配；末字节为票务作业标记，RW |
| 后台控制 `0x00492000–0x00493000` | 平台、任务、界面侧请求登记 | 实际 ARM 大小 `0x9D8`，RW |
| 任务正文 `0x00493000–0x00593000` | 上传／下载正文和 NDS 路径副本 | 1 MiB，RW，不随原作业析构释放 |
| 后台栈 `0x00593000–0x005A3000` | 原 SDK TLS 跳板启动的服务线程 | 64 KiB，RW；原主线程栈不变 |
| 本地来源控制 `0x005A3000–0x005A4000` | 原尾页容纳 `FsLocalSource` | ARM 对象 `0xAE8`，RW；不是未映射保护页 |
| 本地 Gen5 镜像 `0x005A4000–0x00624000` | 独立完整工作镜像 | 512 KiB，RW，不覆盖银行 I/O 或任务正文 |

启动钩子只在调用点 `0x00100010` 改为跳转到加载器。加载器保存 `r0–r12/LR`，
先使用 SVC `0x2A` 查询环境，再通过 SVC `0x27` 复制当前进程伪句柄取得真实句柄，
随后调用 SVC `0x70`（操作 `6`，
权限 `7`）仅启用四十一页代码预留的 RWX，服务及后台运行区保持 RW，关闭句柄并恢复寄存器，再以 Thumb 状态继续
`0x00102ADC` 的原构造函数遍历。实机失败以 SVC Break 中止；只有下面明确识别为
Azahar 的兼容情况，才允许未成功修改权限时继续。

配套 ExHeader 保持三个原段起点和 text／rodata 大小不变，仅把 data 扩到 `0x338` 页
（末尾 `0x00624000`），将 BSS 大小设为 `0`，并在既有能力描述符中补所需的 SVC 位。
原 BSS 区域成为镜像中的零填充，其变量地址不移动；`0x00364000–0x00365000` 也是
零填充 RW 隔离页，而非未映射的保护页。本配置原先已授权 `0x23/0x27/0x2A/0x3C`，
实际只新增 `0x70`。
这借鉴了 [Magikoopa 的 data 尾扩容方式](https://github.com/RicBent/Magikoopa/blob/master/MagikoopaUI/patchmaker.cpp)，
但不将 text 实际大小扩至页边界，避免改变 Luma 的 LayeredFS 注入位置。
新增页最初由加载器作为 RW data 装入，SVC 仅改变四十一页代码预留的权限，不会把服务及后台运行区、旧 data/BSS
或整个进程全部改成可执行。

### BPS 通用装载与自动环境识别

BPS 的来源长度为 `0x22A000`，目标长度为 `0x524000`，元数据长度为 `0`。Luma 根据
扩容 ExHeader 提前分配目标缓冲；原版 Azahar 的 BPS 实现会先把镜像扩长到目标长度，
再还原补丁。两边得到相同字节，data 都映射至 `0x00624000`。1 MiB I/O 缓冲
与任务正文分别持有，后台栈单独预留，原主线程栈不变。原程序的 BSS 清零边界
`0x003293FC–0x003638A4` 不变。参见
[Luma 的 BPS 解码](https://github.com/LumaTeam/Luma3DS/blob/master/sysmodules/loader/source/bps_patcher.cpp)
和 [Azahar 的 BPS 扩长处理](https://github.com/azahar-emu/azahar/blob/9e6f523a57fac9564ac0bf8286db3c3702d301ec/src/core/file_sys/patch.cpp#L260-L280)。

只有 `GetSystemInfo(0x20000, 0)` 返回 `0`、输出低 32 位为 `2`、高 32 位为 `0`，才识别
为 Azahar。Luma 实机返回 `1`、输出 `0`，不会进入该分支。所有环境都会调用 SVC
`0x70`，返回 `0` 时正常成功；非零结果只有在已识别为 Azahar、且恰好等于输入的真实
进程句柄时才接受，对应未实现调用保留 `r0` 的行为。负值、其他正值、未知环境以及
句柄创建／关闭失败均按错误处理，并非忽略所有 SVC 错误。未实现 SVC 的模拟器仍
依赖宽松取指；已经实现时则正常执行权限修改。参考：
[Azahar 的身份查询](https://github.com/azahar-emu/azahar/blob/9e6f523a57fac9564ac0bf8286db3c3702d301ec/src/core/hle/kernel/svc.cpp#L1866-L1870)、
[未实现调用处理](https://github.com/azahar-emu/azahar/blob/9e6f523a57fac9564ac0bf8286db3c3702d301ec/src/core/hle/kernel/svc.cpp#L2440-L2448)
和 [Luma 实机查询](https://github.com/LumaTeam/Luma3DS/blob/master/k11_extension/source/svc/GetSystemInfo.c#L218-L222)。

票务模块仍采用 ARM；其他功能模块采用 Thumb。共用 TLS／SVC 原语保留为禁止内联的
ARM 函数，采用地址间接调用；ARM 分派通过 `BX/BLX` 明确切换状态，验证器会拒绝
目标文件导入器产生的不安全立即数 Thumb→ARM 调用。
卡带读写入口、列表虚表与来源选择处属于原址钩子；后续原版函数体由跳板继续
调用，不用于存放新代码。原版 data/BSS 地址不移动。

扫描器按需从原版堆分配 `0xF40` 字节上下文；指针使用 `0x00363FF0`，三个模式
字节使用 `0x00363FF4` 起的空间；`0x00363FF8` 保存本次票务作业的后端。这些地址位于逻辑 BSS 末尾 `0x003638A4`
之后、RW 页末尾 `0x00364000` 之前，不再使用原版 BSS 资源指针表中的
`0x00329FF8/0x00329FFC`。来源扫描不读取模式字节，由在线与离线两种模式共用。

票务初始化、活动、系统绑定／解绑及发送钩子为原址 4 字节 `BL` 替换；原轮询、
解析器、结果消费和析构保留，不把整段原作业用于存放新代码。

`.rodata`（`0x002EBA58–0x002EC000`，`0x5A8` 字节）和镜像中
`0x003293FC–0x0032A000` 的 `0xC04` 字节零填充不可执行；后者属于运行时逻辑
BSS 起始部分，不是空闲 data。静态零值不代表没有引用。
仅增大 ExHeader 的 `.text` 大小会与现有 `.rodata` 映射重叠。因此若要越过 `0x0028E000`
扩容，不能直接把 text 向后延伸。本 SVC 方案改为扩 data／物化 BSS，并使用配套
ExHeader、BPS 和启动权限修改，因此不需要对原程序整体重定位。

## 共用 Bank 语言设置

Bank 已有的主机原存档是语言来源，Mover 不初始化另一份主机记录。启动先读取 Bank
有效的 `0x200` 字节快照再绑定资源；原档缺失或无效时保留原版回退。

| 钩子 | 当前处理 |
| --- | --- |
| `0x00240F38` | 原启动初始化前轮询任务自有的主机设置快照。 |
| `0x00241024` | 原启动析构前取消未交付结果。 |
| `0x0025C618` | 调用原语言 setter，只保留语言及汉字标志的数值。 |
| `0x002470F4` | 在返回标题的转圈状态中保存 Bank 原档语言，再同步 SD。 |
| `0x002472E8` | 原返回状态析构前取消尚未交付的请求。 |

文件读写前已经关闭语言界面。后台打开 Bank 受许可存档 `0x567890B4`，二进制路径
`[1, 0xC9B, 0]` 下的 `/turtle`，检查原标记及 CRC16，只修改 `0x28/0x2A` 的两个
16 位字段，再提交、关闭、重开并核对整份记录。成功后才同步所选用户的 `sav.bin`：
SD 确实缺失时完整复制原档，已存在时只同步语言。

原 CRC16 覆盖前 `0x20` 字节，初值 `0xFFFF`、多项式 `0x1021`，不反射、无最终异或；
语言位于覆盖区外。ExHeader 只向原存档白名单增加 Bank 的 ID，保留其他权限。
I/O 错误不授权初始化或格式化；原档与 SD 不是跨设备原子保存，SD 失败不撤销已提交原档。
设置相同则不写入。

## 标题模式说明与原版提示

模式名称是 START 上方的独立单行文本。下方 R 模式、L 语言、HOME 三行的下屏中心
纵坐标为 `156/182/208`，模式／START 为 `88/120`，均采用整数像素与原版 `15×19`
字号；START 和版权位置不变，HOME 原文不简写。

离线标题按共用注册表选择用户：auto 为首项，其后为升序实际编号，不循环。
十字键和左摇杆上下支持长按及加速，不使用 C 摇杆。浏览只操作内存，进入前后台发布
最终选择。Mover 不代建银行或提前创建会阻止 Bank 首次迁移的用户目录。

原首次姓名提醒标志与标题布局及逐槽检测相互独立，见[逐槽判定](#逐槽传送判定)。

## 票务状态与本地结果

原版票务状态为 `0x00249600`，局部子状态保存在状态对象 `+0x10`。两种模式都保留
该函数及回调 `0x0024991C`、清理 `0x00249CD8`，转接以下作业调用：

| 调用点 | 原函数 | 已选本地后端：离线，或自动策略 `1` 确认 Azahar 缺接口 | 已选原版后端：严格策略 `0`，或其他在线情况 |
|---|---|---|---|
| `0x00249754` | `0x0023D3C0` 初始化 | 仅记录后端选择，两种后端都调用原初始化 | 原调用及参数不变 |
| `0x00249774` | `0x0023E230` 轮询 | 原调用不再替换；SDK 解析和轮询决定完成／失败 | 原调用及参数不变 |
| `0x00249818` | `0x0023BE4C` 免费活动请求 | 将本地窗口交给原版活动回调处理 | 原请求与异步回调不变 |
| `0x00249CEC` | `0x0023E63C` 解绑 | 外层原调用不改，内部系统解绑按后端适配；析构保留 | 原解绑不变 |

界面另有三处只判断会话是否离线的分支：`0x00249650` 跳过为系统小程序清屏，
`0x002496CC` 不启动其渐变，`0x00249704` 跳过再次清屏及渐变准备。
离线仍推进子状态并分配／构造作业，不跳过回调移除、析构及资源释放。
在线模式完整还原这三处原指令和调用，即使测试策略选了本地票务后端也不跳过界面。
原票务状态除后端选择、活动／解绑及三处界面钩子外，其余字节不变。
作业内部仅系统绑定／解绑及发送提供者 `0x001D17E0` 适配后端；原 SDK 构造、
操作 10/1/5/6 的解析器、轮询和析构保留。

初始化包装保留作业 `r0`，从状态 `+0x28` 取共享数据作为 `r1`，以 `r2/r3` 传递
模式／策略，尾调用 C 后端选择器；其原版路线仍仅传作业给原版初始化函数。
后端只在初始化时确定一次，写入 `0x00363FF8`。发送、活动和解绑包装只用易失寄存器
`r12` 读取这个标志；本地活动分支以状态对象作为 `r0`，原版分支保留原参数。
原 `BL` 返回地址、栈对齐与被调用者保存寄存器均保持。

| 子状态／节点 | 原版流程 | 本地结果流程 |
|---|---|---|
| `0` | 更新界面，等待下一阶段 | 离线跳过小程序清屏，仍按原子状态推进；在线测试替代保留原界面 |
| `1` | 等待界面准备，分配并构造 `0x158` 字节作业，初始化客户端 | 离线跳过小程序渐变；保留分配、构造和原初始化，只适配系统提供者绑定 |
| `2` | 轮询作业；成功后计算期限、拷贝账户与购票次数、设置有效标志、注册活动回调 | 原 SDK 解析和轮询保留；只替换发送提供者及活动正文来源 |
| `6` | 等待免费活动回调；回调转入 `3` | 逐帧接收后台正文，释放任务后调用同一回调，由其转入 `3` |
| `3` | 检查期限与免费活动：可用转 `7`，不可用转 `4` | 同一判断；本地有效期限与免费标志转 `7` |
| `4/5` | 显示不可用提示并等待确认，随后进入错误退出 | 保留，不强行放行 |
| `7` | 设置完成阶段 `3`，返回成功退出 | 不变 |
| `8` | 设置错误阶段 `2`，返回结束 | 本地日期越界或分配失败也走此路线 |
| 清理 | 解绑、虚函数析构、清空作业指针、移除回调及释放活动资源 | 只免除未绑定客户端的解绑；其余仍执行原版 |

伪服务器正文由原解析器消费，不由客户端另行回填作业或共享期限结果。下表是默认
有效配置下的原版消费结果，不是客户端赋值表：

| 作业字段 | 本地值及含义 |
|---|---|
| `+0xB8` 当前日期 | 主机当前时间，按原版 8 字节日期布局保存 |
| `+0x70` 到期日期 | 配置到期日，默认 `2050-12-31 23:59:59`；不冒充当前时间 |
| `+0xB0` 账户字段 | 从共享数据 `+0x30` 保留现值，不生成账户编号 |
| `+0x78–0x8B` 五项购票次数 | 试用／年券由共用服务返回，默认 `0`；其余三项为 `-1` |
| `+0x04`、`+0xA0` | 系统商店结果、匹配目录数为 `0` |
| `+0xA4` 作业子状态 | 初始化 `0`，轮询成功后 `10` |
| `+0xA8/+0xA9/+0xAA` | 原目录／期限和取消处理决定，不在适配层写入 |
| SDK 指针、容器、字符串 | 原初始化和请求创建、消费及析构；仅免除真实网络客户端绑定 |

原版天数／小时数函数 `0x001DB83C`、`0x0023DFA8` 使用真实当前日期和配置到期日
计算剩余天数和总小时数；原状态回填共享数据 `+0x3C/+0x40`，并通过原版
有效性判断写入 `+0x44 = 1`，年度购票次数回填服务记录，默认 `0`。伪服务器将配置活动窗口
编码为原版 20 字节 `FREE` 正文：4 字节标识、两个 7 字节日期、2 字节 CRC。
库独立计算 CRC；客户端只取得资源正文，回调来源的请求标识匹配状态
`+0x44`，随后调用未修改的原版回调 `0x0024991C`。原回调继续检查请求标识、长度、

## 来源列表与第五世代卡带接口

`0x00244D2C` 是来源列表状态更新函数，其虚表入口位于 `0x002E6620`。状态对象中与
来源枚举直接有关的字段如下：

| 对象偏移 | 内容 |
|---:|---|
| `+0x08` | 第五世代来源／存档上下文 |
| `+0x10` | 列表状态编号 |
| `+0x38` | 列表 UI 对象 |
| `+0x3C` | 40 项来源 ID 数组 |
| `+0x64` | 当前来源数量 |
| `+0x66` | 当前游标 |
| `+0x68` | 异步读取工作区 |
| `+0x78` | VC 枚举器 |

来源 ID `1–4` 分别表示 Black、White、Black 2、White 2，`5` 起进入 VC 路线。
原版列表先检测、读取并校验当前实体卡带，再从状态 3／4 追加 VC 来源；总容量固定为
40。选择处 `0x00244870` 以 `sourceId < 5` 区分第五世代与 VC。

选择状态更新 `0x002445A4` 与来源枚举 `0x00244D2C` 是不同函数。SD 来源确认时，
包装在子状态 9 把路径副本交给后台 `ObserveSource`，完整 `0x80000` 字节存档的 CRC32
观察与原渐变并行。仅在原淡出调用 `0x0024483C` 的完成边界等待观察结果，再交原
`0x00244870` 分派 ID；不再在整次界面更新前阻塞。原表、结果及后续加载保留；
渐变和等待不重复观察，取消不向下一次选择投递旧响应，读取失败不允许暂存。实卡及 VC
不新增这次文件观察。

原 NDS 读写在存档作业线程执行：构造器 `0x001C181C` 设置虚表 `0x002E654C`，
其 `+0x0C` 为 `0x00243510`；`0x001E39D4 → 0x001E3F58 → 0x0010E250` 创建线程
（SVC `0x08`），原 TLS 跳板 `0x0011F100` 调用作业体 `0x0011C678`，后者在
`0x0011C6F8` 调用虚表 `+0x0C`。作业体调用 `0x0021A7E0/0x0021AB50`，因此这些
同步分段接口不能仅因含阻塞锁就视为主线程读写，也不能任意改为异步返回 ABI。
此结论来自原二进制调用链；并非实机线程时序或磁盘耗时测量。

共用扫描器最多可先加入四个第五世代来源，因此补丁在原版 VC 计数写入点
`0x0024149C` 重放 `strh r0,[r6,#0x58]`，再检查第五世代与 VC 的合计数。合计达到 40
时让原版循环在下一次递增后退出；未达到 40 时不改变循环状态。该容量保护同样在两种
模式中执行，避免覆盖固定数组。

第五世代来源读取和最终保存通过三个独立入口完成：

| 地址 | 原版作用 |
|---:|---|
| `0x0021A7E0` | 按偏移读取卡带存档 |
| `0x0021AA0C` | 读取卡带游戏代码 |
| `0x0021AB50` | 按偏移写回卡带存档 |

原版异步存档载入由 `0x0019ADEC` 启动、`0x0019AD60` 轮询，并在
`0x0019AA30` 执行格式与冗余存档面判定。当前补丁复用这套上层状态和校验；在任一模式
选中数字来源时，把上述三个底层入口转接到对应 SD 存档。实体卡带在任一模式中都经
精确跳板重放原函数序言并进入未修改函数体。模式差异只从后续银行、联网、合法性服务
及事务状态开始。

### 第五世代游戏名按来源语言显示

原版显示函数 `0x0019B1F0` 将来源 ID `1–4` 映射到当前界面语言档案中消息文件 `24`
的消息 `4–7`，因此第五世代游戏名原本跟随界面语言。VC 来源则已经通过
`0x002B47E0` 的 43 项原版表选择相应语言的条目。

补丁仅转接 `0x0019B240` 的 `BL MoverUi_SetMessageLine`。包装函数使用 `r4` 中
保留的来源列表状态，替换 `r3` 的游戏名消息编号，恢复 `r0–r2/LR`，再尾调用原版
文本框函数。字体选择、宽度适配、后续训练家姓名／ID 调用和原版游戏名表均不修改。

`NdsSources_TitleMessage` 使用胜出来源的游戏代码，不依赖文件名或当前 I/O 后端。
SD 胜出项原本就记录该代码；有效实体卡带在原版发现完成后，通过
`NdsSources_OriginalReadGameCode` 额外读取一次。读取或识别失败时回退到原版消息，
不改变来源是否可用。查询本身不分配扫描上下文，也不读取模式字节。

构建时从 `J/O/F/I/D/S/K` 七种语言档案各复制四个原版第五世代游戏名到所有界面
语言档案的消息文件 `24`，保留其 UTF-16 数值和标志。原消息 `0–53` 保持不变；
新增消息 `54–81` 采用 `54 + languageRank * 4 + sourceId - 1`。七个来源档案依次为
`a/0/0/5` 至 `a/0/0/9`，再到 `a/0/1/0` 和 `a/0/1/1`。`a/0/2/3` 中四套正文
CFNT 字体均包含这 28 个名称所需的全部字符；专用数字字体不用于显示游戏名，也
没有修改。不需要切换整个界面的语言或新增字体资源。在线／离线模式共用此游戏名
选择，VC 游戏名及来源发现／存档校验规则不变。

## 逐槽传送判定

### 完整判定层次

一次传送并不是只执行一组“合法性检测”，而是依次经过四层：

1. 来源存档必须能正常读取并通过原版完整性检查；第五世代还会选择可用的冗余存档面。
2. 第五世代在线模式把 BOX1 的 30 条原始记录（含空槽）提交给远端服务；此时尚未执行
   14 项本地检查或传送格式转换。VC 则先转换候选。客户端验证响应后，取得与
   30 个槽位一一对应的 32 位结果码。该结果码表示通过、空槽／跳过、服务器拒绝，
   或要求修正昵称／原训练家名。服务器内部究竟执行了哪些检查并不存在于客户端代码中，
   客户端只负责消费这些结果码。
3. 远端结果允许继续处理的第五世代候选还要执行 14 项原版本地检查；VC 则使用另一条
   较短的本地判定链。
4. 通过的候选还要满足本地 `bankdata.bin` 有效且传送盒为空，才能写入传送盒。

第五世代已确认的远端结果语义为：`0` 表示允许继续，`20` 表示空槽，除 `20` 外非零且
小于 `250` 的值表示服务器拒绝，`250`、`251`、`252` 分别要求修正昵称、原训练家名或两者。
VC 使用 `0`、`20` 以及对应的名字修正码 `253`、`254`、`255`；其他非零结果会被拒绝。
因此这里的“远端信息”是逐槽判定码，不是另一份宝可梦数据，也不是第五世代 14 项本地
检查生成的失败位。

离线模式由伪服务器提供第 2 层的响应数组：客户端只读观察记录与姓名，服务端先
判定结构、空槽及种族范围，再应用可选的组合规则和姓名词表。有效空槽返回 `20`，
异常／规则拒绝返回 `1`，其余返回 `0` 或原版姓名修正码；没有可选配置时不附加
规则／词表命中。第 1、3、4 层仍走原版流程。附加配置是本项目策略，不等于已复原
官方服务器的完整检查或词库。

### 通用改名提醒与实际命中提示

原版提示状态 `0x00247304` 先显示消息文件 23 的第 `7` 条传送／道具说明。
随后子状态 `2` 检查运行时 Bank 对象的 `+0x182` 字节：序列化正文从对象 `+8` 开始，
因此对应 `bankdata.bin` 的 `0x17A`（不是文件的 `0x182`）。尚未显示过提醒时设为 `1`，再显示
第 `16` 条“**如果**昵称／初始训练家名字包含禁用词，将改名”的通用提醒。这里不读取
词表、逐槽检测码或名字修改标记，不能据此判断盒子里已有违禁名字。该字节是提醒
已显示标记，不是敏感词命中标记。

正常保存由原版全量序列化带出此标记，伪服务器将同一正文写入 `bankdata.tmp`，提交时
发布为 `bankdata.bin`，事务完整结束后仍保留修改前的银行备份。下载／重新载入、
显示元数据更新及配置重载不单独改写此字节；Bank 原版下载回调调整相邻会话标志时也
保留它。因而同一份银行数据正常保存后，下次不再显示第 `16` 条通用提醒。仅在内存中
看过提醒、提交前取消、回滚到旧值为 `0` 的版本，或换入另一份值为 `0` 的银行数据时，
仍可能再次提醒；不能为隐藏提示而额外发布银行文件。

真正的检测命中走后面的子状态 `10`（`0x00247884`）：共享数据 `+0x1C7` 非零时
显示第 `24` 条“有宝可梦的昵称中包含……即将更改昵称”；`+0x1C8` 非零时显示第
`25` 条 OT 提示。显示时清除对应标记，避免重复通知。Gen5 后处理仍由原版消费
`250–252` 和 14 项本地检查；补丁不在界面分支强行设置或清除姓名标记。此提示状态
的机器码和三条消息均保留原值。

### 第五世代的远端结果与本地结果

反编译函数 `0x002455D0` 的状态 4 会遍历 30 个固定 `0x88` 字节记录。共享流程对象
`+0x48` 保存逐槽的 32 位结果。主要分支可整理为以下等价伪代码：

```c
for (slot = 0; slot < 30; slot++) {
    result = slot_result[slot];

    if (result == 20)
        continue;                       // 原版空槽，不设置警告
    if (result != 0 && result < 250) {
        mark_remote_rejection();
        continue;
    }

    apply_known_remote_name_fixes(result); // 250、251、252
    failures = run_all_14_local_checks(candidate[slot]);
    handle_nonfatal_item_and_name_bits(&failures);

    if (failures == 0)
        convert_and_enqueue(candidate[slot]);
    else
        mark_local_rejection(failures);
}
```

14 项检查由 `0x002AFFE0` 的“函数地址 + 失败位”表驱动，全部执行后再合并处理，没有
遇到第一项失败便提前停止：

| 失败位 | 检查入口 | 实际本地检查 | 失败后的最终效果 | 本次补丁 |
|---:|---:|---|---|---|
| `0x0001` | `0x00242F8C` | 蛋标志必须关闭 | 致命；设置蛋类错误 | 不改 |
| `0x0002` | `0x00243028` | 酋雷姆不能是合体形态 | 致命；设置专用错误 | 不改 |
| `0x0004` | `0x00242FA0` | 是否携带道具 | 非致命；调用方清除此位，随后提示并移除道具 | 不改 |
| `0x0008` | `0x00243124` | 原训练家名检查位置 | **固定返回成功**：指令仅为 `r0=1; return`，不会本地产生失败 | 不改 |
| `0x0010` | `0x002432E0` | 昵称检查位置 | **固定返回成功**：指令仅为 `r0=1; return`，不会本地产生失败 | 不改 |
| `0x0020` | `0x00243050` | 物种与来源版本是否属于允许组合 | 致命；归入通用无法传送 | 不改 |
| `0x0040` | `0x0024320C` | 活动标志与指定来源训练家 ID 是否一致 | 致命；归入通用无法传送 | 不改 |
| `0x0080` | `0x002431FC` | 捕获／获得等级不能为零 | 致命；归入通用无法传送 | 不改 |
| `0x0100` | `0x002432E8` | 孵化地点、获得等级与来源世代的一致性 | 致命；归入通用无法传送 | 不改 |
| `0x0200` | `0x00243390` | 非孵化获得的记录不得低于物种最低捕获等级 | 致命；归入通用无法传送 | 不改 |
| `0x0400` | `0x00242FB4` | 语言 ID 必须受支持；保留一个特殊来源例外 | 致命；归入通用无法传送 | 不改 |
| `0x0800` | `0x00243018` | 来源版本不能为零 | 致命；归入通用无法传送 | 不改 |
| `0x1000` | `0x0024312C` | 旧来源版本必须与迁移／相遇地点组合一致 | 致命；归入通用无法传送 | 不改 |
| `0x2000` | `0x00243318` | 旧来源版本不能带有不相容的隐藏特性标志 | 致命；归入通用无法传送 | 不改 |

调用方会显式清除 `0x0004`、`0x0008`、`0x0010` 三个位：携带道具会被移除；两项
名字位预留了修正分支，但对应的本地检查函数固定成功，因此正常情况下不会由本地链
触发。在线模式中，远端结果 `250` 表示修正昵称、`251` 表示修正原训练家名、`252`
表示两者都修正；这些是独立于两项固定成功本地函数的远端行为。

### VC 的本地判定

VC 使用反编译函数 `0x002463D8`，没有调用上面的 14 项表。其顺序可整理为：

```c
for (slot = 0; slot < 30; slot++) {
    if (converted_candidate_is_null(slot))
        continue;
    if (source_had_item[slot]) {
        mark_item_rejection();
        continue;
    }
    if (source_was_egg[slot]) {
        mark_egg_rejection();
        continue;
    }

    result = slot_result[slot];
    if (result == 20)
        continue;
    if (result != 0 && result != 253 && result != 254 && result != 255) {
        mark_remote_rejection();
        continue;
    }
    if (result == 254 || result == 255)
        normalize_original_trainer_name();
    if (result == 253 || result == 255)
        normalize_nickname();
    enqueue_converted_candidate(slot);
}
```

因此，VC 在本地明确检查的是空对象、携带道具和蛋；更广泛的合法性判定及 `253–255`
名字修正码来自远端。它不会执行第五世代的 14 项本地表。

### 本次补丁实际调整的位置

在线模式会提交 30 个候选，验证返回签名后覆盖完整逐槽结果数组。来源记录访问函数
`0x0019A6D8` 直接定位选中的存档保存面及 BOX1，不规范化空记录。`0x002B3FD4` 是
原版成功传送后清除来源槽时使用的写入模板，不能作为所有输入空槽的唯一判据。

第五世代离线适配在原请求点 `0x00245728` 完成以下只读分类：

1. 保留此前的原版整份存档校验和冗余保存面选择。候选来源不可用时设置读取错误
   子状态 `13`，从 `0x00246368` 返回本帧；随后由原版错误提示、等待确认及退出路径
   处理，不进入逐槽转换。
2. 按原版记录头读取 PID、控制标志、校验和及 64 个 16 位记录体字。控制标志带
   原版排除位 `0x04` 时写入拒绝结果 `1`。
3. 按控制位 `0x02` 判断记录体是否已经解码。未解码时以头部校验和值为种子，逐字
   执行 `seed = seed * 0x41C64E6D + 0x6073`（32 位回绕），再异或 `seed >> 16`。
   解码仅使用临时值，不改写来源记录、控制标志或校验和。
4. 解码字之和的低 16 位必须与记录头校验和一致，否则写入拒绝结果 `1`。这项记录
   校验与整份存档块校验相互独立，不重新计算后覆盖来源校验值。
5. 使用 `(PID >> 13) & 31` 和原版 `0x002B42E4` 分块排列表定位种族。校验正常且
   种族为 `0` 时写入 `20`；种族为 `1–649` 时继续可选策略；其余种族写入 `1`。不要求
   空槽其余字段全零或匹配模板，不提前对空槽执行等级、语言、来源版本或名字规则。
6. 有效非空记录只读提取形态、原生等级、招式、闪光、OT／训练家 ID、语言、来源版本、
   昵称标记、相遇／迁移等级及命运相遇标记，交给 `CheckPokemon`。相遇等级取 PK5
   `0x84 & 0x7F`，命运相遇取 `0x40` 的 bit 0；只是补充观察值，不在客户端作规则决策。
   启用 `BanUnicodeChinese` 筛选规则且未允许汉字时，Gen5 昵称或 OT 含受限汉字即返回 `1`，优先于白名单，
   不进入 `250–252` 改名；`allowFanTranslationCHN` 隐式允许汉字。组合规则拒绝也为 `1`；否则词表命中返回原版
   `250–252` 姓名修正码，没有命中返回 `0`。没有配置文件时不添加这些策略。
7. 成功覆盖全部 30 项结果后，从 `0x00245800` 接回原版本地链。`1` 只作为本地
   通用拒绝值使用，不表示已复刻某个服务器专属错误码或完整合法性算法。

### 在线与离线的执行顺序对照

| 顺序 | 第五世代在线模式 | 第五世代离线模式 |
|---|---|---|
| 读取来源 | 原版读取、存档块校验、冗余保存面选择 | 保持不变 |
| 准备 30 槽 | 取得并复制原始 `0x88` 字节记录，包含空槽 | 从同一缓冲区只读检查完整性和种族 |
| 获取逐槽结果 | 发出远端请求，等待并验证响应，取得 30 项结果 | 完整性／空槽后应用可选规则、词表；整体读取失败进入原版错误链 |
| 开始后处理 | 清除内存候选槽、警告和来源槽映射 | 接回同一原版入口 |
| 消费结果 | `20` 无警告跳过；拒绝值设置警告；允许值继续 | 使用同一分支 |
| 准备非空候选 | 复制记录到临时副本，处理远端名字修正，并确保解码和分块定位 | 同一原版分支处理本地返回的姓名修正码，不直接改写来源记录 |
| 本地判定 | 执行全部 14 项检查，合并并处理失败位 | 保持不变，见上方完整检测表 |
| 转换及入盒 | 通过者转换后加入内存传送盒，记录对应来源槽 | 保持不变 |
| 确认及保存 | 显示警告与确认，随后执行原版保存事务 | 保持现有本地 bankdata 保存事务，不由分类器修改来源记录 |

分类结果 `0` 只表示允许继续本地检查，不表示已经允许传送。被前置或本地检查拒绝
的记录不会进入成功候选映射；“无法传送”是从本次候选列表排除，不是清空来源槽。
只有成功候选在后续确认传送流程中由原版来源游戏保存逻辑处理。

其他适配保持如下：

- 在 VC 远端请求点 `0x002460B8`，离线模式以原生访问器检查已转换记录。空槽为 `20`，
  校验／排除异常或配置拒绝为 `1`，正常为 `0` 或 `253–255` 姓名修正码，然后从
  `0x002461D0` 继续。VC 原空对象跳过及本地判定分支保留。转换后种族范围为
  `1–255`，不额外封禁第二世代 `252–255`；第一世代原转换及本地限制仍有效。
  PK7 相遇等级取 `0xDD & 0x7F`，命运相遇取 `0x1D` 的 bit 0。
- 每次进入离线路径都覆盖全部 30 项，防止从标题切换模式后继承同一进程中在线模式
  留下的结果。
- 在线模式仍从两个钩子返回原始远端请求流程；14 个第五世代检查函数、失败位后处理、
  VC 的空对象／道具／蛋判断及候选写入均未修改。

离线模式保留全部原版本地检查，并补足可在本地确定的记录完整性与空槽分类；它不
复现未知的服务器专属拒绝规则。可选组合规则和词表由管理员维护，不宣称完整官方
v1.5 判定；词表仅交给原版修正／提示，不禁止传送。清除离线会话残留的远端事务参数属于状态
隔离，不是宝可梦合法性检测。

筛选配置仅有 enabled/action/condition，字段以分号结束，支持多行空白和 # 单行注释。
跨字段 &&/|| 和括号在加载时编译为非递归的内存指令；require 只约束本条表达式的
种族适用范围，其他种族跳过。旧 group/allow 及独立条件键移除；规则不覆盖结构校验
和上述 14 项检查。词池、词长、数量及语法帧均按实际内容动态分配，
默认载入公开 3DS v18 的 4016 条原始表达式、已注明的兼容例外及十语言种族名昵称白名单
（NDS 001–649、VC 001–251）；日、英、法、意、德、西、拉美西语、韩、简中、繁中分组，组内按图鉴编号。
保留官方游戏更名及存储字形，不加入港台旧译／社区别名；不改昵称标记，不豁免 OT 或合法性，
共 9268 条、226572 个实际记录字节。来源语言与历史变体说明见

不再读写配置 BIN 或冻结全套配置；已返回结果及暂存事务正文不重算，事务日志为 v5。

Gen5 读取 PK5 原始 16 位字段，存储字形不一定等同普通 Unicode。模板、许可和证据边界见

### 离线本地事务日志

独立 common/src/fakeServer/transaction.c 以共用 `sd:/3ds/Bank/fakeServers/users/<userID>/transaction.bin` 管理
银行、NDS 来源和 SD Turtle；SD 适配按 Mover 自己的 SDK 地址编译。格式见
[Bank 日志](../../bank/docs/code-analysis.zh-cn.md#本地日志格式与恢复依据)。

`0x0024A0C4` 在两个模式均转接保存包装，重放序言后续接原主体 `0x0024A0C8`。
离线 substate 16 成功文字前必须 Finish 成功；在线不以本地银行替代服务器。
原保存开始 `0x0024B92C`／轮询 `0x0024B868` 各修改一个入口指令，跳板重放
`push {r4-r6,lr}`／`push {r3-r5,lr}`，其他原始主体保留。

卡带／VC 的保存开始及轮询不再请求本地文件许可。首次原保存成功的 `5→10` 才
交接一次 `SOURCE_SAVED` 持久化确认，完成后运行原子状态 10 的提交请求；失败不能
进入提交。SD 来源已由本地后端确认发布，不重复该确认；在线仍只走原请求。未决
离线 SD 银行事务不能被在线来源保存覆盖。清理开始、成功及 Finish 的原有交接保留。

NDS 选择时由本地后端载入完整镜像及摘要，原 loader 随后从内存取得；保存开始前
复核可读写及身份。旧快照保留于 x.bak，原分段读写只访问独立内存镜像，
原保存完成后才统一写齐并回读 x.tmp。第一次及清理
保存均检查完整镜像、原版冗余面校验、Box 1 和解码事务块的预期内容，再核对内存／
文件 CRC32。原版作业返回成功还不足以发布未经封存的工作文件。

这些本地文件判断位于 `common/src/fs_system/source_image.c`，而非远端服务器接口，
与伪服务器仅共用调度及现有持久化检查点；不为分段读写建立服务会话或检查银行。
暂存核对实际捕获的旧版本；不匹配时不生成新的准备记录或工作文件。客户端只保留原生
存档解码、冗余面及预期编辑校验。客户端通过 `QueryRemoteStatus`／`QueryMetadata`
取得原版描述符与显示资料，再用 `RequestTransaction` 提交原有事务分支的决定；
不另设续办权限或原生事务块摘要。

`SettledSource` 的“无匹配完成记录”不等于本次选择观察失败。原来源恢复在无令牌时
也会进入完成阶段；该阶段返回 `FS_MISSING` 时保留本次已经核对的 SD 存档摘要及其
有效标记，不自行补造缺失的观察。只有服务返回有效的完整 `0x80000` 字节来源摘要
时才更新它；日志读取／校验失败或不完整的成功响应仍沿失败分支处理。新一轮选择
重置完成查询标记，避免沿用上一款游戏的完成状态。后续 `BeginSourceSave` 仍重新
核对文件是否匹配本次摘要，仍需完成原保存、完整工作镜像校验与发布。

同一路径的 `.sav` 经正常游戏保存或手动更新后，已结束的旧事务也不能覆盖本次观察。
`SettledSource` 只确认与请求摘要相同的完成镜像；不相同或没有有效观察时返回
`FS_MISSING`，不改文件、不重建事务。真正保存成功后的完成查询使用本次校验的工作
镜像摘要，新一轮选择及保存开始会清除旧工作镜像标记。接口只比较已有摘要，不增加
整份存档的读取或哈希；实际写入前的复核和未决事务保护仍保留。

离线封存第一次保存后记录 STAGED，再发布已验证 NDS 来源，让原版加载器能读到状态 2；
银行仍为旧版，直到原版提交请求记录 COMMIT_DECIDED 并发布为 PUBLISHED。
清理从第一版复制工作镜像，经原 setter／保存作业更新，封存 CLEANUP_READY，
发布并核对清理后的存档，删除 NDS 同名恢复文件，再正式记录 COMPLETED，才显示成功。在线 SOURCE_ONLY
先验证完整镜像、记录 COMMIT_DECIDED，再发布／核对原 .sav，返回原版成功后继续云端
操作；中断后按已确认的单文件决定续办，发布失败不会误走首次保存失败的云端回滚。

服务器提交已发布后，若客户端最后一次清令牌确认丢失，重连／下载仍可核对银行、
设置及已提交 NDS 来源后结束服务记录，不伪造清理保存确认。未确认的清理暂存
不会发布，来源保留已提交正文；残留令牌由原版来源恢复回调及独立本地保存处理。
实卡／VC 同样不因缺失最后确认重新锁住已提交银行。未提交事务及文件不符仍保留
原匹配、回滚和错误处理。

标题不新增恢复提示或 X／Y 交互。元数据恢复 state 14（`0x00243AF4`）保留原版
编号／当前版本匹配和不匹配提示，提交、回滚及既有强制回滚请求仅在离线转向本地服务。
强制回滚仍由原版两次确认触发，不套用 Bank 的数字键盘。服务要求描述符与当前非零未决
预留完整匹配，不接受提交后回滚或旧请求重放；仅银行回滚不改写另一份游戏存档。
共用服务使用 CRC32，以可容纳完整银行的 1 MiB 缓冲减少读盘；完整银行正文直接校验已载入的内存快照，
本次原生载入的只读请求复用正文观察及缓冲中的实际字节；来源绑定完整路径和游戏代码，
不混用其他存档。此视图不是持久化日志权威，日志／设置／配置仍独立读取。重入退回
1 KiB 缓冲；文件修改前使相关观察失效，失败清空视图，下一次载入／来源选择、连接或
重启重新观察。实际上传／来源保存准备重查主文件，发布另检查存在性及长度。
外部同长度编辑不在载入中即时同步，需重新选择／连接；原生匹配仍交客户端。
已结束事务及无服务记录的既有银行准备，把分组／顺序检查合并进全文摘要读取；首次
登记及只读核对复用本次载入摘要，未决和恢复决策保留。原生票务作业的子请求共享
配置／时间快照；新作业、重载／编辑、购买／充值或地区改变使其失效。下一次配置读取
采用当前文本，配置合并写入仍核对源文件与完整中转。Bank 下载快照仅在共用服务内部使用；Mover
仍经原有读取 API 取得完整银行正文，不创建 Bank 下载预留。
进入前的 SD 原生保存准备复用本次核对一致的 `x.bak`；完整镜像复制在既有
1 MiB 缓冲优先复用已验证字节，否则先核对实际读取字节并关闭来源再写目标；
新目标完整回读一次，后续步骤不各自再扫描。已载入银行的传送许可也不再为了读取
未参与决策的头部而重载正文；传送盒是否为空仍由原客户端判断。
`BeginSourceSave` 的 SD 分支不在已有 `Stage` 完整保护检查前再扫描一次银行。
`SOURCE_ONLY` 的 `SourceSaved` 已持久化决定并发布来源，响应随后直接 `Finish`
核对与更新备份，不额外重复 Commit。文件发布以一次主文件观察判前／后版，不减少
tmp／备份检查；原版双面、CRC16、来源保存与成功轮询均保留。
来源恢复 state 13（`0x00246B68`）保留原版事务读取：无令牌继续，状态 1 回滚、状态 2
提交；成功或原回调允许的过期／不存在结果后，只清令牌并执行保存类型 2。其他失败
保留原提示／结果，不清令牌。
来源加载、VC 校验及 NDS 冗余面判断仍走原函数，不另设选择时的续办路线，也不重新
转换或移除 Pokemon。

离线共用服务可登记无日志的合法主银行，也可在合法主正文同时不同于未决前／后版本时
通过 `ADOPT_BANK=6` 放弃旧服务预留、登记新编号并清旧银行备份。正常未决版本仍走原
匹配／恢复。银行三份全失时，旧有效日志可转为空基线，但 Mover 不创建银行，按原
下载失败流程结束。换档不回写／恢复实际来源 `.sav`，不能保证此前转移的双边一致性。
设置缺失的已核对副本恢复、已结束设置全删后的原初始化均保留银行编号及元数据；
未决设置全失、坏正式日志和无依据 tmp 仍保全。配置读取当前文本，恢复不重新执行筛选。
详见[文件组合及导入风险](../../common/docs/fakeServer/architecture.zh-cn.md#删除损坏和手动换入的处理边界)。

实卡／VC 暂存记录原 SDK 描述符与 36 字节显示资料，不记录原生事务块写前／写后／
清理摘要。服务按编号、版本、长度与非零令牌匹配；原调用未填充的 SDK `+0x14` 对齐字
不参与匹配。最后一笔已结束请求只允许同一决定重试，未知历史或不符请求不能伪报
提交／回滚成功；明确的业务错误仍由原回调决定残留令牌清理。原生保存
保留原结果处理，在线实卡／VC 写入不受本地日志的跨模式限制。NDS 的路径、完整镜像、
工作文件及 SOURCE_ONLY 协调仍属于文件后端。R 切换保留；实卡／VC 尚无完整快照，
不保证双边回滚。日志不上传。
离线实卡／VC 也不会在发布银行时提前结束日志：保存子状态 14 先匹配描述符并记录

`6/8/9` 同样观察原清理保存。失败保留未决日志，其他暂存不能覆盖；原描述符允许
跨 Bank/Mover 续办。数字版仍走既有镜像校验与发布路径，在线原生流程不受该确认影响。
旧描述符不能为另一端的新预留补确认；有效正式日志优先、正式文件缺失才读取
`.bak`、`.tmp` 不作为已发布依据的规则同样适用于两端交替使用。已结束／不存在
的旧令牌清理仅确认银行状态未受影响，原生事件不能替 Gen5 文件的实际保存和
校验发布补写来源／清理确认位。
刷新／回读不是实际 SD 断电持久化证明，同一目录

## 原生服务接入

嵌入式服务提供离线银行正文、票务／免费活动响应、元数据、逐槽结果及事务决定，不持有
原宝可梦对象，也不替代游戏转换。在线请求仍走官方后端；明确的模拟器票务能力回退与
离线账户政策分开。

下载保留原 SDK 构造、分配、观察及正文消费。服务结果分帧复制并释放后才完成 SDK 作业。
取消先解绑观察者而不等待工作线程，迟到结果不能交给同地址的新请求。

票务操作 `6` 及免费活动完成，在响应交付并释放后继续原 `0x00249600/0x0024991C`。
原目录辅助函数的同步等待不能依赖下一帧界面；不支持的操作直接完成失败。
离线连接监控不轮询不存在的官方会话，在线监控仍走原版。

## v1.5 转换的个人地区赋值

离线转换使用确认用户 `user.conf` 中的 `region/language/country/state` 给主机区域字段
赋值；它们不是宝可梦原生语言或原始游戏。autoRegion 只在确认账户入口刷新，autoCurrency
跟随该配置地区。手动设置可以覆盖实际主机或 Luma 的区域结果。

Bank 接收后不再改写宝可梦这些字段；在线 Mover 保留原系统设置调用。

## 可选的离线中文姓名转换

用户 `user.conf` 中的 `allowFanTranslationCHN=false;` 默认关闭。连接成功响应在候选转换前
交付该用户的自定义开关。开启时采用指定美版／韩版 VC 汉化码表，并仅在内存中关闭
BanUnicodeChinese 规则，不改共享配置；其他宝可梦规则及 NGWord 检测仍生效。

Gen5 名字已经是 UTF-16。默认命名分支在写入前选择获准的原中文昵称，并跳过该次
数据库默认名查询，特殊字形／控制符仍按原表处理；原版已带昵称和 OT 的转换保留。逐槽姓名修正码随本次调用栈传递，
服务器要求修改昵称时不采用保留分支，也不改昵称标记。

VC 的英、法、意、德、西文来源使用美版汉化双字节表，原单字节字符仍按来源语言解读；
两类编码的前导字节不重叠。韩版金银独立使用韩版表并兼容单字节混排，日文不进入。
来源编码由原版所选游戏版本／语言映射取得，不依据姓名内容或主机地区猜测。
VC 在原版昵称／OT 写入接点选择对应汉化字符串，覆盖三条转换路径及梦幻
的专用重命名分支。用于确定昵称标记的原版字符串比较仍执行；不先写入默认名再重开
宝可梦对象补写。转换后的 UTF-16 姓名随后交给伪服务器判定，姓名修正仍由原消费者
执行。关闭开关或遇到无效／不完整汉化编码时使用原文本；不保留全局候选指针。

独立的 `enableMoverv1.2=false;` 只切换离线 RGBY 旧转换，不改变 Gen2、Gen5 或在线。
